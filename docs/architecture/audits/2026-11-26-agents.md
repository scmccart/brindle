# Agent code review, 2026-11-26

- **Commit:** `5f335dc` (`feat(agents): list an agent's earlier conversations and continue one (#150)`), `origin/main`.
- **Scope:** the ACP agent code, about 28,000 production lines:
  - the server's pure ACP modules (`remote-agent/src/acp/`) and the shared transcript (`transcript/`);
  - the agent-session paths of the server core and the holder (`remote-agent/src/server/`) and of the two protocols (`remote-protocol/`);
  - the client's agent model, thread seam and link (`src/agent/`, `src/remote/`);
  - the agent zone's view, Markdown and chat components (`src/agent/view.rs`, `markdown.rs`, `ui/src/components/`), and the agent paths of `zone_view.rs`, `workspace.rs` and `notify/`.
- **Out of scope:** the unmerged `agents-commands` work (PR #151), the fake ACP agent, and tests except as evidence of a gap.
- **Standard:** principal-engineer code. That means correctness under every interleaving, cost proportional to the change, bounded memory, decisions in pure code, and types that rule out bad states. `docs/architecture/*.md` supplies the rule numbers cited.
- **Method:** five reviewers each read one layer in full and wrote a report with `file:line` evidence and a concrete scenario per finding. Every high and medium finding was then opened and checked by hand against `5f335dc`; "Checked by hand" below lists the sites. Nothing was built or run, so every finding is from reading. The two labelled *plausible* depend on a hop that was not traced.
- **Batch reports:** [`2026-11-26-agents/`](2026-11-26-agents/): `a.md` (the reducer), `b.md` (codec, checkpoint, transcript), `c.md` (server core and holder), `d.md` (client model and thread seam), `e.md` (view and components). "D-1" below means finding 1 of `d.md`. Each report also answers its layer's questions (cost per chunk, every bound, ids, backpressure) and lists structural observations.
- **Remediation:** [`2026-11-26-agents-remediation.md`](2026-11-26-agents-remediation.md), seven OpenSpec changes.

## Summary

The design holds. The server core is the only ACP client, the reducer is a pure step function, the shared fold is total, ACP names stay in `acp/v1/`, and the decoders of agent output are bounded and split-safe. The crate graph matches the dependency rule. No finding is critical: nothing lets an agent act unseen, and nothing corrupts a stored conversation in ordinary use.

The 38 findings (3 high, 14 medium, 21 low) sit at four kinds of seam, and in module size:

- **State kept in two places that are ordered by nothing.** The client learns "the agent is ready" from the reader thread and "the session can send" from the session thread, in either order (D-1, the known first-prompt flake). The server keeps a waiting permission both in the log and in `Rpc`, and a pending restart both in `Life` and in `Core.waiting`; each pair has a path that updates one and not the other (A-3, C-1). The Earlier row's fetch is recorded twice in the model (D-7).
- **GPUI defaults nobody overrode.** A press on anything unfocusable in a conversation moves keyboard focus to the zone tree, off the prompt (E-1). A splice of the item at the top of the view resets its scroll offset, so reading back while a reply streams jumps (E-2). A focused control scrolled out of view is not drawn, so its keys go dead (E-3).
- **Bounds that hold per field and not in sum.** Every string is bounded, but one transcript event can still pass the 1 MiB frame, and a batch holding it is refused whole (A-2). One text entry has no bound, so the 16 MiB log bound and the checkpoint bound do not hold (A-1). A raw tool input is pretty-printed in full before its 16 KiB cut (B-2).
- **Cost that follows the conversation and not the change.** Each checkpoint segment rewrites the whole tool map and the whole partial line (B-3, B-4). The client re-renders a growing message under the lock the reader thread needs, once per wake (D-2, D-3). A large table is one list item rebuilt every frame (E-5).
- **Four files hold most of the logic.** `reduce.rs` (3,188 production lines), `model.rs` (3,293), `checkpoint.rs` (1,242) and `transcript/src/lib.rs` (1,756) each carry between four and twelve responsibilities. Several findings (A-3, C-1, D-7) are bugs a narrower module or a tighter type would have made visible.

**Fix first:** D-1, E-1 and E-2. They are the three a user meets in ordinary use, and each has a small fix.

## Verdict

**SOUND, WITH SEAMS TO CLOSE.** The layering and the pure core are what the architecture docs ask for, and they made this review possible: almost every finding could be traced to one function. The work is in the places two owners meet (threads, processes, the log and its indexes, GPUI's focus and list) and in cutting four files down so those places can be reviewed alone.

## What is clean

One line each, so later work does not re-audit them:

- `acp/lines.rs`: one scan per chunk, no rescans, an over-long line dropped without buffering.
- `acp/rpc.rs`: request ids never repeat across a restart or a restored checkpoint; permissions capped at 16.
- `acp/envelope.rs`, `v1/encode.rs`, `dialect.rs`, `plain.rs`: total, bounded, one exhaustive match per method.
- The checkpoint restores every `AgentSession` field; the three differences are recorded decisions.
- The transcript fold is total, O(chunk) per append, and the core and the client run the same `apply`.
- `src/agent/markdown.rs`: linear parse, bounded depth and columns, panic-free; `link_action` is the one pure decision, and nothing opens without the ctrl gesture.
- Agent-to-client and agent-to-core backpressure is bounded; an attach holds events back until its replay; one session has one attached client, so a permission is never shown twice.
- The holder owns the hang-up sequence, so a core that dies mid-way leaks no process.

## Findings

Severity: **high** is a wrong result, hang or lost input under ordinary use; **medium** needs an unusual sequence or costs noticeably at scale; **low** is a latent hazard or a structure problem. Confidence is *confirmed* (every hop read) unless marked.

## Structure

The reports' structural observations agree on these moves; `2026-11-26-agents-remediation.md` plans them as one change with no behaviour change.

- **`acp/reduce.rs`** into `reduce/{mod,lifecycle,turn,tools,permission,login,list,text}.rs`, each an `impl Step` block with its tests. The state that belongs to one agent process (awaited requests, the line splitter, the run, open outputs) becomes one `Process` value that a respawn replaces whole.
- **`acp/checkpoint.rs`** into `checkpoint/{format,state,adopt}.rs`.
- **`transcript/src/lib.rs`** into `event.rs`, `fold.rs`, `page.rs` and `output.rs` behind the same exports.
- **`src/agent/model.rs`** into eleven modules along its state (blocks, ledger, queue, prompt, login, recovery, choosing, paging, attention, dump, phase).
- **`server/core/sessions.rs`**: the restart and ended-session lifecycle moves to `agents.rs`, and `session_lost`'s 70-line decision becomes `policy::lost_fate`.
- **`src/workspace.rs`** loses the conversations palette to `workspace/conversations.rs`; **`src/zone_view.rs`** loses the terminal-login orchestration to `zone_view/login.rs`.
- **One gate for protocol 4**: an exhaustive `agent_request(&ToCore)` in `handle_client`, in place of four call sites.
- **The wire bounds in one place**, with a test that derives "every event fits a frame" and "a full log fits a checkpoint" from the constants.
