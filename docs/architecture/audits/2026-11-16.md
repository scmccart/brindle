## Summary

The architecture on paper and the crate graph match exactly. Every crate references only what the dependency rule allows, there are no cycles, and `tests/architecture.rs` passes and checks real targets. `brindle-term-core`, `brindle-ui` and the protocol codecs are close to clean.

The drift is inside the crates, mostly in the app and the server roles:
- **Decisions in the shell.** About 70 `fcis R1`/`R10` cases: decisions written inside views, entities and core handlers rather than in pure functions or models.
- **Failures logged and replaced by a default** (`railway R1`). One of these can blank `session.toml`.
- **Bool, sentinel and index state** (`types R1`/`R7`/`R3`), about 85 entries.
- **A stale exception.** The `ports R4` exception names 4 files, but 97 platform `cfg` attributes and 18 `cfg!` uses sit outside seams, in 23 files.
- **Flaky-prone tests.** Fixed sleeps and timing-dependent asserts (`testing R7`/`R8`).

**Fix first:** the four MUST findings that are real or likely defects (findings 1–4), then make the `ports R4` exception an explicit list and give it a check.

## Verdict

**DRIFTING.** The dependency rule holds and the MUST violations are spread across layers rather than breaking a boundary. They are numerous but not structural, and three areas of enforcement and docs are stale:
- the `ports R4` exception text;
- clippy, which isn't in CI and fails;
- the conflict between `testing`'s platform pairs and `ports R4`.

## Structure

The intended dependency rule is that `brindle` (`src/`) and `brindle-remote-agent` (`remote-agent/`) depend on three shared crates, which have closed dependency lists:
- `brindle-ui` (`ui/`): `gpui` only.
- `brindle-term-core` (`term-core/`): `alacritty_terminal`, `base64`, `parking_lot`.
- `brindle-remote-protocol` (`remote-protocol/`): `serde`, `serde_json`, and `windows` on Windows.

The binaries never reference each other, and neither do the shared crates.

`cargo metadata` finds the actual graph identical to that rule:
- no wrong-way edge, no cycle, no unassigned crate and no source file outside a crate;
- the five crate versions match (`process R21`).

Every source file was assigned to one layer, as the table above shows.

## Findings

Most severe and widespread first. Each group lists the rule, its spread, representatives, the cause and the smallest fix. The result file named in brackets has every instance.

### 1. A serialization failure overwrites the saved session (`railway R1`, MUST, isolated)

"An expected failure is a value … never logged and replaced by a default."
- **Where:** `src/session.rs:267` `State::to_text`, written through `pending_write` at `src/session.rs:724` [b27].
- **Effect:** a value that fails to serialize empties `session.toml` atomically and correctly, losing the user's saved windows.
- **Fix:** `to_text() -> Result<String, toml::ser::Error>`, and `pending_write` returns `None` and logs on `Err`. Size: S.

### 2. Perf and two e2e paths aren't hermetic (`testing R4`, MUST, one layer)

"Every run has its own state, config and server directory."
- **Where:**
  - `tests/perf/cases.rs:27`: no `BRINDLE_SERVER_DIR`, no `BRINDLE_NO_SCOPE`, no `brindle-remote stop` [b36].
  - `tests/e2e/cases/restore.rs:130` and `tests/e2e/cases/remote.rs:1957`: hand-built spawns that bypass `Run` and its isolation [b34].
  - `tests/e2e/instance.rs:39`: `Launcher::launch` sets the state, config and server directories but not `BRINDLE_NO_SCOPE=1`, which `Run` sets [b33, recorded as a smell].
  - 6 entries in all.
- **Effect:** perf runs create sessions in the user's real server and may leave them running. The two e2e spawns start roles in systemd scopes.
- **Fix:** give perf the e2e harness's private server directory (under `/tmp`, for `sun_path`), `BRINDLE_NO_SCOPE=1` and its stop-and-check step; route the two e2e spawns through `Run`. Size: S.

### 3. Sessions are matched by bare id after a reconnect (`types R3`, MUST; 16 entries in all)

"An identity MUST be the value that stays stable … Sessions are named by endpoint, id and key"; the doc's anti-pattern is "Looking a session up by id alone after a reconnect".
- **Primary site:** `src/remote/local/connection.rs:276-281`, `1217-1233`, `1279-1282`, `1836-1842` [b25 item 13].
  - `State.sessions`, `parents` and `foreground` are keyed by `SessionId`.
  - `attached_by_replay` matches `attach.session == session`.
  - Carried non-recorded attaches match `info.session == session` with no key check.
  - The comment at 1809-1811 shows the hazard is known; only a recorded attach is protected.
- **Effect:** after a fresh core, a lost tab can be kept alive and fed another session's replay.
- **Fix:** keep the key beside each shown session (`Running` already has it) and compare `(id, key)` when pruning and when a replay arrives. Size: S–M.
- **Other `types R3` entries** use an index as identity across refreshes:
  - `brindle-ui`'s `Select`, `Combobox`, `Menu` and `Tabs` keep a highlighted or selected index across item changes [b40–b42].
  - The settings dialog's selection is index-based [b04, b05].
  - Fix: key by the item's own id, as `SessionsModel` does with `RowKey`.

### 4. Bytes from outside can panic or grow memory without bound (`railway R5`, MUST, 5 entries; `process R6`, 6 entries)

"Decoders never panic"; "bytes from outside the process are bounded".
- `remote-protocol/src/holder.rs:538`: `Assembler` doesn't bound how many blobs are open [b20]. Fix: cap `open.len()` at the session count or a constant, and refuse past it. Size: S.
- `ui/src/text_input.rs:529`: a reversed UTF-16 range panics the slice [b43]. Fix: order the range (or clamp it) in `range_from_utf16`. Size: S.
- **No fuzz target** for `skip_preamble` (relay link), `SessionMeta::from_value`, the `semver` parse used by upgrade, `parse_holder_lock`, or the `term-core` OSC 7/133/7501 parsers [b22, b25, b30, b31]. Fix: add them to `remote-protocol/src/fuzz.rs` or a term-core equivalent. Size: S.
- **Transcript gaps** (`process R6`, "every message variant has a transcript"): no transcript pins `Exit.lost = Some(..)`, `Previous::Crash` or `ExitStatus { code: None }` [b22]. Size: S.

### 5. A local-only action runs under a possibly remote profile (`types R8`, MUST, isolated)

"A value that is only meaningful on one host carries that host."
- **Where:** `src/workspace.rs:1748` `open_config` [b07].
- **Fix:** launch with `Host::Local` explicitly, or a local-only profile, regardless of the default profile's target. Size: S.

### 6. Decisions live in the shell (`fcis R1` 52, `R10` 17, `R3` 12, `R9` 10; MUST/SHOULD; systemic in app views and the core)

`fcis R1`: "Decisions are pure functions or GPUI-free models; entities, threads and loops only gather, call and apply."

| Area | Entries | Examples | Batches |
|---|---|---|---|
| `src/workspace.rs` | 7 | Tab-index arithmetic on move/close, the new tab's cwd policy, overlay exclusivity | b07 |
| `terminal_view.rs`, `terminal_element.rs` | 8 | Selection and scroll decisions in handlers, link hover policy | b00, b01 |
| `find_bar.rs` | several | Match navigation and wrap logic in the view | b02 |
| Settings dialog | the largest share, with `fcis R3`/`R9` | The section models read and write `config.toml` themselves (`config_edit` called from the view) | b04, b05 |
| Server core (`remote-agent/src/server/core.rs`, `core/{sessions,clients,holders}.rs`) | ~9 | `tick`'s exit and grace decisions, `should_exit`, handler policy branches | b10–b12 |
| `src/main.rs`, `src/reattach.rs` | several | Launch decisions inline in the GPUI closure | b01, b24 |

- **Cause:** views and handlers grew before the models existed. `SessionsModel` and `FontsState` show the target shape.
- **Fix:** one GPUI-free model per view or handler group, taking `now` and the values as arguments, unit-tested in its file. Do it when the file next changes (L overall).

### 7. Failures logged and replaced by a default (`railway R1` 36, `R6` 5, `R8` 8; MUST; app-wide)

`railway R1`: "never logged and replaced by a default"; `R6`: "the cause is kept"; `R8`: "shown on the tab or endpoint that failed".
- `src/config.rs`: an unknown theme is logged and the default used; font sizes and line height are silently clamped [b26].
- `src/terminal/links.rs`: `links::open` only logs a failed opener [b28].
- `src/workspace.rs` `listing_from`: falls back to an empty listing [b07].
- `src/remote/local/connection.rs`: `reconnect_local` drops the real cause [b25].
- `remote-protocol` `SessionMeta::from_value`: malformed fields get defaults [b20].
- `tests/e2e`: `events.join().unwrap_or_default()` [b32].

**Fix:** return the error to the tab, endpoint or settings error line that owns it. Size: M, in passes.

### 8. UI-thread blocking and unbounded queues (`process R13` 5, `R9` 4, `R15` 2, `R10` 2, `R14` 1, `R3` 1, `R8` 1, `R4` 1)

- **`process R13`**, "no blocking work on the UI thread":
  - `src/main.rs:863` `running_sessions()`, up to 2 s before the window opens (see doc drift).
  - Others in b01 and b24: the config read on reload, and `session::state_dir` work in the launch closure.
- **`process R9`**, "every queue between threads is bounded":
  - the terminal event channel (`src/terminal/server.rs`, `src/terminal/mod.rs`);
  - `connection.rs`'s outgoing writer queue (bounded only by the core's backpressure);
  [b23–b25]. `src/latency.rs:232-239`'s `samples` and `all_samples` also grow without bound for the life of a `--latency-log` run [b01, recorded as a smell].
- **`process R15`**, "files read by more than one version are written atomically": `src/config.rs` writes the default config with a plain `fs::write` [b26].
- **`process R10`**, "a refused connection is closed": refused connections are flushed and then dropped rather than shut down [b10].
- **`process R3`**, "a crash in one session's data never ends the role": the app's `SessionSink` calls `parser.advance` with no `catch_unwind` (`src/terminal/server.rs:72, 92`), unlike the core's feed [b24]. The holder has none around its `handle` and `spawn` either [b12, recorded as a smell].

### 9. Pure Windows logic tested only on Windows (`fcis R7` 14, `ports R7` 7; MUST; remote-agent and remote-protocol)

`fcis R7`: "Pure logic is not behind a platform gate"; `ports R7`: "a seam holds the effect, not the decision".

## Doc drift

- **`ports R4` against `testing`'s "platform pairs" idiom.** The testing doc endorses paired `cfg(unix)`/`cfg(windows)` tests, and the test support code and e2e harness have about 60 of them; `ports R4` forbids `cfg` outside seams. Suggestion: exempt test-only code from R4, or name `tests/**/support` and `tests/e2e/{main,capture}.rs` as seams.
- **`process R13` against CLAUDE.md.** CLAUDE.md's Reattach section describes the launch listing sessions on the UI thread before the window opens; R13 forbids blocking work there. Recommendation: move the listing to a background task, as the instance listener already does at `main.rs:767`, then leave R13 as written. The alternative is to document it as an exception.
- **`fcis R8` and test harnesses.** Batches applied R8 to pure helpers inside e2e and perf harness code. Say whether R8 covers harness code; this report counts those as smells.
- **`fcis`'s list of pure modules** names `cmdline` as pure, but `windows_default_program` calls `Path::is_file()`. Fix the code (pass a probe), not the doc.
- **The relay's platform gate** is `cfg(unix)` in `remote-agent/src/server/mod.rs` and `target_os = "linux"` in `remote-agent/src/main.rs`; they disagree on any non-Linux Unix. That matters for `port-to-macos`, and the docs should name one.
- **`remote-protocol`'s `transcripts.rs` module doc** says it pins protocols 1–2; the file also pins protocol 3 (`client-set-layout`).
- **Rules the code breaks almost everywhere:** none at a rate that suggests the rule is wrong. `fcis R1` and `types R7` are widespread, but the newer code (`SessionsModel`, `FontsState`, `term-core`) already follows them, so the code is behind, not the rules.
