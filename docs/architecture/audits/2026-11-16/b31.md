## Violations

1. `term-core/src/shell_integration.rs:110` — ports R4 (MUST; file NOT named in the exception) — "cfg attributes for a platform concern outside its seam module". `windows_paths: cfg!(windows),` in `impl Default for Scanner` picks the OSC 7 path style from the host platform inside pure code. Fix: take the path style as a constructor argument (a `PathStyle { Posix, Windows }` enum) and let the app's shell pass `cfg!(windows)` where it builds its `Parser`. `Parser::posix()` already exists for remote sessions.

2. `term-core/src/shell_integration.rs:110` — fcis R7 (MUST) — "Don't `cfg`-gate logic; `cfg` belongs to the seam that calls it". Same line: the default behaviour of the pure scanner differs per platform, so `Parser::new()` parses differently on Linux and Windows. Same fix. The test `the_latest_report_is_kept` (line 991) branches on `cfg!(windows)` for the same reason.

3. `term-core/src/shell_integration.rs:96-98,465-466` — types R1 (MUST) — "Not two bools, and not an Option whose meaning depends on another field". `Scanner { intermediate: bool, overflow: bool }` are independent flags, so they are fine. The violations are: `Marks.alt_snapshot: Option<Vec<..>>` beside `alt_resized: bool`, where `alt_resized` has meaning only while a snapshot exists and is set to false whenever the snapshot is taken (line 800). `track` (line 555) reads it with `std::mem::take(&mut self.alt_resized)` and `let Some(snapshot)`. Fix: `alt: Option<AltScreen { snapshot, resized }>`, or an enum `Primary | Alt { snapshot, resized }`.

4. `term-core/src/shell_integration.rs:351-357` — types R1 (MUST) — "an Option whose meaning depends on another field". `Command.exit: Option<i32>` is set only together with `end` (line 534-535), and `None` means both "not ended" and "shell gave no status". `input`, `output` and `end` are also an ordered progression held as three Options, which allows `end` without `output` in principle (`record` prevents it by hand). Fix: `exit` moves into a stage enum such as `Ended { at: Pos, exit: Option<i32> }`.

5. `term-core/src/status.rs:79-90` — types R1 (MUST) — "an Option whose meaning depends on another field". `Record.kind: Option<Kind>` is valid only when `state == Blocked`, and `Record.progress: Option<u8>` only when `state.is_activity()`. `parse` enforces this with `.filter(|_| state == State::Blocked)` (line 223) and `.filter(|_| state.is_activity())` (line 230), but the type does not, and `encode` can emit an invalid pair. Fix: carry the data on the variants (`Blocked { kind: Option<Kind>, progress }`, `Working { progress }`), or make the fields private behind a constructor (types R11).

6. `term-core/src/status.rs:295-301` — types R1 (MUST) — "an Option whose meaning depends on another field". `Update { changed: bool, notice: Option<Notice> }`: a notice implies `changed`, and `apply` builds the combinations by hand. Fix: an enum `Update { Unchanged, Changed, Notified(Notice) }`.

7. `term-core/src/status.rs:129,131,234,406` — types R7 (MUST) — "No sentinels: no empty string for 'none'". The root record's id is `""`: `Message::Report { id: String }` gets `id.unwrap_or_default()` (line 234) when the report had no id. `Clear { id: Option<String> }` shows the absence as `None` in the same module. `notice_for` and `effective_app` do `map_or("", ..)` (lines 379, 406) and `id.is_empty()` tests (lines 98, 379, 403, 446). The notice title is `unwrap_or("")` (line 381), so an empty title means "none". The empty id is documented ("the root is `""`") and is a real key. It still is the "empty string for none" pattern. Fix: `enum RecordId { Root, Child(String) }`; make `Notice.title` an `Option`.

8. `term-core/src/shell_integration.rs:609-610,653,487,631,655` — types R5 (MUST) — "Values in different spaces MUST NOT meet without a named conversion ... absolute lines and viewport lines ... One function owns each conversion." `Marks::line` (absolute to grid) and `pos` own the conversion. These do it inline instead: `prune` (`self.base + grid.topmost_line().0 as i64`), `restore` (`base + line as i64`) and `snapshot` (`self.line(pos) as i32`, an unchecked narrowing). `failed_spans` builds a `Pos { line: self.top, col: 0 }` only to convert it (line 752). Fix: add `Marks::absolute(grid_line: i32) -> i64` and a checked `grid_line(abs) -> Option<i32>`, and use them in these places.

9. `term-core/src/shell_integration.rs:1-1296` and `term-core/src/status.rs:160` (no fuzz test) — railway R5 (MUST) — "Every decoder has a fuzz test (`process R6`)". `Scanner`/`Parser::advance` and `status::parse` read bytes from any program. Neither file has a test that feeds arbitrary or random bytes, or all short byte strings, and asserts "no panic". Only hand-picked cases exist. I found no fuzz or property test anywhere under `term-core/` (a grep for "fuzz|proptest" there is empty); `term-core/src/osc.rs` and the replay tests were not in my batch. The code I read has no panicking path on input: slicing is guarded, there is no `unwrap` and no unchecked arithmetic on input, and buffers are bounded by `OSC_KEEP`, `CSI_KEEP`, `MAX_BODY` and `MAX_COMMANDS`. Fix: add a deterministic fuzz test (a seeded generator without a clock) in each file.

## Design smells
- `shell_integration.rs:366` `.max().unwrap_or(0)` in `Command::last_line`: 0 as a stand-in for "no lines" is unreachable (the prompt is always present), but it is a sentinel in shape.
- `shell_integration.rs:98` `windows_paths: bool` is really a path-style choice and would read better as a two-variant enum.
- `shell_integration.rs:566` `Box<dyn Iterator>` closure in `track`, allocated on every processor call (hot path); a pure-function split would also help `fcis R9`.
- `shell_integration.rs:384,382` `RowId = *const Cell`, a row's identity taken from the address of its cells. It relies on alacritty's row rotation (documented) and is compared only, but it is fragile against a grid reallocation on resize (resize goes through `snapshot`/`restore` instead).
- `Parser::advance` takes the `Mutex<Marks>` and locks it in several places per call, so the lock order (parser, then term, then marks) lives in this code's call structure alone.
- `shell_integration.rs:991,994` the test depends on the host platform (`cfg!(windows)`) rather than building `Parser::posix()` or a Windows-style parser on both.
- `status.rs:441 describe()` is dump formatting for the app's `--dump-screen-after` inside the shared state crate (it has a test, so it is only a placement smell).
- `status.rs:14-15` the `BASE64` engine config is repeated in `encode`, which uses `general_purpose::STANDARD`: encode and decode use different engines (padding differs only on decode), so they are consistent today.
