## Violations
1. `remote-agent/src/server/platform/windows/listen.rs:104` (also `:128` `check_path`, `:237` `check`) — fcis R7 (MUST; with ports R7) — "A pure helper MUST compile and be tested on every platform, whichever platform's data it handles... `cfg` belongs to the seam that calls it" / "A decision it needs (... a name) comes from a pure helper that is tested on every platform". `fn pipe_name(path: &Path) -> io::Result<Vec<u16>>` validates the `\\.\pipe\` prefix, an empty or backslash-bearing name and the 256-character cap; it and `check` (what a refused peer is) are pure decisions that exist only in the Windows module, so Linux CI never compiles or tests them. Smallest fix: move the name validation (taking `&str`) next to `endpoint`/`server_dir` in `brindle-remote-protocol`, tested there on every platform, and have `pipe_name` only encode to UTF-16. (`check` leans on `win::peer_allowed`, which is itself `cfg(windows)`, so it is lower confidence.)
2. `remote-agent/src/server/platform/windows/listen.rs:266` — types R7 (MUST) — "Absence that means something MUST be a variant... No sentinels". `Done(u32)` ("Ended with this error; with none, a client is connected") uses `0` (`NO_ERROR`) for "no error": `Connect::Done(NO_ERROR)` at :348, `if error != NO_ERROR` at :537, `matches!(state.connect, Connect::Done(_))` at :448. Smallest fix: `Connected` and `Failed(u32)` variants (or `Done(Result<(), u32>)`).
3. `remote-agent/src/server/platform/windows/listen.rs:856`, `:955`, `:986` — testing R7 (MUST) — "no fixed sleeps... To wait, poll for the condition within a scaled limit". `thread::sleep(Duration::from_millis(50));` (:856, waits for three connect threads to be "busy"), `thread::sleep(Duration::from_millis(1));` (:955) and `thread::sleep(Duration::from_millis(50));` (:986) (the last two make the reader slow on purpose). Smallest fix: for :856 poll until the waiting connects have been refused with `ERROR_PIPE_BUSY` (or drop the sleep, since the accepts are what unblock them); for :955 and :986 throttle the reader with a gate it is told to open (a channel or a counter) instead of wall time.
4. `remote-agent/src/server/platform/windows/lock.rs:68-73, 124, 132, 152` — testing R7 (MUST) — "Each test has its own temporary directory with a cleanup guard". `temp_dir(tag)` makes `brindle-lock-{tag}-{pid}` and every test ends with a manual `std::fs::remove_dir_all(&dir).unwrap();`, so a failed assertion leaves the directory behind; the child process in `a_lock_held_by_another_process_is_refused_until_it_dies` (:94-102) is not killed on failure either and sleeps 120 s (:88). Smallest fix: a guard type (Drop removes the directory and kills the child).
5. `remote-agent/src/server/platform/windows/pipe.rs:1475` — testing R8 (MUST) — "assert the rule, not a number that depends on timing or machine speed". `assert!(start.elapsed() < Duration::from_secs(20));` in `a_write_pending_before_registration_still_completes`. Smallest fix: drop it. `ev.wait(.., Some(30 s))` returning one event already shows the rule (the wait comes back by itself).
6. `remote-agent/src/server/platform/windows/pipe.rs:366-368, 461-464` — types R1 (MUST) — "States that exclude each other MUST be one enum... Not two `bool`s, and not an `Option` whose meaning depends on another field". `Reader { eof: bool, error: Option<u32> }` ("the read hit the end or failed", `ready()` is `end > start || eof || error.is_some()`; `read_done` can set `eof` after `error` through `if reader.handle.is_none() { reader.eof = true; }` at :543, and `read` then lets `error` win), and `State { registered: bool, abandoned: bool }`. Smallest fix: `enum Input { Open, Ended, Failed(u32) }` and `enum Life { Idle, Registered, Abandoned }`. Moderate confidence: the pairs are mostly, but not provably, exclusive.
7. `remote-agent/src/server/platform/windows/pipe.rs:529-546, 594-606, 384-386, 429-435, 655-687` — fcis R7/R8 (MUST; with ports R7) — "A decision MUST be a pure function or a method of a GPUI-free model" and "A pure helper MUST compile and be tested on every platform... Every pure function and model MUST ship with unit tests in its own file". `read_done` (error code into end of input, failure or retry), `write_done`, `Reader::ready`, `Writer::unsent`/`ready`, `State::readable`/`writable`/`sent`/`hung_up`/`meets` decide readiness from plain numbers, but live inside the `State` that owns raw handles and the `Mutex`, compile only on Windows, and are tested only through real pipes and loops (`mod tests` at :1328 has no test that feeds these plain values). Smallest fix: split `Reader`/`Writer` bookkeeping (byte counts, error codes, flags) into a handle-free model, tested with values, and have `State` call it. Moderate confidence: they can be read as part of the seam's translation job.
8. `remote-agent/src/server/platform/windows/pipe.rs:1064-1098` — railway R1 (MUST) — "An expected failure MUST be in the return type... Not... a log line with a default returned in its place". `input_waiting() -> bool` drops the `port.pump` error (`let _ = port.pump(Duration::ZERO);` :1081) and reports a failed `PeekNamedPipe` as "nothing waiting" (`.is_ok() && waiting > 0` :1096-1097), so a broken pipe reads as quiet. Smallest fix: return `io::Result<bool>`, or record the failure on the reader as `read_done` does. `Conn::input_waiting` (outside this batch) is the caller to adapt.

## Design smells
- listen.rs:335-351: the `ConnectNamedPipe` result to `Connect` mapping (pending, connected already, client gone, failed) is written inline in `State::listen`. A pure `fn connect_outcome(error: u32) -> Connect` would be unit-testable (fcis R10/R9).
- listen.rs:83, 88: `Identity(Result<Principal, String>)` stores the token error as text only so the type can be `Clone + Eq`; the `ErrorKind` is lost. Not covered by railway R4 as worded (a field, not a function return).
- lock.rs:52: `is_at` reports any failure of `File::open(path)` or the identity read as `false`, so a permission error reads as "the file was deleted". Probably right for the caller, but it merges two outcomes.
- pipe.rs:1189-1210: `wait` chooses a wait strategy (pump one port, wait on events, take turns every `TURN` = 10 ms) and falls back to `thread::sleep` when nothing is in flight. This is polling inside the seam, and `pump` errors are dropped (:1194, :1202). It is the documented design, but it is a decision written in place.
- pipe.rs and listen.rs are 1536 and 1080 lines, mostly tests and `unsafe` state machines; `ports R13` (organise by concern) is met, but `pipe.rs` holds the I/O state machine, the readiness facade and a wait function.
- Tests: absence assertions after a fixed 30 ms wait (listen.rs:680, 688; pipe.rs:1464), a 120 s child sleep (lock.rs:88), and 300/500/100-round stress loops (listen.rs:1013, pipe.rs:1355). They don't assert timing numbers, but the 30 ms absence checks pass trivially on a slow machine.
- pipe.rs:1042-1050: `Pipe::write` returns a fail-fast error only after having queued the bytes (`count` bytes accepted, then `Err`), so the caller can't tell how much was taken; harmless, since the pipe has failed.
