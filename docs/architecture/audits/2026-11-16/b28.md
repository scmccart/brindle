## Violations

### Untagged violations

1. `src/terminal/cmdline.rs:48` — `fcis R3` (MUST). Rule: "Pure code MUST NOT read the environment, files, `/proc` ... The caller reads them and passes values." The file header says "Pure, so they are tested on every platform", and `fcis`'s table lists `cmdline.rs` as pure. Code: `dirs.iter().map(|dir| dir.join(exe)).find(|path| path.is_file())`. `windows_default_program` stats the disk, so its tests have to build temp trees (`bin_dirs`, lines 127-144). Smallest fix: the shell passes the directories' file listings, or an `exists` result per candidate (for example `impl Fn(&Path) -> bool`, with the shell passing `Path::is_file`). Then unit-test the order with a table instead of files.

2. `src/terminal/cmdline.rs:12` and `:41` — `ports R4` (MUST), reported without a tag. Rule: "code outside [the seam] MUST NOT carry a `cfg` for that concern." Code: `#[cfg_attr(not(windows), allow(dead_code))]` on `windows_editor_command` and `windows_default_program`. `cmdline.rs` is not a seam and is not among the files the exception names, so the exception does not cover it. This is low severity: the attribute only suppresses dead-code warnings and gates no logic. Smallest fix: call the helpers from an ungated site, or `allow(dead_code)` them without a platform condition.

3. `src/terminal/mod.rs:1214-1219` (`default_program`, the `#[cfg(unix)]` variant) — `ports R7` (MUST). Rule: "A decision it needs (what to run, the environment ...) comes from a pure helper that is tested on every platform." Also `fcis R3` and `fcis R7` ("Don't `cfg`-gate logic"). Code: `let program = std::env::var("SHELL").unwrap_or_else(|_| "/bin/sh".into());`. The unix default shell is decided inline, reads the environment itself, is gated on `unix`, and has no test. The Windows variant does it correctly: it reads the environment and passes values to `cmdline::windows_default_program`. Smallest fix: add an ungated `cmdline::unix_default_program(shell: Option<&str>, args)` with a test, and have the gated shell function only read `SHELL`. (`cfg(unix)` itself is [EXCEPTION ports R4], tagged below.)

4. `src/terminal/mod.rs:1159-1203` (`spawn_request`) — `fcis R9` (SHOULD). Rule: "A function that decides *and* acts SHOULD be split: return what to do as data." Code: `.or_else(dirs::home_dir).filter(|dir| dir.is_dir())`, and `profile.working_directory()` reads the home directory through `config::expand_tilde`. The function decides the request (host to local or remote, program, directory, environment) and also reads the environment and the disk. Its test `a_spawn_request_follows_its_host` depends on `/var/log/brindle-nowhere` not existing on the machine running it. Smallest fix: pass `home: Option<PathBuf>` and an `is_dir` result (or a predicate) in from `spawn`.

5. `src/terminal/mod.rs:757-778` (`Terminal::jump_to_prompt`) — `fcis R1` (MUST). Rule: "A decision MUST be a pure function or a method of a GPUI-free model: what to show ... an ordering". Code: `let new_offset = match target { Some(line) => (-line).clamp(0, history), None if previous => offset, None => 0 };`. The scroll-offset decision (clamp, and where to go when there is no target) sits inside an entity method and is reachable only with a `Term` and a `Context`. Smallest fix: extract `fn jump_offset(target: Option<i64>, offset: i64, history: i64, previous: bool) -> i64`, unit-test it, and have the entity apply the result.

6. `src/terminal/mod.rs:245-252` and `:989-991` (`exited`, `attaching`, `failed`, `replaying`) — `types R1` (MUST). Rule: "States that exclude each other MUST be one enum ... Not two `bool`s." Code: `exited: bool, attaching: bool, failed: bool`, and `shows_only_message(&self) -> bool { self.attaching && self.failed }`. `mark_lost` sets `exited`, and the `Failed` event sets `failed` and then calls `mark_lost`. So `failed` implies `exited`, and the flags describe one lifecycle (running, attaching, ended, failed, or attach failed). Only `replaying` is independent. Smallest fix: one `Life` enum (`Running`, `Attaching`, `Ended`, `Failed { attach: bool }`, or similar) in place of the three flags.

7. `src/terminal/mod.rs:1172-1175` — `types R7` (MUST). Rule: "No sentinels: no `-1`, no `0` id, no empty string for 'none'." Code: `match request.command.as_str() { "" => format!("open a shell on {}", host.name()), command => ... }`. The wire field `SpawnRequest.command` uses `""` for "no command", and the app branches on it after building the request. Smallest fix: derive `doing` from `command_override` and `profile.command` (both `Option`s) before the request is built. The frozen wire encoding stays; only the branch on the empty string goes.

8. `src/terminal/mod.rs:894` — `ports R8` (SHOULD). Rule: "Platform types (`HANDLE`, `RawFd`, ... `windows` crate types) stay inside the seam module." Code: `session.reparent(hwnd.0 as usize as u64);`. `win::hwnd` returns `windows::Win32::Foundation::HWND`, and `terminal/mod.rs` reads its `.0` field. Smallest fix: have `win::hwnd_value(window) -> Option<u64>` do the conversion inside the seam. (The `cfg(windows)` at line 890 is [EXCEPTION ports R4], tagged below.)

9. `src/terminal/mod.rs:104,112,413,443,481` (the `unbounded()` channel behind `Listener`/`spawn_events`) — `process R9` (MUST). Rule: "Every queue between a producer and a slower consumer MUST have a high and a low mark." Code: `UnboundedSender<ChannelEvent>` is fed from the connection's reader thread (a `Wakeup` per read, plus found OSCs, title changes and bells) and drained by the UI task, which is paced (`pace::PACE`, `BUDGET`). `Batch::coalesce` thins the events only after they have queued, and nothing pauses the producer. Mitigation: the output bytes themselves are not queued here, since they go straight into the `Term`, and the client queue has its own `PAUSE`/`RESUME`. So the growth is of small events only, but the rule's words cover a queue of this kind. Smallest fix: coalesce at the producer (an atomic `woke` flag, as `OutputMarker` already does for the generation), or bound the channel with a high/low mark.

10. `src/terminal/links.rs:111-116`, `:119-121`, `:126-152`, `:156-176` (`open`, `open_default`, `open_with`) — `railway R1` (MUST). Rule: "An expected failure MUST be in the return type ... Not a panic, a sentinel value, or a log line with a default returned in its place." Code: `open(uri: &str)` returns `()`. A rejected scheme, a failed thread spawn, a missing opener (`Err(err) => log::warn!(...)`) and a non-zero exit (`Ok(status) if !status.success() => log::warn!(...)`) all end in `log::warn!` and nothing is returned. Opening a link on a machine without `xdg-open` fails silently as far as the user can see. Smallest fix: `open` returns an outcome (`Opened`, `NoScheme`, `CouldNotStart(io::Error)`) for what it can know synchronously, and the caller shows it (for example as a bell or a status). The result of the detached opener's exit is still log-only, unless reported back through the event channel.

11. `src/terminal/process.rs:79-93` (`windows_rows`) — `railway R12` (MUST). Rule: "A seam module MUST turn the platform's failure into the caller's type." Code: `let Ok(snapshot) = CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0) else { return rows };`, and `Process32FirstW(...).is_ok()` is treated the same way. A failed snapshot becomes an empty `Vec`, which looks the same as "no processes", with no log line. Smallest fix: return `io::Result<Vec<ProcessRow>>` or an outcome. `Snapshot::take` can then keep the failure (or log it) and `foreground_name` can fall back to `None` knowingly.

12. `src/terminal/links.rs:313-329` (`opener_gets_the_uri_as_one_argument`; the Windows twin at `:293-309` has the same shape) — `testing R7` (MUST). Rule: "Each test has its own temporary directory with a cleanup guard." Code: `std::env::temp_dir().join(format!("brindle-opener-test-{}", std::process::id()))`, with `std::fs::remove_dir_all(&dir).ok();` at the end of the test body. A failing assertion skips the cleanup. The name is per process, not per test. The sibling tests in `cmdline.rs` do it right with `RemoveOnDrop`. Smallest fix: use a guard and a name that includes the test.

13. `src/terminal/pace.rs:143-150` (`drain_stops_at_the_budget`) — `testing R7` (MUST). Rule: "no fixed sleeps". Code: `std::thread::sleep(BUDGET / 2 + MS);` inside the `drain` callback, so the test's length and outcome depend on the scheduler. The comment at lines 134-136 shows `testing R8` was handled by asserting against recorded times, so only R7's sleep is reported. Smallest fix: give `drain` a `now` or clock parameter, or split the budget check into a pure `fn within_budget(start, now) -> bool` and test that with constructed `Instant`s.

14. `src/terminal/mod.rs` (`resolve_color` at 1298-1308, `term_config` at 266-284, `parser_for` at 1207-1210) — `fcis R8` (MUST). Rule: "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`." The test module (1317-1585) has no test that calls `resolve_color`, `term_config` (the config-to-`term::Config` mapping, including the `osc52` choice) or `parser_for` (local `Parser::new()` against remote `Parser::posix()`, which matters for OSC 7 paths). Smallest fix: add tests for the three mappings. In addition, `Terminal::default_color` is exercised only through `palette_color`.

## Design smells

- `src/terminal/pace.rs:33-42` (`drain`) reads `Instant::now()` and decides when to stop (`start.elapsed() < BUDGET`) inside a stream-draining helper, in a module whose `step` is deliberately pure with `now` as an argument. It is shell-side, because it takes a stream and a callback, so `fcis R2` (pure code) does not strictly apply. The stop decision is the reason `drain_stops_at_the_budget` needs sleeps (violation 13).
- `src/terminal/mod.rs:994-998` (`impl Drop for Terminal`) still detaches or closes in `Drop`. `process R16` is met because the quit path does it explicitly (`quit_with`). The Drop remains a second path, and `leave` has no "once" guard of its own despite the doc comments at 929-940 ("later calls, and the drop, do nothing"). The guard is presumably in `Session`, which I did not read.
- `src/terminal/mod.rs:942-960` — the doc comment above `set_layout` (946-951) is the leftover first half of `leave`'s comment. The text sits on the wrong function.
- `src/terminal/mod.rs:870-881`, `:903-922`, `:1184-1187` — the 1 s title poll, `working_directory` and `spawn_request` do `/proc` reads and `is_dir` stats on the UI thread (the Windows `dir.is_dir()`, `read_link` on `/proc/<pid>/cwd`, `read_to_string` on `/proc/<pid>/stat`). They are cheap, and `process R13`'s named calls return at once, but a network path could block.
- `src/terminal/mod.rs:1298` — `resolve_color` takes the whole `&Terminal` (which holds a `Task`, a `Session` and a `FairMutex`) only to call `default_color`. It should take `&Theme`, since `palette_color` is already pure over it. This is close to `fcis R5` for a function used as pure.
- `src/terminal/mod.rs:200-206` — the `Backend::Remote` name ("read-only message") reads as `Host::Remote` and invites confusion. `Backend::Message` would be clearer.
- `src/terminal/mod.rs:255,258` — `pub theme` and `pub last_activity` are public fields on a type with invariants.
- `src/terminal/mod.rs:457,1169,1209` — `host.is_local()` bool tests are used where `Host` is a two-variant enum. The `Host::Local` match arms elsewhere (873, 906, 910) are the better shape. `types R8` is satisfied either way.
- `src/terminal/mod.rs:514-543` (`flush_sync`) holds a small decision (`t <= Instant::now()`) inside an entity. `fcis R10` says to question it. It is a one-line comparison.
- `src/terminal/links.rs:111-116` (`open`) reads `BRINDLE_LINK_OPENER` and chooses the program inside the function that also acts. It is the documented stand-in at the seam, but a pure `choose_opener(env: Option<String>) -> Opener` would make the choice testable. `open_default` (Windows) repeats `open_with`'s scheme check and thread spawn.
- `src/terminal/keys.rs`, `mouse.rs` — clean: pure, tested, no panics on input. `mouse::report` indexes nothing and `32 + 1 + v` is in `usize`.
- `Cargo.toml:16` — the app depends on `alacritty_terminal` directly as well as through `brindle-term-core`, and `keys.rs`, `mouse.rs` and `mod.rs` import it. The dependency rule's picture routes it through `term-core`. `ports R3` binds only the crates below the app, so no rule is broken.
