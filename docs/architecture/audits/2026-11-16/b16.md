### testing R7 (MUST: "no fixed sleeps ... To wait, poll for the condition within a scaled limit")
- core.rs:607 — `thread::sleep(Duration::from_millis(500));` then `assert!(alive(kept_pid), ...)`. Fix: wait on an observable (e.g. a `list` from another client or a core log line showing the owner-gone handling finished) instead of padding.
- core.rs:638 — `thread::sleep(Duration::from_millis(500));` then `assert!(alive(pid))`. Same fix.
- core.rs:665 — `thread::sleep(PAST_GRACE);` (12 s) before `assert!(alive(pid))`. Fix: poll for the core's log line that the grace period ended (it logs adoption/hang-ups), then assert.
- core.rs:1153 — `thread::sleep(Duration::from_millis(500));` then `assert!(alive(pid), ...)`.
- core.rs:1322 — `thread::sleep(PAST_GRACE);` then `assert!(alive(left_pid), ...)`.
- core.rs:1424 — `thread::sleep(Duration::from_millis(500));` then `assert!(alive(killed_pid) && alive(kept_pid));`.
- core.rs:1446 — `thread::sleep(Duration::from_secs(1));` then `assert!(alive(pid), ...)` (also bounds the test to returning inside a 3 s linger on a loaded machine).
- core.rs:1453 — `thread::sleep(Duration::from_secs(4));` (past the 3 s linger) then `assert!(alive(pid), ...)`.
- core.rs:1506 — `thread::sleep(Duration::from_millis(2100));` so that `detached_secs >= 2`. Fix: poll `list` until `detached_secs >= 2`.
- core.rs:1558 — `thread::sleep(Duration::from_millis(300));` "Another thread reads the flood" before the DETACH, inside a 20-iteration race loop. Fix: wait until the flood's output has been read (e.g. a counter the draining thread bumps).
- core.rs:1932 [Windows module] — `thread::sleep(Duration::from_secs(3));` "Long enough for the flood to fill every queue". Fix: poll the core's working set or a PAUSE-related observable.
- core.rs:899-905 and 2080-2086 [2080 is Windows] — `loop { match other.attach(...) { Ok(replay) => break replay, Err(_) => thread::sleep(Duration::from_millis(20)) } }`: a poll with no limit at all (never gives up, so a regression hangs the suite), and it swallows the refusal. Fix: bound it with `eventually(TIMEOUT, ..)`-style deadline.
- (Scaling) every limit in the file is `TIMEOUT` (30 s const) or a literal `Duration::from_secs(N)` (5, 3, 60); none scales with a factor, so "within a scaled limit" is not met anywhere. Counted once here, not per site.

## Design smells
- Negative-existence assertions ("the session is still alive after N ms") cannot be written as a poll for a positive condition without an observable; the core logs could provide one (the core already logs adoption and hang-ups). Eleven of the fixed sleeps above are of this kind.
- core.rs:433 — `thread::sleep(Duration::from_millis(30))` deliberately throttles a slow client; intent is clear, but it makes the test's duration speed-dependent (60 s deadline).
- core.rs:1531 — `DETACH_RACE_ATTEMPTS = 20` repeats a race and asserts none was lost; it detects but does not guarantee the race occurred (the sleep(300) at 1558 is what tries to set it up). Probabilistic detection, not a rule check.
- core.rs:1739-1744 and core.rs:2221-2224 [Windows] — the scope test and the ConPTY REPARENT test `return` early with `eprintln!("skipped: ...")` and report green. `testing R9` ("no skip") is about flakes, so not a violation, but the pass is not "verified" (cf. `testing R17`, `R11`).
- core.rs:762 — `a_panicking_emulator...` needs a debug core (`inject_fault` is `#[cfg(debug_assertions)]` in src/server/core/screen.rs) but the test has no matching cfg; under `cargo test --release` it fails instead of skipping.
- core.rs:1746 — the scopes test sets `BRINDLE_NO_SCOPE=0` so roles really call `systemd-run --user --scope` in the developer's own user manager, outside the test's private directory (`testing R4`: touches nothing of the user's). Scopes end with their processes, so low impact.
- core.rs:1113 — uses `SystemTime::now()` against the core's wall-clock `started`; fine for a test, but ties to the host clock.
- Windows `on_windows` module (core.rs:1766-2316) is unverified from Linux (`testing R17`: its first run on Windows is its first run).
