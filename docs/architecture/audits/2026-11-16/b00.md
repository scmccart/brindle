## Violations

1. `src/actions.rs:441-457` (`bind_keys`) — railway R1 (MUST), with fcis R1 (MUST) — "Not a panic, a sentinel value, or a log line with a default returned in its place" / "what to ... keep or drop" is a decision. A user keybinding to an unknown action or with an invalid keystroke is an expected failure. It is logged and skipped inside the shell function: `log::warn!("unknown action {name:?} bound to {keys:?}")` and `log::warn!("invalid keybinding {keys:?}: {err}")`. Nothing returns the rejections, so the config warning can't show them, and the keep/drop split is untested. Smallest fix: a pure `fn user_bindings(&[(String,String)]) -> (Vec<KeyBinding>, Vec<Rejected>)` that returns the findings as data. `bind_keys` binds the first list and reports the second. Unit-test it in this file. (Moderate confidence on the railway R1 reading; the fcis R1 half is plain.)

2. `src/actions.rs:446` — railway R9 (SHOULD) — "`unwrap` and `expect` ... SHOULD be `expect("why this can't fail")`". Code: `gpui::KeyBindingContextPredicate::parse("Terminal").unwrap()`. The literal is constant, so failure would be a bug, but the call has no reason and is rebuilt on every loop iteration. Smallest fix: build it once above the loop, with `.expect("\"Terminal\" is a valid context predicate")`.

3. `src/actions.rs:110, 424` (doc at 93) — types R7 (MUST) — "No sentinels: no `-1`, no `0` id, no empty string for 'none'"; "Absence that means something MUST be a variant". Code: `ActivateTab(usize::MAX)` stands for "the last tab" (`|| Box::new(ActivateTab(usize::MAX))`, `let index = if n == 9 { usize::MAX } else { n - 1 }`). It is an integer sentinel in an action's payload, and the handler must special-case it. Smallest fix: `ActivateTab` takes a `TabTarget { Index(usize), Last }`, or `ActivateLastTab` becomes its own action. (Borderline: it is a special value, not strictly "absence".)

4. `src/actions.rs:291-294` (`ActionMenu`) — types R11 (SHOULD) — "A type with an invariant SHOULD have private fields and constructors that enforce it". Code: `pub entries: Vec<MenuEntry>` and `pub actions: Vec<Option<Box<dyn Action>>>`. The two vectors must stay the same length and agree on where the separators are, but both fields are public. `action(ix)` indexes one by the other, so a caller that pushes to one breaks it. Smallest fix: make the fields private and expose accessors (`entries()`), or store one `Vec<(MenuEntry, Option<Box<dyn Action>>)>`.

5. `src/actions.rs:251, 298` (`palette_commands`, `ActionMenu::new`) — fcis R9 (SHOULD) — "Reach for a callback parameter only when the output must interleave with a stream in order". Both take a closure that the caller points at GPUI (`available: impl FnMut(&dyn Action) -> bool`, `shortcut: impl Fn(&dyn Action) -> Option<SharedString>`). Neither output interleaves with a stream. Smallest fix: `palette_commands` returns every labelled action and the caller filters. `ActionMenu::new` takes a precomputed `HashMap`/slice of shortcuts.

6. `build.rs:9, 16` — ports R4 (MUST) — "code outside [the seam] MUST NOT carry a `cfg` for that concern". Code: `#[cfg(windows)] resources();` and `#[cfg(windows)] fn resources()`. The Windows resource embedding is a platform concern. `build.rs` is not in the seam list, and the exception names `src/workspace.rs`, `src/terminal/mod.rs`, `src/main.rs` and `src/remote/local.rs`, not `build.rs`. NOT tagged: the file is not named in the exception. Practically, `build.rs` is the only home of this concern (`remote-agent/build.rs` is its twin), so the likelier fix is to add build scripts to the doc's seam list rather than change code.

7. `src/config_edit.rs:792` — ports R4 (MUST) — "code outside [the seam] MUST NOT carry a `cfg` for that concern". Code: `#[cfg(unix)] #[test] fn save_writes_through_symlinks`. It is test-only, and it gates symlink creation (`std::os::unix::fs::symlink`). NOT tagged: the file is not named in the exception ("and a few others" is not a list). Smallest fix: move the symlink helper into a test-support seam, or list test modules as allowed.

8. `src/config_edit.rs:134-135` and `199-200` (`custom_themes`, `profiles`) — railway R1 (MUST) — "an expected failure MUST be in the return type ... Not ... a log line with a default returned in its place". Code: `let Ok(root) = toml::from_str::<toml::Table>(&doc.to_string()) else { return Vec::new() };` and `let Some(toml::Value::Table(themes)) = root.get("themes") else { return Vec::new() };`, and the same for `profiles` with `Value::Array`. A file where `themes = 3` or `profiles = "x"` (the wrong shape) gives an empty list with no finding. `upsert_profile` later says "`profiles` is not an array" only on append. The comment justifies the first `else` as unreachable, but the shape check is a real case. Smallest fix: return `Result<Vec<..>, ShapeError>`, or a `Listing`-style enum with a `Malformed` case, so the dialog can show it. (Lower confidence than the rest.)

9. `src/config_edit.rs:169, 414-415, 424-425, 428-429, 435-436` — railway R9 (SHOULD) — "SHOULD be `expect("why this can't fail")`". Code: bare `.unwrap()` in `(2..).map(..).find(..).unwrap()` and `a.get(i).cloned().unwrap()`, `a.get_mut(i).unwrap()`, and the same with `j`. The invariants hold (`i`, `j` are bounded by `count` and by the `profile_at` check, and the iterator is infinite), but the code states none. Smallest fix: `.expect("...")` naming the invariant, or restructure `move_profile` to use `slice::swap`-style access that can't miss.

10. `src/config_edit.rs:55, 178, 281, 494` — railway R9 (SHOULD) — same words. Code: `.expect("theme table")`, `.expect("themes table")`, `.expect("new profile")`, `.expect("font table")`. They name the thing, not why it can't fail. Smallest fix: write the reason (for example `"just inserted as a table"`).

11. `src/config_edit.rs:187-190` (`ProfileRef`) — types R3 (MUST) — "An identity MUST be the value that stays stable, never a position". Code: `pub struct ProfileRef { pub index: usize, pub name: Option<String> }`; the doc comment says "Profiles have no ids". The position is the identity, checked against the name before every write (`profile_at`), so a stale position is refused and not misapplied. That mitigates the bug the rule is for, but the identity is still a position plus a non-unique name; two profiles can share a name, and `delete_profile(.., name)` takes a second, separate name. Smallest fix: if profiles get no ids, document the check as the rule's accepted form. Otherwise key by an occurrence count of the name, or add a stable id.

12. `src/config_edit.rs:749-754` (`temp_dir`) and its eight users (757-814) — testing R7 (MUST) — "Each test has its own temporary directory with a cleanup guard". Code: `std::env::temp_dir().join(format!("brindle-config-edit-{}-{name}", ..))`, then `std::fs::remove_dir_all(dir).ok();` as the test's last line. Names are per-pid and per-test, so they don't collide. But the cleanup is a trailing statement, not a guard: a failed assertion leaves the directory, and the next run's `remove_dir_all` at creation is what clears it. Smallest fix: a `TempDir` guard type with `Drop`, as the other crates' tests use (if one exists), or `tempfile`.

## Design smells

- `src/actions.rs:105` `ACTIONS` is a tuple `(&str, Option<&str>, fn)`, and its fields are read by position in four places. A named struct would read better.
- `src/actions.rs:261-263` `menu_label` builds every action in the table (`build()`) on each lookup to compare. The same happens per item in `ActionMenu::new`.
- `src/actions.rs:93-101` `ActivateTab(usize)` and `NewTabWithProfile(usize)` carry positions. This is by user intent ("alt-3", "ctrl-alt-2"), so not a types R3 case, but the profile one shifts when profiles are reordered.
- `src/actions.rs:328-335` key contexts are string literals shared by hand with the views that set them. A shared constant per context would stop typos.
- `src/actions.rs:431` `bind_keys` has no test; its pure half would.
- `src/config_edit.rs:20-41` `save` does file IO (canonicalize, read, create_dir_all, write, rename) in a module that is otherwise pure document editing. Callers on the UI thread would block (process R13); the callers are outside these files, so this was not checked.
- `src/config_edit.rs:120` `theme_references(&mut DocumentMut, ..)` takes `&mut` for a read-only question, because `for_each_reference_slot` is mutable. A read-only twin would let callers hold `&DocumentMut`.
- `src/config_edit.rs:132-140, 198-208` `custom_themes` and `profiles` re-serialize the whole document to a string and re-parse it on each call.
- `src/config_edit.rs:404` `move_profile(.., up: bool)` takes a direction as a bool. A `Direction` enum is clearer.
- `src/config_edit.rs:482-548` `set_font_family(table: &str)` and `set_font_number(key: &str)` take open strings for closed sets (`font`/`ui_font`; `size`/`line_height`). Any other string silently creates an arbitrary table or key. An enum would reject it at compile time; no numbered rule covers it.
- `src/config_edit.rs:193` `IMPLICIT_PROFILE = "Shell"` duplicates a name `Config::normalized` also owns, kept in step by a comment.
- Tests assert on error text (`:710`, `:725`, `:733-734`, `:763`, `:786`, `:991`, `:1026`: `contains("reopen")`, `contains("not valid TOML")`, `contains("last profile")` and others). That is railway R4's "never compare error text" in spirit, and it comes with the `Result<_, String>` exception. The dialog's use of the same texts (`CHANGED`) was not checked.
- `Cargo.toml:41-79` the platform dependency blocks (`cfg(unix)`, `cfg(target_os = "linux")`, `cfg(windows)`) are manifest-level `cfg`s for platform concerns. The rule text speaks of source attributes, so this is not counted.
- `build.rs:6, 20, 25-26` `std::env::var(..).unwrap()` on Cargo-provided variables is bug-only, so not a railway R9 breach. `.expect("compiling assets/windows/brindle.rc")` is the build failing loudly, which is right for a build script.
