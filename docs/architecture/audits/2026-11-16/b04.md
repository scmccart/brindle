## Violations

1. `src/settings_dialog.rs:383, 482-493, 687-690, 843-844, 348-350, 499` — fcis R3 (MUST) — "Pure code MUST NOT read the environment, files, ... The caller reads them and passes values." (R5 puts "models" in the same class.) The GPUI-free `Model` reads and writes the config file itself: `reload_entries` (`std::fs::read_to_string(&self.config_path)`), `request_delete` (`std::fs::read_to_string(&self.config_path)`), `save` (`config_edit::save(&self.config_path, edit)`), `select_section` (`self.profiles.reload(&self.config_path, ...)`, `self.fonts.reload(&self.config_path, ...)`), and `Model::new` (`ProfilesState::new(&config_path, ...)`, `FontsState::new(&config_path, ...)`). Note: CLAUDE.md describes `FontsState` as reading the file, so this is an established pattern, but the rule's words still cover it. Fix: the view reads the file text and passes the parsed doc in; the model returns an `Outcome`/edit description and the view writes it.

2. `src/settings_dialog.rs:497-530, 562-572, 631-664, 701-716` — fcis R9 (SHOULD) — "A function that decides *and* acts SHOULD be split: return what to do as data". `confirm`, `apply`, `save_editor` and `delete_selected` validate, write the file, reload the entries and re-select in one body (e.g. `let saved = self.save(|doc| { ... config_edit::upsert_theme(doc, &name, &theme); ... });` followed by `self.reload_entries()`). Fix: return a `Write(edit)` value and apply the result in a second step.

3. `src/settings_dialog.rs:1286-1304` — fcis R1 (MUST) — "A decision MUST be a pure function or a method of a GPUI-free model: what to show, send, open, keep or drop". `SettingsDialog::enabled` (a view method) decides which buttons are pressable from the model's internals: `(Section::Profiles, Btn::Delete) => editable && profiles.entries.len() > 1`, `(Section::Profiles, Btn::Up) => editable && profiles.selected > 0`, `(Section::Fonts, Btn::Apply) => model.fonts.can_apply() && model.fonts.read_only.is_none()`. It also feeds `stops()`, so it decides the Tab order. It has no unit test (see 6). Fix: a `Model::enabled(Btn)` or a pure `fn enabled(section, kind, &ViewFacts, Btn)` with tests.

4. `src/settings_dialog.rs:1336-1356` (`place_focus`) and `1642` (`render_list`) — fcis R10 (SHOULD) — "A new conditional in a view ... SHOULD be questioned ... If it chooses between outcomes from state, it moves into the model". `place_focus` chooses whether and where to move focus (`moved`, `section_changed`, `valid`, `menu_open`) in the entity. `render_list` decides which row is the active one in `render` (`let active = entry.name == model.active && model.selectable_index(&model.active) == Some(ix);`). Fix: a model method `active_row() -> Option<usize>` and a pure `focus_target(placed_for, view, focus facts) -> FocusMove`.

5. `src/settings_dialog.rs:420-430, 468-479, 498-513, 534-536, 576-586, 598-607, 668-677, 721-737` — fcis R10 (SHOULD) — same rule, in the model. Eight `Model` methods open with the same ladder `if self.section == Section::Fonts { return }` / `if self.section == Section::Profiles { ...delegate...; return }` before the theme code. Section dispatch is repeated per method rather than being one `match self.section` returning a richer value. Fix: split the theme state into a `ThemesState` beside `ProfilesState`/`FontsState` and dispatch once per operation.

6. `src/settings_dialog.rs:893-908, 864-873, 927-930, 1286-1304` — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`". `Model::start_duplicate`, `Model::move_profile`, `Model::theme_names`, `Model::take_renames`, `Model::profile_preview` and the view's `enabled` (a decision, see 3) have no test in this file (grep of the test module finds none). Some may be covered in `settings_dialog/profiles.rs` (not in this batch); the wrappers in this file are not.

7. `src/settings_dialog.rs:200-212, 391-410, 467-480, 710-714` — types R3 (MUST) — "An identity MUST be the value that stays stable, never a position... An index is valid only within the render or the call that computed it." `Model::selected: usize` (the highlighted theme) and `Editor::return_to: usize` are list positions stored across events; `delete_selected` deliberately keeps the index over a `reload_entries` (`self.selected = previous.min(self.entries.len().saturating_sub(1))`), and `cancel` restores `self.selected = editor.return_to`. Other paths do re-resolve by name (`save_editor`, `selectable_index`), so this is the one place a rebuilt list is addressed by position. Fix: keep the selected theme's name, resolve to an index at render.

8. `src/settings_dialog.rs:249-251, 264-268, 275-285, 1423-1424, 1781-1782` — types R5 (MUST) — "Values in different spaces MUST NOT meet without a named conversion... One function owns each conversion." The editor field index space (0 = name) and the slot index space (`SLOTS`) are converted inline in at least six places: `let ix = n - 1;`, `n => &self.colors[n - 1]`, `SLOTS.get(n - 1)`, `.position(...).unwrap() + 1`, `self.editor_scroll.scroll_to_item(field - 1)`, `let field = ix + 1;`. 10. `src/settings_dialog.rs:1090-1094, 1395-1406` — types R12 (MUST) — "A wrapper, variant or abstraction MUST exist for a meaning the code has today. 11. `src/settings_dialog.rs:299-305, 331-332, 798-803` — types R1 (MUST, borderline) — "States that exclude each other MUST be one enum... not an `Option` whose meaning depends on another field." `Model` holds `section`, `mode: Mode` (valid only while `section == Theme`), and `profiles.mode` (valid only while `section == Profiles`), and `mode_kind()` has to reconcile them with a nested match. `ModeKind::Form` is only valid for Fonts, but `(Section::Theme, ModeKind::Form)` is representable (the `footer_buttons` match absorbs it with `(_, ModeKind::Form)`). ## Design smells
- The module doc says `Model` "has no GPUI dependency" but it imports `gpui::Keystroke` for `Model::key`; plain data, but the claim is inaccurate.
- File IO (read at `Model::new`, `reload_entries`, `select_section`; write at `confirm`) runs on the UI thread inside event handlers. Small config file, not in `render`, and the rule's examples are about connecting, so not reported against process R13.
- `Model::save` returns `Result<(), ()>` while the real error goes into a side field `self.error`.
- `src/settings_dialog.rs:852-853`: the doc comment "Cycles through the sections (ctrl-tab)." sits on `edge_section`, not `next_section`.
- `src/settings_dialog.rs:270`: stray blank line before the closing brace of `impl Editor`.
- `render` clones the whole `Editor` each frame (`let editor = editor.clone();`, line 1876) only to satisfy the borrow checker.
- `render` calls `follow_focus(&mut self ...)`, which mutates scroll handles and `scrolled_to` during rendering.
- The view reads model internals directly (`model.profiles.read_only`, `profiles.selected`, `model.fonts.read_only`, `model.mode`, `model.selected`), so the model's encapsulation is nominal.
- `SettingsDialog` carries about 30 fields across three sections (shared focus handles by `Btn`); each section's view state could sit with its model.
- `render_list` calls `selectable_index` per row (O(n^2) over a small list).
- Test `Fixture` uses `std::env::temp_dir()/brindle-settings-<pid>-<name>` with a `Drop` guard and unique case names, so it is parallel-safe (testing R7 OK); several tests assert on hard-coded list positions (`model.select(5)`, `select(7)`), which break if a built-in theme is added.
