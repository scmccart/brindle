## Violations

1. `remote-agent/src/server/core/sessions.rs:856` and `:872` — ports R4 (MUST) — "code outside it MUST NOT carry a `cfg` for that concern". This file is not named in the README exception, so it carries no tag. The server core (`server/core/`) is not a seam. Code: `#[cfg(windows)] pub(super) fn client_reparent` and `#[cfg(not(windows))] pub(super) fn client_reparent`, with the Linux arm answering `"REPARENT is for Windows; this core runs on Linux"`. Also fcis R7 (MUST), "Don't `cfg`-gate logic": the Linux refusal is a decision gated by `cfg` in the core. Smallest fix: one `client_reparent` in the core with no cfg, which asks a platform item (for example `platform::sys::supports_reparent()` or a `reparent` item that returns a refusal value) and answers with the error from that value.

2. `remote-agent/src/server/daemon.rs:7` and `:10` — ports R4 (MUST) — "code outside it MUST NOT carry a `cfg` for that concern". The file is not named in the exception and is not in the seam list. Code: `#[cfg(windows)] pub use super::platform::daemon::launch;` and `#[cfg(unix)] pub use super::platform::daemon::start_role_as;`. The facade re-exports items that exist on only one platform, so the per-platform sets don't export the same names (ports R5). Smallest fix: export both items from both `platform::daemon` modules (the unused one returning an `Unsupported` io error), then drop the cfgs here.

3. `remote-agent/src/server/core/sessions.rs:158`, `:190`, `:192` — fcis R2 (MUST) — "Pure code MUST take time as an argument and MUST NOT call `Instant::now()`". The state model's own methods read the clock. Code: `self.active_at = Instant::now();` in `Session::mark_active` (and so `tell_foreground`, called from `replay` and `session_spawned`), and `detached_since: Some(Instant::now()), ... active_at: Instant::now()` in `Session::adopted`. Smallest fix: pass `now: Instant` to `mark_active`, `tell_foreground` and `adopted`, taken once per loop turn in the shell. This is the same pattern as `look_at_processes(now)`.

4. `remote-agent/src/server/core/holders.rs:393`, `:513-525`, `:539-545` — fcis R1 (MUST) — "A decision MUST be a pure function or a method of a GPUI-free model: what to ... send ... an ordering ... a policy". Code: the drain policy (`let drain = !holder.own_build;`) in the `adopt` handler, which chooses the holder with `.filter(is_adopted && welcome.build == self.build).min()` in `spawn_holder`. Whether to start a holder is decided by `let coming = ... any(own_build && welcome.is_none()); if !coming && self.holder_start.is_none()` in `place_waiting`, inside the loop handler. Smallest fix: a pure `fn place(holders: &[HolderView], build, starting: bool) -> Placement { Spawn(Token) | Start | Wait }` and `fn adopt_plan(welcome_build, core_build) -> Drain | Keep`, called by the handlers.

5. `remote-agent/src/server/core/sessions.rs:631-654` (`client_gone`) — fcis R1 (MUST) — a policy decided inside a handler. Code: `Policy::Kill if linger.is_zero() || starting => self.hang_up(id), Policy::Kill => { ... linger_until = Some(Instant::now() + linger); self.checkpoint(id) } Policy::Detach => ...`. It decides and acts in one body (fcis R9, SHOULD). Smallest fix: `fn on_client_gone(policy, starting, linger) -> Fate { HangUp | Linger(Duration) | Keep }`, with the handler dispatching on it.

6. `remote-agent/src/server/core/sessions.rs:541-561` (`session_exited`), `:605-624` (`end_grace`) — fcis R1 (MUST). Policy in the handler. Code: `let owner_may_return = session.awaiting_owner || session.linger_until.is_some(); if owner_may_return && session.attached.is_none() && !session.hung_up { session.exited = Some(code); return; }`, and the `Policy::Kill` / exited / else branch in `end_grace`. Smallest fix: pure functions that return "keep the exit for the owner / send the replay first / remove and tell the client" and "forget / hang up / leave detached", taking the session's flags.

7. `remote-agent/src/server/core/sessions.rs:890-900` (`client_attach` refusal) and `:569-584` (`reattach` selection) — fcis R1 (MUST). The refusal chain `None => Some(format!("no session {id}")) ... Some(session) if session.attached.is_some() => ...` and the "returning owner gets which sessions" filter are decisions written in the handler. Smallest fix: `fn attach_refusal(session: Option<&SessionView>, client) -> Option<Refusal>` (an enum, which also supports railway R4) and `fn returning(sessions, token) -> Vec<SessionId>`.

8. `remote-agent/src/server/core/manage.rs:34-63` (`client_list`) — fcis R1 (MUST). What `LIST` shows is built inline in the handler: `owned: detached && !session.meta.owner.is_empty()`, `detached_secs: ...filter(|_| detached).map_or(0, ...)`, `layout: ...filter(|_| detached)`. Smallest fix: `Session::info(&self, id, now) -> SessionInfo`, pure, with tests.

9. `remote-agent/src/server/core/process.rs:54-80` (`look_at_processes`) — fcis R1 / R9 (MUST / SHOULD). The activity-settle decision (`session.active = now.saturating_duration_since(session.active_at) < ACTIVITY_SETTLE`) and the "report only when changed" comparison are written inside the loop handler, interleaved with `pty::foreground` and `send_client`. The module doc states these rules but no function holds them. Smallest fix: `fn look(session_state, now) -> LookPlan` and `fn changed(last: Option<&Foreground>, seen: &Foreground) -> bool`, unit-tested.

10. `remote-agent/src/server/core/sessions.rs:246` (`command_line`), `:200` (`kept_layout`), `:281` (`allocate_id`), `:143`, `:150` (`is_running`, `reportable`); `holders.rs:64`, `:69`, `:513` (`is_adopted`, `status`, `spawn_holder`); `manage.rs`, `process.rs` — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file". `sessions.rs`'s only test is `is_due`. `holders.rs`, `manage.rs`, `process.rs`, `screen.rs` and `dir.rs` have no `#[cfg(test)]` module, and `command_line`, `kept_layout` (apart from its `log!`), `allocate_id` wrap and skip-0 behaviour, and the session predicates have no direct test (grep found none in `src`; `remote-agent/tests/*` drive real processes). Smallest fix: extract the decisions in items 4-9 as pure functions and test them beside the code. I counted this as three entries: sessions.rs, holders.rs and manage.rs/process.rs.

11. `remote-agent/src/server/core/holders.rs:636-641` — railway R1 (MUST) — "Not a panic, a sentinel value, or a log line with a default returned in its place". Code: `Err(error) => log!("can't encode a message: {error}")` in `queue`. An encode failure drops the message to the holder (a `SPAWN`, `SET_META`, `HANGUP`, a checkpoint chunk) with only a log line, and the caller proceeds as if it was sent. `store_meta` then records `storing = holder_queue_end(...)` for a meta that never went out. Smallest fix: `queue` returns `io::Result<()>`, and callers fail the session or the waiting spawn and send the client an `ERROR`.

12. `remote-agent/src/server/core/sessions.rs:393`, `:406`, `:557`, `:592`, `:613`, `:681`, `:906`; `holders.rs:594` — railway R9 (SHOULD) — "SHOULD be `expect("why this can't fail")`". Code: `.expect("the session")` ×7 and `.expect("a holder start")`. They guard real invariants, since the key was just checked or collected, so they aren't violations of the MUST. The messages name the value, not why it can't fail. Smallest fix: for example `expect("holder_session just found it")`, or `let Some(..) else { return }` where an early return is harmless. This counts as one entry, 8 sites.

13. `remote-agent/src/server/core/sessions.rs:86`, `:326` — types R7 (MUST) — "No sentinels: no `-1`, no `0` id". Code: `/// The program's pid; 0 until the holder reports it. pub(super) pid: u32` and `pid: 0` at spawn. `look_at_processes` reads `session.pid` and `replay` sends `pid`, and both rely on `spawning`/`reportable` to avoid the 0. Smallest fix: `Option<NonZeroU32>`, or put the pid inside the `spawning` state of a lifecycle enum (see item 17).

14. `remote-agent/src/server/core/sessions.rs:301`, `:580`, `:943`; `manage.rs:55` — types R7 (MUST) — "no empty string for 'none'". Code: `owner: self.client_token(client).unwrap_or_default().to_string()`, `!session.meta.owner.is_empty() && session.meta.owner == token`, `session.meta.owner.clear()`, `owned: detached && !session.meta.owner.is_empty()`. `SessionMeta.owner` is a frozen protocol/meta field, but in-memory code could still wrap it at the boundary (types R9). Smallest fix: in the core, keep `owner: Option<ClientToken>` and map to and from the empty string only in `SessionMeta::from_value` and `to_value`.

15. `remote-agent/src/server/core/sessions.rs:287` — types R7 (MUST) — "no `0` id". Code: `if id != 0 && !taken { return id; }` and `self.next_session.checked_add(1).unwrap_or(1)`. Session id 0 is reserved as "none", and the loop skips it. A protocol id (types R4 keeps those integers), so the cost is small. 16. `remote-agent/src/server/core/sessions.rs:1100` — types R7 (MUST) — "Absence that means something MUST be a variant". Code: `self.resize_session(id, cols, rows, 0, 0);`. The cell size 0×0 means "unknown" and is passed on to the holder's `Resize`. Smallest fix: make `cell_w`/`cell_h` an `Option<(u16, u16)>` inside the core and map to 0 only when building the wire `h1::Resize`.

17. `remote-agent/src/server/core/sessions.rs:82-132` — types R1 (MUST) — "States that exclude each other MUST be one enum ... not an `Option` whose meaning depends on another field". `Session` encodes a lifecycle in `spawning: Option<Spawn>`, `exited: Option<Option<i32>>`, `hung_up: bool`, `rebuilding: Option<bool>`, `awaiting_owner: bool`, `linger_until: Option<Instant>`, `storing`, `pending_replay`, `paused`. Their meanings depend on each other: `owner_may_return = awaiting_owner || linger_until.is_some()` (546), `is_running = spawning.is_none() && exited.is_none()` (144), `reportable` (151), and `checkpoint` bails on four flags (492-497). `exited: Option<Option<i32>>` and `rebuilding: Option<bool>` have nested meanings. Smallest fix: a `Lifecycle` enum (`Starting(Spawn) | Running | Rebuilding{truncated} | ExitedAwaitingOwner(code) | HangingUp`) with ownership (`Attached | Lingering(until) | AwaitingOwner | Detached`) as a second enum, so the combinations that can't occur can't be built.

18. `remote-agent/src/server/core/holders.rs:197-198` — types R6 (MUST) — "Raw input MUST be parsed once into a typed value at the boundary ... never re-checks the raw one". Code: `let name = place.lock.file_name()...to_string_lossy(); let own_build = name.starts_with(&format!("holder-{}-", self.build));`. The core re-parses the holder's lock file name for its build, while `endpoint::holders()` is the boundary that produced `Place`. Smallest fix: have `endpoint::Holder` carry `build: String` (parsed once in `remote-protocol`) and compare it.

19. `remote-agent/src/server/core/holders.rs:38`, `:198`, `:386`, `:520` — types R10 (MUST) — "A cached or stored derived value MUST name what refreshes it, in the code beside it". `Holder::own_build` is derived from the file name at connect (198), overwritten from `welcome.build == self.build` at adopt (386), and the comment (`/// Its files name the core's own build.`) names no refresh. `spawn_holder` ignores the stored flag and recomputes `welcome.build == self.build` (520), so two derivations of one fact coexist. Smallest fix: drop the field and compute from `Welcomed.build` (with `None` meaning "unknown until welcome", where `place_waiting` needs the file-name guess), or document the two refresh points beside the field.

## Design smells

- `holders.rs:132` — `connect` calls `std::thread::sleep(20 ms)` in a loop for up to `CONNECT_RETRY_LIMIT` (1 s) per holder, on the core's single event-loop thread (in `discover(initial=true)`), so a stuck holder stalls every client during startup. No rule's words forbid it; process R8 is about one thread per role.
- `holders.rs:115-116` — `liveness` ignores the results of `endpoint::remove` and `fs::remove_file` with `let _ =`, and the caller then logs "removed what a holder that is gone left behind" even if removal failed.
- `holders.rs:249` — a holder's undecodable message is only logged and the loop continues; the units affected (its sessions) show nothing.
- `holders.rs:270` — `closing_holder_frames` discards the frame error with `Err(_)` and `discard_input()`. This is harmless during shutdown but drops the cause.
- `sessions.rs:218-221` — the doc comment `/// The command line `list` shows; empty for the login shell.` sits above `session_key` (it belongs to `command_line`), so the two comments run together.
- `sessions.rs:222-238` — `session_key` reads `/dev/urandom` directly in the core. On Windows that always fails and the key falls back to time + pid + counter. It is a platform concern (randomness) with no seam item. No rule's words cover it, since there is no cfg or platform type, but it is a seam candidate (ports R4 spirit).
- `sessions.rs:1079-1087` — `replay` queues the whole rendered screen as chunks without consulting the client's queue marks (process R9). It is bounded by scrollback size, and `client_is_over` is checked only after.
- `screen.rs:108-122` — `inject_fault` reads the environment inside the emulator wrapper that `Screen::restore` calls. It is a documented test hook (process R20), and cached in a `OnceLock`, but it is an ambient read inside model-like code (fcis R3 in spirit).
- `holders.rs:16-24`, `process.rs:28` — the core imports `server::platform::{conn::Stream, listen, lock::Lock, pty}` directly, while other items go through facade modules (`daemon`, `dir`, `event_loop`). It is allowed (same item names on both platforms), but the paths are inconsistent.
- `event_loop.rs:22` — `pub type Token = usize` is a bare alias used as the identity of sources and, in the core, of sessions' holder and client. Tokens are never reused (`next_token += 1`), so there's no stale-identity bug, but a newtype would stop mixing with other `usize`s (types R4, SHOULD, out of this batch's checked rule set).
- `manage.rs:59` — `detached_secs` uses `map_or(0, ...)` for "no data", and wire field semantics make 0 mean "not detached or unknown".
