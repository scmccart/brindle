## Violations

1. `remote-agent/src/server/core.rs:185-201` — ports R4 (MUST) — "code outside [the seam] MUST NOT carry a `cfg` for that concern; put a new platform difference in the narrowest module that owns the concern, or add an item to both sets of a per-platform module set". `#[cfg(windows)] fn prune_copies(build: &str)` and `#[cfg(not(windows))] fn prune_copies(_build: &str) {}` sit in the core, not in `server/platform/{unix,windows}`. The Windows body also reads `std::env::var_os("BRINDLE_SERVER_DIR")` and `LOCALAPPDATA` itself (a second env resolution beside `dir::from_env`) and names `server_dir`/`win`. core.rs is not named in the ports R4 exception (the exception names src/ app files). Smallest fix: add `sys::prune_helper_copies(build)` to both platform module sets (a no-op on unix) and call it from `run`; keep the path decision in a pure helper.

2. `remote-agent/src/server/cli.rs:28,43` — ports R4 (MUST) — same rule. `#[cfg(unix)] pub const USAGE` and `#[cfg(windows)] pub const USAGE` (differing in `--ready-fd` vs `--ready-handle`, `launch`, directory text) are a platform difference outside any seam. cli.rs is not named in the exception. Low severity: usage text only. Smallest fix: one `USAGE` built from small per-platform constants exported by `platform::daemon`/`platform::dir`, or accept as a documented exception.

3. `remote-agent/src/pty/unix.rs:25-29,46-57,118-135,137-148,215-226` — ports R7 (MUST) — "A decision [a seam] needs (what to run, the environment, the quoting, a name) comes from a pure helper that is tested on every platform". The seam itself decides which program runs (`default_shell`: `env["SHELL"]`, then `std::env::var_os("SHELL")`, then passwd, then `"/bin/sh"`), the login-shell `arg0` (`"-" + name`), the default `TERM` (`command.env("TERM", "xterm-256color")`), the cwd fallback to `$HOME` (`command_for`) and `home_dir`'s three-step fallback. Only `expand_remote_cwd` and the stat parser have tests. Smallest fix: move these into a pure, ungated helper that takes `SHELL`, `HOME` and the passwd entry as arguments (as `cmdline::launch_line` does) and unit-test it; the seam reads the env and passwd and calls it.

4. `remote-agent/src/pty/unix.rs:202-213,356-371` (module gated at `remote-agent/src/pty.rs:9-12`) — fcis R7 (MUST) — "A pure helper MUST compile and be tested on every platform ... Don't `cfg`-gate logic". `parse_stat_field` (pure string parsing of a `/proc/<pid>/stat` line, with its test `stat_fields_count_from_after_the_command`) and `expand_remote_cwd` (path expansion, with its test) live in a module behind `#[cfg(target_os = "linux")]`, so they compile and run on Linux only. (`expand_remote_cwd` also reaches the environment and passwd through `home_dir`, which `fcis R3` would not allow for pure code.) Smallest fix: lift them into an ungated module of `pty.rs`, with `home` passed in.

5. `remote-agent/src/server/core.rs:451-492` (`tick`) and `:486-492` (`should_exit`) — fcis R1 (MUST) — "A decision MUST be a pure function or a method of a GPUI-free model: what to show, send, open, keep or drop; an ordering, a grouping or a policy". The core's lifecycle policy is written inside the loop handler on `Core<L>`: when the listener starts accepting (`!self.accepting && self.startup_adopted(now)`), when the reconnect grace starts and ends, the idle test (`sessions.is_empty() && clients.is_empty() && pending.is_empty() && waiting.is_empty() && holder_start.is_none()` then `idle_since`), and the exit rule `stepping_down.is_some() || (stopping.is_some() && sessions.is_empty())` or idle >= `UNUSED_LIMIT`. They can only be tested by building a `Core`, which binds a listener (the real-process tests do). Smallest fix: a small pure `Lifecycle` value (counts, flags, `now`, timers in) returning "accept now / start grace / end grace / exit", with unit tests; `tick` applies it.

6. `remote-agent/src/server/core/clients.rs:177-178` (inside `welcome`) — fcis R1 (MUST) — same rule. The HELLO policy is inline in the handler: `Duration::from_secs(hello.linger_secs.into()).min(MAX_LINGER)` and `protocol >= 2 && hello.process_info`, plus the sorted, deduped holder-protocol list at 160-166. Untested in the file. Smallest fix: a pure `fn client_options(protocol, &Hello) -> (Duration, bool)` with tests.

7. `remote-agent/src/server/core/clients.rs:326-329,342-345` — fcis R1 (MUST) — same rule. The backpressure hysteresis (`!entry.over && queued() > CLIENT_QUEUE_HIGH` pauses; `entry.over && queued() < CLIENT_QUEUE_LOW` resumes) is decided inside `send_client` and `flush_client`. process R9 is satisfied; the placement is the issue, and the marks logic is only reached through real-process tests. Smallest fix: `fn mark_change(over: bool, queued: usize) -> Option<bool>` with unit tests.

8. `remote-agent/src/server/check.rs:29-52` (`refusal`) — fcis R9 (SHOULD) — "A function that decides *and* acts SHOULD be split: return what to do as data". `refusal` computes the missing H1 versions and the message, reads the build id from the running binary, and writes `core.log` (`log_refusal`), all in one function. Only the "nothing missing" branch is tested. Smallest fix: a pure `fn refusal_reason(wanted, supported, version, build) -> Option<String>` (tested), with the caller logging.

9. `remote-agent/src/server/cli.rs:71-85,200-248` — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`". Pure and untested in cli.rs: `status_text`, `status_json`, `json_flag`, `no_args`, `unexpected`. Only `list_line` and `uptime` have tests. Smallest fix: add tests for each (`status_json` drops `req` and adds `running`; `status_text` shows `, draining`; `json_flag` rejects extra arguments).

10. `remote-agent/src/server/core.rs:501-576` (`close_peers`, `forget_peer`) — types R1 (MUST) — "States that exclude each other MUST be one enum ... Not two `bool`s". A peer is a holder or a client, carried as `(Token, bool)` and `holder: bool` (`forget_peer(token, holder: bool)`, `open: Vec<(Token, bool)>`), although `Source::{Holder, Client}` already exists in the same file. Smallest fix: `enum Peer { Holder(Token), Client(Token) }` (or reuse `Source`) and match on it.

11. `remote-agent/src/server/core/clients.rs:41,196,218-220` — types R7 (MUST) — "No sentinels: no `-1`, no `0` id, no empty string for 'none'". `Client.token: String` uses `""` for "no token": `take_over` begins `if client_token.is_empty() { return; }` ("An empty token owns nothing"). Smallest fix: parse `hello.client_token` once into `Option<ClientToken>` in `welcome`, and store that.

12. `remote-agent/src/server/cli.rs:121-133` (`list_line`) — types R7 (MUST) — same rule. The CLI interprets wire sentinels directly: `match session.started { 0 => "-" ...}`, `session.command.is_empty()` means "login shell", `session.title.is_empty()` means "none". The types are `SessionInfo`'s (remote-protocol, outside this batch), but the consumer branches on the sentinel instead of a typed value (types R9 says the boundary maps them). Smallest fix: map `SessionInfo` into a small `ListRow { age: Option<u64>, command: Option<&str>, title: Option<&str> }` with `Option`s, then format.

13. `remote-agent/src/server/core.rs:124-126,131,139,143` and `remote-agent/src/server/cli.rs:96,202,207,259,281,308` — railway R8 (MUST) — "Error text MUST name the action that failed and then its cause". Bare `error.to_string()` is returned as the whole message, e.g. `dir::from_env().map_err(|error| error.to_string())`, `Paths::new(&dir).map_err(|e| e.to_string())`, `Loop::new().map_err(|e| e.to_string())`, `stream.set_read_timeout(..).map_err(|e| e.to_string())`. The user reads "Too many open files" or "No such file" with no action. (core.rs:137-141 and cli.rs:265,277,303,310 do it correctly.) Smallest fix: `format!("can't create the event loop: {error}")` and so on.

14. `remote-agent/src/server/core/clients.rs:126-132,154-156` — process R10 (MUST) — "Closes MUST be graceful: send the whole queue, shut down the write side, read to the peer's end within a bound". A refused connection (first message not HELLO; version refusal) gets `queue(...)`, `conn.flush_for(REFUSAL_FLUSH_LIMIT)`, then `drop_source(token)`, and the `Conn` is dropped. That is a flush and a drop, not `Conn::close_for`. `Conn::close_step`'s own doc says closing with unread input resets the connection on Linux, and the peer loses the `ERROR` it was meant to read; a client that pipelined bytes after its first frame (still in the kernel buffer) hits exactly that. Smallest fix: `conn.close_for(REFUSAL_FLUSH_LIMIT)` in both places.

15. `remote-agent/src/server/conn.rs:444` — testing R7 (MUST) — "Unit and real-process tests MUST pass in parallel: no fixed sleeps ... To wait, poll for the condition". `std::thread::sleep(Duration::from_millis(50))` in `a_drop_after_a_timed_flush_loses_nothing` ("The sender is waiting by now"). Smallest fix: drop the sleep. The reader already polls with `wait`, and the sender's `flush_for` is correct whether or not the reader starts late.

## Design smells
- `remote-agent/src/server/build_id.rs:1-3` says the id "is computed once at startup", but `current()` re-reads and re-hashes the whole binary on every call (`check::refusal` and `core::run` each call it).
- `remote-agent/src/server/check.rs:38` `build_id::current().unwrap_or_else(|_| "unknown".into())` puts a sentinel string into a diagnostic. It is display only, so not `types R7`, and the failure is dropped from the message.
- `remote-agent/src/server/cli.rs:99-101` falls back to `now = 0` when the clock is before the epoch (`map_or(0, ..)`), which makes every age read `0s`.
- `remote-agent/src/server/core.rs:227` `claim` polls with `std::thread::sleep(20ms)` for up to 2 s at startup, before the readiness loop exists. Allowed in effect, but it is the one blocking wait outside the loop (`process R8` reads "one thread per role on a readiness loop").
- `remote-agent/src/server/core/clients.rs:130,155` and `core.rs:592-606` block the core's only loop thread for up to `REFUSAL_FLUSH_LIMIT` (1 s) per refused connection, and up to 10 s on a step-down. Bounded, but every other session's I/O stalls meanwhile. Up to 64 pending connections could each cost this.
- `remote-agent/src/server/core/clients.rs:404` `queue` logs an encode failure and drops the message. A reply a client waits for would then never come, and the failure never becomes the session's or client's state (`railway R6` reads "not a log line alone"; arguably it covers this). It only happens for an oversize frame, which the core's own chunking should prevent.
- `remote-agent/src/server/core/clients.rs:246-249` (`take_over`): the stale client's connection is dropped after one best-effort `flush()`, not a graceful close. Intended (the link is dead), and it is documented.
- `remote-agent/src/server/core/clients.rs:76-78`: `log!` for every refused connection past `MAX_PENDING` can flood `core.log` under a connection flood.
- `remote-agent/src/pty/unix.rs:399-405` `signal_process_group` returns `()` and discards `kill`'s result (also `set_utf8`, whose comment says that is deliberate). Failure is mostly `ESRCH`, which is an expected "already gone".
- `remote-agent/src/pty.rs:34-37,45-48`: `cfg_attr(windows, allow(dead_code ...))` is a platform attribute in the seam's root file, which sits at `remote-agent/src/pty.rs`, beside the named seam directory `pty/`. I treated it as part of the seam.
- `remote-agent/src/pty/unix.rs` is gated on `target_os = "linux"` while the module sets elsewhere use `unix`. It will matter for the macOS port.
- `remote-agent/src/server/conn.rs:326-336,355-358` and `core.rs:874-877`: tests assert how much a socket holds (`assert_eq!(sender.queued(), 0, "a socket holds this much")`, `queued() > 0` after 8 MiB). That depends on the kernel's buffer sizes, not on the rule (`testing R8` speaks of timing and machine speed, so not reported).
- `remote-agent/src/server/conn.rs` tests poll with a fixed 10 s deadline that does not scale with `BRINDLE_E2E_SLOW`. `testing R7` asks for "a scaled limit", but unit tests have no scale variable, so not reported.
- `remote-agent/src/server/core.rs` generic `Core<L: EventLoop>` is used only with `Loop` here (tests use `Core<Loop>`). `ports R6` warns against traits added for mockability, and I could not see another implementor in these files.
