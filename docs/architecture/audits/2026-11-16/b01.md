## Violations

### fcis (functional core / imperative shell)

1. `src/find_bar.rs:307-320` (also `:266-281`) — fcis R1 (MUST), R10 — "A decision MUST be a pure function or a method of a GPUI-free model: what to show…". `render_find_bar` picks the status text and colour inline: `if bar.invalid { ("Invalid regex", destructive) } else { match (&bar.regex, bar.count) { (None,_) => "", (Some(_),None) => "…", (Some(_),Some(c)) if c.total == 0 => "No results", … format!("{index}/{}{}", …) } }`. `describe_find` repeats the same regex/count/invalid classification for the dump (`"none"`, `"pending"`, `"{total}+"`). Fix: a `FindStatus` enum, or a pure `fn status(invalid, has_regex, count) -> Status`, with unit tests. Render and dump would both read it.
2. `src/find_bar.rs:144-162, 174-192, 122-142, 195-202` — fcis R1 (MUST), R10 — "…what to keep or drop; an ordering…". The search state machine lives in the `TerminalView` impl and in `FindBar`, which holds `Entity<TextInput>`, `Task` and `Subscription`. Examples:
   - `step_match` picks the next match: `match &bar.focused { Some(current) => search::step(..), None => search::find_from(.., view_bottom, None) }`, then moves `origin`.
   - `recount` drops the current match: `if bar.focused.is_some() && count.index.is_none() && !count.capped { bar.focused = None; }`.
   - `research` and `recount` decide when `full_search_pending` is set and cleared.
   - `find_terminal_changed` decides whether to recount.

   None of this can be tested without a window. Fix: a GPUI-free `FindState` model that takes the term, the options and the query and returns the new focused match, count and pending flag.
3. `src/find_bar.rs:237-246` — fcis R1 (MUST) — in `close_find_bar`, the restore-offset decision is inline: `let target = bar.saved_offset.min(history) as i32; let delta = target - grid.display_offset() as i32; if delta != 0 { term.scroll_display(..) }`. Fix: a pure `fn restore_delta(saved, history, current) -> i32`.
4. `src/find_bar.rs` (whole file) — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`". The file has no `mod tests`. The decisions in items 1-3 would be pure functions or models, and are untested here; `crate::terminal::search` has its own tests but covers only the search primitives. Fix: extract them (items 1-3) and test them in this file.
5. `src/layout.rs:69-77` — fcis R2 and R3 (MUST), ports R11 (SHOULD) — "Pure code MUST NOT call `SystemTime::now()`… Random values (tokens, session keys) are made in the shell and passed in" and "MUST NOT read… mutable statics". The README table lists `layout.rs` as pure. It contains `origin_id()`, which reads `SystemTime::now()` and `std::process::id()` and caches the result in `static ID: OnceLock<String>`. Quote: `std::time::SystemTime::now().duration_since(UNIX_EPOCH)…; format!("{:x}-{nanos:x}", std::process::id())`. The process-wide state is also not created in `main.rs` (ports R11). `record` already takes `origin: &str`, so the shell can make it. Fix: create the id in `main.rs` (or the workspace) once and pass it down to `zone_view.rs:692`; delete `origin_id` from `layout.rs`.
6. `src/layout.rs:84-91` (caller `src/zone_view.rs:688-691`) — fcis R5 (MUST), R9 (SHOULD) — "no callback that reaches the world". `record(.., key_of: &mut impl FnMut(ZoneId) -> Option<String>, ..)` takes a callback. In production it is `|id| self.zone_server_session(id, cx).map(|s| s.key).filter(|k| !k.is_empty())`, which reads entities through `cx`. Nothing here needs output to interleave with a stream. Fix: the caller gathers a `HashMap<ZoneId, String>` first and passes `&HashMap`.
7. `src/desktop.rs:399-406` (inside `#[cfg(windows)] mod start_menu`) — fcis R7 (MUST) and R8 (MUST) — "A pure helper MUST compile and be tested on every platform… Don't `cfg`-gate logic" and "ships with unit tests". In `resolved`, the `\\?\` and `\\?\UNC\` prefix stripping (`strip_prefix(r"\\?\")`, `starts_with(r"UNC\")`, `format!(r"\\{}", &unc[4..])`) is pure string logic, gated behind `cfg(windows)` and untested. Fix: move `fn strip_verbatim(&str) -> String` out of the gated module and unit-test it on every platform.
8. `src/main.rs:862-887` — fcis R1 (MUST), R10 (SHOULD) — "what to… open, keep or drop". The launch policy is written inline in the `Application::run` closure and is untested:
   - `restoring = !args.no_restore && store.is_owner()`.
   - `listed = if restoring || args.attach.is_some() { running_sessions() } else { Some(Vec::new()) }`.
   - `detached = … .filter(|s| restoring && !s.attached && Some(s.session) != args.attach)`.
   - `request = match args.attach { Some(..) => Launch::Attach{..}, None if args.asks_for_a_tab() => Launch::Request{..}, None => None }`.
   - `(first, request) = match restored { Some(state) => (Restore, request), None => (request.unwrap_or_else(..), None) }`.

   Fix: a pure `fn launch_plan(args, owner, listing, restored) -> (Launch, Option<Launch>, Vec<SessionInfo>)`. `forwarded_launch` is the existing model for this.
9. `src/main.rs:735-761` — fcis R10 (SHOULD) — "A new conditional in … `main.rs` … chooses between outcomes from state, it moves into the model". The role decision (take the lock and be the instance, forward to a running one, retake after the instance went away, or run unowned) is a nested `match` on `err.kind() == WouldBlock && !args.is_debug_run()` and `instance::forward`'s result. Fix: a pure `fn role(lock_result_kind, is_debug) -> Role`, with the shell executing it.
10. `src/main.rs:567-573` and `:792-797` — fcis R1 and R10 — the same decision ("the profile `-p` names, else the default") is written twice, once in `forwarded_launch` (tested) and once in the run closure (untested). Fix: one pure function used by both (see railway item 14 for the swallowed failure).
11. `src/main.rs:248-358` — fcis R9 (SHOULD) — "A function that decides *and* acts SHOULD be split". `parse_args_from` decides and acts in the same function:
    - it calls `std::process::exit` directly (`--help`, `--version`, `--list-actions`, `--list-themes`, `--shell-integration`, `usage_error`);
    - it prints (`print!`, `println!`);
    - it sets the environment (`std::env::set_var("BRINDLE_CONFIG", path)`, line 305).

    The exit paths can't be unit-tested (the tests exercise only `Ok` parses). Fix: return `Result<Parsed, UsageError>` with `Parsed::{Run(Args), Print(String)}` and let `main` print, exit and set the env.
12. `src/main.rs:375-377` — fcis R8 (MUST) — `unescape` (pure; handles `\r`, `\n`, `\e`, `\t`) has no test in `mod tests`, although `--send`/`--wait-for` depend on it. Fix: add a test.

### types (illegal states unrepresentable)

13. `src/find_bar.rs:38-41` — types R1 (MUST) — "States that exclude each other MUST be one enum… Not … an `Option` whose meaning depends on another field". `regex: Option<RegexSearch>` and `invalid: bool` encode one of three query states (empty, valid, invalid regex), and `invalid` implies `regex.is_none()`. The code matches on `(&bar.regex, bar.count)` plus `bar.invalid` in several places. `full_search_pending` is likewise meaningful only with a `regex`. Fix: `enum Query { Empty, Invalid, Compiled { regex, … } }`.
14. `src/latency.rs:29-38` — types R1 (MUST) — in `Probe`, `output: Option<(Instant, u64)>` and `paint: Option<Instant>` are stages of one life cycle. `paint` is only ever `Some` when `output` is `Some`, and `frame()` relies on that with `.expect("painted probes have output")`. Fix: `enum Stage { Waiting, Output{..}, Painted{..} }`.
15. `src/main.rs:523, 554` and `:863-875` — types R1 (MUST) — `Forwarded.listing: Option<Option<Vec<SessionInfo>>>` stands for three states (not asked, listing failed, listed), and `forwarded_launch` collapses them with `listing.flatten()`. `listed: Option<Vec<_>>` in `main`'s run closure does the same, and `Some(Vec::new())` is used for "not asked" (line 863), so `listed.is_some()` at line 873 means two different things. `picker::Listing` is the existing precedent. Fix: `enum Sessions { NotAsked, Failed(why), Listed(Vec) }`.
16. `src/layout.rs:26-39, 265-266` — types R3 (MUST) — "An identity MUST be the value that stays stable, never a position". The tab's identity for grouping is `(layout.origin, layout.index)`, where `index` is the tab's place in the strip when recorded (`record(.., index: usize, ..)`). Tabs that move between `SET_LAYOUT` ticks, or a kill that lands between one tab's sessions being re-sent, can give two tabs the same pair. `layout_of` and `prune` limit the damage, since a blob must name its own session and leftovers become own tabs. Fix: a tab id (random, kept in the tab) in the blob, with `index` kept for ordering only.
17. `src/main.rs:161-166` — types R3 (MUST) — "never … a number that is reused". `WaitLog::begin` mints `id = entries.last().map_or(0, |(id, ..)| id + 1)`. After the last entry is cleared, the next wait reuses its id, so a late `set`/`clear` for the old handle would act on the new wait. Fix: a monotonically increasing counter field.
18. `src/layout.rs:241` — types R7 (MUST) — "No sentinels: … no empty string for 'none'". `!info.key.is_empty()` treats `""` as "a core that predates keys" (the test says so). `SessionInfo.key: String` comes from the protocol's additive default. Code past the boundary re-checks the sentinel here and at `zone_view.rs:690` (`.filter(|key| !key.is_empty())`). Fix: parse once at the `SessionInfo` boundary into `Option<SessionKey>`.

### railway (failures as values)

19. `src/main.rs:300-358` — railway R1 (MUST) — "An expected failure MUST be in the return type… Not … a sentinel value". Bad option values are silently dropped instead of reported:
    - `"--dump-screen-after" => args.dump_after = it.next().and_then(|s| s.parse().ok())` — a typo turns the dump off with no message, and the run then never exits.
    - `-p`, `-d`, `--config`, `--send`, `--action`, `--find`, `--wait-for`, `--key` with a missing value use `it.next()` / `extend(it.next()…)`, so the option vanishes.
    - `-e` with nothing after it is ignored.

    Meanwhile `--step-interval`, `--latency-*` and `--attach` do call `usage_error`, so the parser is inconsistent. Fix: return `Err(UsageError)` for each.
20. `src/main.rs:567-573` and `:792-797` — railway R1 (MUST) and R6 (MUST) — "Not … a log line with a default returned in its place" and "A failure of a … tab … MUST become that unit's visible state… not a log line alone". An unknown `-p NAME` is `log::warn!("no profile named {name:?}")` and then the default profile opens. Neither the user nor the tab is told, and in the forwarded case the second Brindle exits 0 ("ok"). Fix: return an error (forwarded: the `reply` `Err`; first launch: a message tab or the config warning).
21. `src/main.rs:582-590, 558-561` — railway R1 and R8 (MUST) — `running_sessions` returns `Option` and logs the cause: `Err(why) => { log::warn!("not attaching detached sessions: {why:#}"); None }`. The cause is dropped, and `forwarded_launch` replaces it with a fixed string, `Err("Brindle could not list the terminal server's sessions".into())`, so the user sees no cause ("drops the cause the system already had"). Fix: return `Result<Vec<_>, ListError>` and carry it into the `Launch::Attach` target.
22. `src/main.rs:875` — railway R8 (MUST) — "A message that reads as a different failure is a defect". For `--attach` at first launch, `attach_target(session, listed.as_deref().unwrap_or_default())` passes an empty listing when listing failed, so the user gets a "no such session" style error for what was a listing failure. `forwarded_launch` (line 560) handles the same case correctly. Fix: map `listed == None` to the "could not list" error here as well.
23. `src/main.rs:643-649` — railway R1 (MUST) and R10 (SHOULD) — "a bad config falls back to defaults and shows why" (`process R15`). An unusable state file is `Err(why) => { log::warn!("{why}"); return None }`, which drops the saved tabs with no visible state. Fix: surface the reason (config warning or message in the first tab).
24. `src/main.rs:925-945` — railway R1 (MUST) — the debug steps `--key`, `--action` and `--hover/--click` report failure only through `log::error!` (`bad keystroke`, `unknown action`, `--hover/--click: {why}`). The run continues and the dump says nothing, whereas `--wait-for` timeouts are put in the dump. Fix: validate the names at parse time (usage error), or record them in the dump.
25. `src/main.rs:669-674` — railway R1 (MUST, low severity) — a failed session-state write is only `log::warn!`ed and not shown. Fix: set a visible flag, or retry on the next tick with a notice.
26. `src/latency.rs:295-300` — railway R1 (MUST, low severity; debug option) — a failed write to `--latency-log` is `log::error!`ed and the log silently disabled (`self.log = None`). Fix: surface it in the summary line.

### process

27. `src/main.rs:863` (`running_sessions` at `:582-585`) — process R13 (MUST) — "The UI thread MUST NOT block." The `Application::run` closure calls `remote::local::running_sessions(Duration::from_secs(2))` synchronously, so the UI thread can wait up to 2 s on the terminal server before the window opens. CLAUDE.md describes it as a deliberate pre-window listing, but the rule has no exception for it. Fix: list on the background executor and open the window when it answers (as the sessions palette's `OPEN_GRACE` does).
28. `src/main.rs:495-515` and `:418-421` — process R13 (MUST, low severity) — `watch_config` runs on the foreground executor (`cx.spawn`) and does `std::fs::metadata(Config::path())` every second (`config_mtime`). `reload_config_renaming` reads and parses the file in `Config::load_or_default()` on the UI thread. Fix: stat and read on `background_executor().spawn`, then apply on the UI thread.
29. `src/find_bar.rs:255-261` (called from `src/terminal_element.rs:176`, `prepaint`) — process R14 (MUST) — "`render` and `prepaint` MUST stay free of IO, heavy allocation and lock contention". `find_highlights` takes the terminal's term lock (`self.terminal.read(cx).term().lock()`) and runs `search::visible_matches(&term, regex)`, a regex scan of the viewport that allocates `Vec<Match>`, every frame while the bar has a regex. It is bounded by the viewport (documented), but it runs under the fair lock the reader thread also takes. Fix: compute matches in `research`/`recount`/on output (event time), cache them, and let prepaint read the cache.

## Design smells

- `src/layout.rs` (declared pure in fcis' table) imports `crate::zone_view::{SplitAxis, ZoneId, ZoneTree}` from the GPUI view module, so the model's tests compile only with gpui in the graph. `SplitAxis` also carries serde for the layout blob, mixing the persisted form with the in-memory type (types R9 flavour). Move those types to a GPUI-free module.
- `src/layout.rs:274-310` — `group` sorts on an anonymous tuple `(u64, u32, String, u32)` and an `anchors` map. A small `SortKey` struct would be clearer. `u32::try_from(index).unwrap_or(u32::MAX)` and `serde_json::to_value(layout).ok()` in `record` hide a failure that cannot happen.
- `src/desktop.rs:225-229` — `run_tool` turns an `update-desktop-database` or `gtk-update-icon-cache` failure into `log::warn!` only. Documented ("failures are only warnings"), but the user running `--install-desktop` never sees it.
- `src/desktop.rs:300-328` — the tests run `install`/`uninstall`, which call `refresh_caches` and therefore execute `update-desktop-database` from the host's `PATH` against a temp directory. They are not hermetic (testing R7 spirit). The temp names include the pid and the test name, so they do not collide. `prefix_is_rejected_on_windows` asserts on error text (`err.contains("winget install")`).
- `src/find_bar.rs:164-182, 144-162` — a full-scrollback `search::count(.., COUNT_CAP)` runs on the UI thread while holding the term lock (in `step_match` and `recount`). It is capped, but it contends with the reader thread. The `count` field (a derived value) names its refreshers only indirectly (`recount`, `step_match`, `research`), with no comment beside the field (types R10 flavour).
- `src/main.rs:195, 155` — `WaitLog` is `Arc<Mutex<Vec<(u64, String, WaitState)>>>` with an anonymous tuple. A struct entry would read better.
- `src/main.rs:213, 523` and `reattach::attach_target(session: u32, …)` — `--attach ID` and `Forwarded` name a session by its bare id (and `:867` compares `Some(s.session) != args.attach`). It resolves within one fresh listing, so it is not stale, but it is the "id alone" shape that `types R3` warns about. The CLI can't supply a key.
- `src/main.rs:447, 611` — `futures::channel::mpsc::unbounded` for host reports and launch listings, and `:762` for forwarded requests. The consumers drain eagerly and the payloads are small state reports, so this is probably fine, but they have no high/low marks (process R9 wording is about producer/slower-consumer queues).
- `src/main.rs:1058, 1014` — debug loops poll on 1 ms and 100 ms timers on the foreground executor (Windows pacing note in process R13 concerns tasks that wake without pause; 1 ms is paced but dense).
- `src/main.rs:1025-1032` — the `--latency-bench` jitter (xorshift) is an inline closure with its own seed from `SystemTime::now()`. Pure enough to extract and test.
- `src/latency.rs:232-239` — `samples` and `all_samples` grow without bound for the life of a `--latency-log` run (debug only).
- `src/main.rs:230-241` — `Args::instance_request` reads `std::env::current_dir()` and `Request::launch_token()` (env) inside a method on pure data. Its test compares against `current_dir()`, which is fine, but the ambient reads could be arguments (fcis R3 applies only to pure code).
