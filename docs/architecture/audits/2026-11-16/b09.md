## Violations

1. `remote-agent/src/main.rs:2,4,6,12,14,45,52,57,62,68,74,79,84,89` — ports R4 (MUST) — "A platform concern MUST have one seam, and code outside it MUST NOT carry a `cfg` for that concern." — 14 `cfg(target_os = "linux")`, `cfg(any(target_os = "linux", windows))`, `cfg(windows)` and `cfg(not(...))` attributes choose which roles/modules exist per OS (`#[cfg(target_os = "linux")] mod liveness;`, `#[cfg(windows)] Some("launch") => server::daemon::launch(&rest)`, three `#[cfg(not(any(...)))]` stub functions). `remote-agent/src/main.rs` is not a seam module and is NOT named in the README exception (the exception names the app's `src/main.rs`, `src/workspace.rs`, `src/terminal/mod.rs`, `src/remote/local.rs` "and a few others"), so untagged. Smallest fix: let `server/mod.rs` (or `server/platform`) export `run_serve`, `run_hold`, `run_relay`, `run_manage`, `USAGE` for every platform (with the unsupported-platform stubs inside the module) so `main.rs` has no cfg; keep only the Windows `launch` arm behind the platform set (e.g. a `launch` item that is the "unknown command" path on Linux).

2. `remote-agent/build.rs:13,19` — ports R4 (MUST) — same words — `#[cfg(windows)] resources();` and `#[cfg(windows)] fn resources()` gate Windows resource embedding by the *host* OS. build.rs is not a listed seam and not named in the exception, so untagged. Arguably unavoidable (`embed-resource` is a Windows-only build-dependency, Cargo.toml:40), so the smallest fix may be to add `remote-agent/build.rs` to the seam list in `docs/architecture/ports-and-adapters.md` rather than change the code.

3. `remote-agent/src/conpty/api.rs:67-109,115-133` (`packaged`, `shipped_dir`) — ports R7 (MUST) and fcis R9 (SHOULD) — ports R7: "A decision it needs (what to run, the environment, the quoting, a name) comes from a pure helper that is tested on every platform"; fcis R9: "A function that decides *and* acts SHOULD be split" — `shipped_dir` decides which directory to load from (exe dir if both files match, else extract dir, rewriting if they differ) and does the reads/writes in the same function; `packaged()` builds the extract path itself (`PathBuf::from(dir).join("brindle").join("conpty").join(version)`) from `LOCALAPPDATA`. The whole module is `cfg(windows)`, so none of this is tested on Linux. Smallest fix: a pure `plan(exe_matches: bool, extract_matches: bool, extract_dir: Option<&Path>) -> Plan { UseExeDir | Extract(dir) | Unavailable }` (and a pure `extract_dir(local_app_data: Option<&OsStr>, version)`), ungated and unit-tested, with `shipped_dir` only gathering `matches` and applying the plan. (Counted once under each rule.)

4. `remote-agent/src/conpty/api.rs:67-109` (`packaged`) — railway R1 (MUST) — "An expected failure MUST be in the return type … Not a panic, a sentinel value, or a log line with a default returned in its place." — `Err(why) => { eprintln!("conpty: the packaged ConPTY {version} isn't usable ({why}): …"); None }` and the earlier `let Some(files) = bundle::FILES else { eprintln!(...); return None; }`: the failure reason is logged and `None` (then the inbox ConPTY) returned in its place; the caller (`api`) cannot tell why or tell the session. The fallback is designed (CLAUDE.md), but the rule's words cover it. Smallest fix: return an outcome (`Chosen { api, degraded: Option<Reason> }`) so the caller can log/report it, and `Pseudoconsole` can expose it (e.g. to the session's exit/diagnostics).

5. `remote-agent/src/conpty/api.rs:50-64` (`PACKAGED: OnceLock<Option<Api>>`) — railway R6 (MUST) — "It MUST NOT be cached: the next attempt retries." — a failed packaged load is stored as `None` for the holder's whole life (a holder runs for days) and shown only in the holder log (`eprintln!`), not on any session. (Per-build helper copies mean a new holder retries, which softens it.) Smallest fix: cache only `Some(api)`; on `None` retry on the next `api(false)`, and surface the degraded state per the fix in 4.

6. `remote-agent/src/conpty/console.rs:138-154` (`Pseudoconsole::reparent`) — railway R1 (MUST) — same words — returns `()`: `if let Err(err) = unsafe { reparent(self.handle, window) }.ok() { eprintln!("conpty: parenting a console to window {hwnd:#x}: {err}"); }`, and the no-export case only logs once and returns. Expected failures are logged and dropped. The request is advisory (CLAUDE.md), so smallest fix: return `io::Result<Reparented>` (`Done`/`Unsupported`) and let the holder log it where it handles the message.

7. `remote-agent/src/conpty/api.rs:165-167,191-196` (`missing`) — railway R8 (MUST) — "A message that … drops the cause the system already had" — `ok_or_else(missing)` yields `"conpty.dll lacks a pseudoconsole function"` without saying which export (`ConptyCreatePseudoConsole`, `…Resize…`, `…Close…`) is absent although the call site knows the name. Smallest fix: `missing(name)` → `format!("conpty.dll lacks {name}")`.

8. `remote-agent/src/conpty/api.rs:181-183` (`inbox_api`) — railway R9 (SHOULD) — "SHOULD be `expect("why this can't fail")`" — `.expect("CreatePseudoConsole")`, `.expect("ResizePseudoConsole")`, `.expect("ClosePseudoConsole")` give the name, not why it can't fail (line 179's `"kernel32 is loaded"` is fine). A panic here is in the holder, which holds every session, if Windows is older than 1809. Smallest fix: reasons such as `expect("kernel32 exports CreatePseudoConsole on Windows 10 1809 and later")`.

9. `remote-agent/src/conpty/console.rs:245-258` (`Drop for Pseudoconsole`, thread `conpty-close`) — process R8 (MUST, borderline) — "Each server role MUST run one thread on a level-triggered readiness loop" (anti-pattern: "Blocking … threads per session in the server") — each closed session spawns a thread that polls `WaitForSingleObject(process, 0)` + `thread::sleep(1 ms)` for up to `CONNECT_LIMIT` (1 s) and then makes a call that can block. It is documented and deliberate (`ClosePseudoConsole` can block), so this is flagged for the rule's words only. Smallest fix: if kept, add an exception row for it in `docs/architecture/README.md`; otherwise register the process handle on the loop (`Waker::wake_on_exit`) and run only the blocking `close` on one long-lived closer thread.

10. `remote-agent/src/conpty/api.rs:215-223` (test helper `scratch`) — testing R7 (MUST) — "Each test has its own temporary directory with a cleanup guard" — `scratch()` makes `temp_dir()/brindle-remote-conpty-<pid>-<name>` and removes it only *before* use; nothing removes it afterwards, so every run leaves four directories in the temp dir. Names are unique per test, so parallel runs are safe. Smallest fix: return a guard struct whose `Drop` removes the directory (or use a tempdir type).

## Design smells

- `remote-agent/src/main.rs:91` repeats the command list `"check" | "list" | "kill" | "status" | "stop"` that `server::cli::run` already owns, and `USAGE` is defined twice (lines 13 and 15); the two copies can drift.
- `remote-agent/src/conpty/console.rs:297-299` and `:304-308` decode the undocumented `NtQueryInformationProcess` answer (`host & !3`, `& CONNECTED`, non-zero) inline in Windows-only code with no unit test; a pure `decode(host: usize, own_pid) -> Console { NotYet, On(pid) }` would be testable everywhere, and the "when Windows doesn't say, count as connected" default (`is_none_or`) is an untested policy.
- `remote-agent/src/conpty/console.rs:288-290` polls every 1 ms for up to 1 s per closing session; a burst of closes means many polling threads.
- `remote-agent/src/conpty/console.rs:236-262` relies on a detached thread finishing `ClosePseudoConsole`; if the holder exits right after dropping the last session, the thread dies before the close runs (a cleanup in `Drop`, though not a GPUI quit, so `process R16` doesn't apply).
- `remote-agent/src/conpty/console.rs:169` the attribute-list buffer is a `Vec<u8>` (alignment 1) cast to `LPPROC_THREAD_ATTRIBUTE_LIST`; works in practice but is not guaranteed aligned.
- `remote-agent/src/conpty/console.rs:228` `try_clone().ok()` silently drops a failure that "doesn't fail" (the close then just doesn't wait).
- `remote-agent/src/conpty/cmdline.rs:49` sorts the environment with `to_uppercase()` (Unicode) where `CreateProcessW` uses the OS upcase table; equal for ASCII, may differ for non-ASCII names.
- `remote-agent/src/conpty/api.rs:42,122 (console.rs)` `#[cfg_attr(not(test), allow(dead_code, reason = "read by tests"))]` on production fields/functions that exist only for tests.
- `remote-agent/src/conpty/console.rs` tests use fixed 30 s limits (`Instant::now() + 30 s`, `recv_timeout(30 s)`) that don't scale with a factor; the loops poll for a condition, so `testing R7` is met, but `BRINDLE_E2E_SLOW`-style scaling is absent.
- `remote-agent/build.rs:49-52` parses the pinned version out of a PowerShell script by line prefix (`$Version = '`); a format change in the script panics the build with a terse message.
- `remote-agent/src/liveness.rs` is clean against the rules (time passed in, atomics only, three tests, no sleeps); the `as u64` on `as_millis()` is harmless.
