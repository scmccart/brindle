## Violations

1. `tests/e2e/cases/restore.rs:130` — testing R4 (MUST) — "Every run MUST be hermetic: each case has its own config, state directory and server directory, touches nothing of the user's ...". The idiom list in the doc names `BRINDLE_NO_SCOPE=1` as part of the hermetic case. `run_until_window_closes` hand-spawns Brindle (`Command::new(&ctx.bin) ... .env("BRINDLE_SERVER_DIR", ...)`) instead of going through `Run`. `Run` sets `BRINDLE_NO_SCOPE=1` (tests/e2e/brindle.rs:488), but this spawn does not. The terminal-server core and holder are therefore started through `systemd-run --user --scope` in the developer's or CI's own user manager. Used by `restore-forget-on-exit` and `restore-close-window`. Fix: add `.env("BRINDLE_NO_SCOPE", "1")`, or better, give `Run` a mode that waits for exit and use that.

2. `tests/e2e/cases/remote.rs:1957` — testing R4 (MUST) — same rule. `run_brindle` hand-spawns Brindle (`Command::new(&ctx.bin) ... .env("BRINDLE_SERVER_DIR", ...)`) with no `BRINDLE_NO_SCOPE=1`. It is used by `remote-container-exec` and `remote-ssh-container`; the local server they start can be scoped into the user's systemd manager. Fix: add `.env("BRINDLE_NO_SCOPE", "1")`, or build the run on `Run` as the other remote cases do (`Needs::run`).

3. `tests/e2e/cases/remote.rs:1978` — testing R5 (MUST) — "Every delay scales with one factor (`BRINDLE_E2E_SLOW`)". The deadline is `Duration::from_secs_f64(dump_after + 30.0)`. `dump_after` is scaled, but the 30 s margin is a bare constant. Fix: `dump_after + ctx.secs(30.0)`.

4. `tests/e2e/cases/remote.rs:959-960` (with `INTERVAL` at 921) — testing R8 (MUST) — "A test MUST assert the rule, not a number that depends on timing or machine speed". `palette_slow_host` asserts that "Attach Session…" shows the `listing sessions…` row at `INTERVAL * 2.5 + 0.7`. That is 0.7 s after the palette step, "well under `LIST_LIMIT`, 2 s". Under `BRINDLE_E2E_SLOW` the 0.7 s gap is stretched along with the step interval, but the app's `LIST_LIMIT` and `OPEN_GRACE` are not, so at slow >= about 3 the dump comes after the listing has given up and the row differs. The `docker pause` is likewise timed by `call_at(INTERVAL * 2.5 - 2.0, ...)` against the step timeline rather than by a condition. Fix: dump on a condition (a `--wait-for` on the pending row, or the dump taken just after the palette opens), and pause the container when the relay is seen, not at a computed time.

5. `tests/e2e/cases/palette.rs:37` (`step_time`), `:223` (`border_rows`), `:299` (`label`) — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`". These are pure helpers with real logic (border-run scan over pixels, row-label split, step-time arithmetic), and the file has no tests or `self_test`. Read literally; they are test-support helpers. Fix: a self-test case beside `remote::self_test`, or move them into the harness's `capture.rs` which has self-tests.

6. `tests/e2e/cases/profile_menu.rs:12` (`step_time`), `:18` (`two_profiles`) — fcis R8 (MUST) — same rule. `step_time` is copied from palette.rs with no test. Fix: one shared, tested `step_time`.

7. `tests/e2e/cases/restore.rs:26-45` (`local`, `titled`, `tmux`, `state`, `titles`), `:284` (`printed_pwd`) — fcis R8 (MUST) — same rule. They are pure text builders and checkers, and `printed_pwd`'s wrapped-row matching is real logic. The file has no tests or `self_test`. Fix: add a self-test, or fold them into the harness's tested helpers.

8. `tests/e2e/cases/search.rs:27` (`mostly`), `:101` (`bar_rows`), `:146` (`field_strip`), `:152` (`mix`), `:161` (`panel`) — fcis R8 (MUST) — same rule. `mix` and `panel` are pure colour arithmetic and `field_strip` and `bar_rows` are pure pixel arithmetic, with no tests. Fix: add a self-test.

## Design smells
- tests/e2e/cases/search.rs:161: `panel()` re-derives the chrome token (`mix(BACKGROUND, black, 0.35)`, then `mix(.., FOREGROUND, 0.04)`) that `Theme::ui_tokens` computes. A change to the derivation silently breaks the case; the e2e theme could expose the popover colour as a constant.
- Timing-coupled setup: many cases rely on "one step per second" and `dump_at`/`capture_at` constants instead of a `--wait-for` barrier. Examples: palette.rs `step_time` (comment: "Brindle runs its steps one second apart, the first 1.5 s in"); search.rs `PRINT_LINES` followed by `.find(..)` and `capture_at(4.5)` with no wait for `line-300`; reload.rs `theme_at(4.0)` and `capture_at(6.0)`; restore.rs `close_window` (comment "cd at ~1.5 s, recorded by the 2 s poll, window closed at ~2.5 s", where the case depends on the poll beating the close). These are the "extra padding" anti-pattern, but testing R7 is worded for unit and real-process tests, so none are counted.
- tests/e2e/cases/restore.rs:196: `ctx.sleep(2.0)` orders the second launch after the first. It is scaled, but it is a fixed sleep (the anti-pattern list names it); waiting for the first run's window or lock would be a condition. `thread::scope` plus two dumps at 7.0 and 3.0 make the case order-by-clock.
- tests/e2e/cases/remote.rs and restore.rs hand-roll Brindle spawns (`run_brindle`, `run_until_window_closes`) parallel to `Run`. This is what caused violations 1-3: each hermetic setting has to be repeated by hand.
- palette.rs and profile_menu.rs duplicate `step_time`, `expect_focus` and `expect_closed`.
- remote.rs `logged`/`log_line` and several restore.rs reads use `read_to_string(..).unwrap_or_default()`. An unreadable log looks the same as an empty one, so a poll just times out without the cause. This is test code; railway R1/R6 are not claimed.
- remote.rs `ClosedTab::run` proves absence with a 10 s sampling loop (`started` pids, 100 ms sleeps). The comment admits a short-lived `ssh` can be missed; the failed-attempt count is the real check.
- remote.rs `FIXTURE_IMAGE` caches the first case's `Result` process-wide. A failed first build repeats for every later remote case.
- restore.rs `run_until_window_closes` calls `child.kill()` on timeout without `wait()`, and has no guard like remote.rs's `ChildGuard` for an early `?` return.
- remote.rs `mark_tty`/`Docker::mark` write straight to another process's tty output through `/proc/<pid>/fd/1`. This is not synthetic OS input (testing R2 holds), but it bypasses the debug hooks; the file is Linux-only and relies on the mod-level gating of the cases.
