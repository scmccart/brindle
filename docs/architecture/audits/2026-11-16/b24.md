## Violations

1. `src/remote/local.rs:379-401` (`running_sessions`), called at `src/main.rs:863` (inside the startup closure, before the window opens) — **process R13** (MUST) — "The UI thread MUST NOT block." — The function blocks in `try_connect_within`, `hello` (`HELLO_LIMIT` 10 s) and a read loop (`stream.set_read_timeout(Some(limit))`). Its doc comment says "It blocks … it runs once, before any window opens", and `main.rs` runs it from the app's startup on the main/GPUI thread. The `main.rs:767` call is off the UI thread, in the instance listener. — Fix: list on a background task and open the window first, or have `Session::attach` supply the sessions (as `when_listed` does for remote hosts).
2. `src/terminal/server.rs:58, 96, 107, 113` (`self.listener.0.unbounded_send(..)`, `send_event`; channel made in `terminal/mod.rs`) — **process R9** (MUST) — "Every queue between a producer and a slower consumer MUST have a high and a low mark." — The reader thread's `Sink` feeds an unbounded `futures` channel (`Osc`, `Wakeup`, `Replay`, …) drained by a paced GPUI task. `Osc` events are not coalesced at the source, and the channel has no marks. The core's per-client `PAUSE`/`RESUME` bounds the bytes, not this queue. — Fix: a mark on the channel, or a written reason in the code (the consumer coalesces; the producer is bounded by `PAUSE`).
3. `src/terminal/server.rs:72, 92` (`parser.advance(&mut *term, &self.marks, bytes)`) — **process R3** (MUST) — "A new per-session … call that handles outside data gets the same guard or a reason it can't panic." — `Sink::output` and `feed_replay` parse a session's bytes on the endpoint's shared reader thread with no `catch_unwind` (grep: none in `src/remote` or `src/terminal`) and no comment saying it can't panic. A panic would end that endpoint's reader, not just the session. The code predates the docs. — Fix: wrap the per-session feed in `catch_unwind`, mark that session's terminal broken and keep the connection, as the core's `screen.rs` does.
4. `src/remote/local.rs:826-828, 865` (`std::env::set_var("BRINDLE_SERVER_HELPER" / "BRINDLE_SERVER_DIR" / "BRINDLE_NO_SCOPE", ..)`) — **ports R10** (MUST), **testing R7** (MUST) — "A unit test MUST NOT set a process-wide environment variable to steer code under test" / "no process-wide environment changes" — `a_real_core_starts_from_a_copy_and_answers` sets three process-wide variables so `Endpoint::from_env()` finds them. It is `#[ignore]` and its doc says "it runs alone", which limits the harm but isn't the constructor-argument substitute the rule asks for. — Fix: build the `Endpoint` from the values (`Endpoint::at` plus a helper/scope argument) and pass the stop command its env on the `Command`, as it already does.
5. `src/remote/local.rs:1015, 1022` (`std::thread::sleep(idle * 2)`, `std::thread::sleep(idle / 5)`), `:1029` (`assert!(taken.elapsed() >= idle * 4 / 5, ..)`), `:718` (`assert!(started.elapsed() < Duration::from_secs(2), ..)`), `:1059` (`assert!(waited >= 200ms && waited < 5 s)`) — **testing R7** (MUST: "no fixed sleeps … To wait, poll for the condition"), **testing R8** (MUST: "assert the rule, not a number that depends on timing or machine speed") — `a_relay_closes_after_its_last_session_goes` sleeps 2 s and 0.2 s as padding and asserts a lower bound on elapsed time. `a_blocked_read_does_not_delay_a_write` asserts "< 2 s" and uses a 200 ms `recv_timeout` as "the reader is waiting by now" (`:714`, `:738`, same for `:749`'s 100 ms read timeout). — Fix: poll or use channels or a fake clock for the idle timer (`Timings` with a controllable time source), and replace the elapsed-time bounds with state assertions.
6. `src/remote/local.rs:312-314, 364` (`Arc::as_ptr(&connection) as usize`, compared in `forget`) — **types R3** (MUST) — "An identity MUST be the value that stays stable, never a position or a number that is reused." — A connection's identity across `on_end` is its heap address, a number the allocator reuses. The comment argues no other connection has the address while the ending thread lives, and `Connection` already has a monotonic `id` (`NEXT_CONNECTION`, used for `LinkState` reports). — Fix: compare `connection.id()` (or hold a `Weak`/`Arc::ptr_eq` pair) instead of the address.
7. `src/remote/hosts.rs:49, 80` (`newest: 0` in `Entry`; doc "`None` before any report") — **types R7** (MUST) — "No sentinels: no `-1`, no `0` id" — `Entry::newest: u64` uses `0` for "no connection has reported". Ids start at 1 (`NEXT_CONNECTION`), so `0` works as "older than any" only by that coincidence, and `conn: Option<u64>` carries the other half of the same fact. — Fix: `newest: Option<u64>` (or one enum for no report, live and ended), so the `conn < entry.newest` test is explicit about "none yet".
8. `src/remote/local.rs:538-550, 558` (`struct Start { ready: bool, signalled: bool, status, stderr }`) — **types R1** (MUST) — "States that exclude each other MUST be one enum … Not two `bool`s" — `ready` and `signalled` are outcomes of one wait: ready, exited (status, stderr), or timed out. `ready && !signalled` can't happen, and `status` and `stderr` only matter in the not-ready cases. — Fix: `enum Start { Ready, Exited { status, stderr }, TimedOut { stderr } }`; the platform `start` returns it.
9. `src/remote/local.rs:561-565` (`let reason = match start.stderr.trim() { "" if !start.signalled => format!("no ready signal within …"), "" => …, text => … }`) — **fcis R1** (MUST: "what to show … MUST be a pure function"), **fcis R8** — The choice of the "didn't start" reason text sits inside `start_core`, which also calls `sys::start`. It is covered only by the unix shell-script tests (the Windows counterpart needs a real core). — Fix: `fn start_failure(start: &Start, limit: Duration) -> String`, unit-tested on every platform with plain values.
10. `src/terminal/server.rs:68` (`self.replay_size.take().filter(|s| s.cols > 0 && s.rows > 0 && (s.cols, s.rows) != (own.cols, own.rows))`) — **fcis R10** (SHOULD: "A new conditional in a … thread … handler SHOULD be questioned"; decision "whether to feed at another size") — The decision of whether a replay is fed at the session's size is inline in a method that holds both locks on the reader thread, and `0` stands for "invalid size" (see Design smells). It is tested only through a real `Term` and `Sink`. — Fix: `fn replay_resize(own: (u16, u16), recorded: Option<GridSize>) -> Option<GridSize>`, pure, with unit tests.
11. `src/remote/local.rs:218, 247` (`log::warn!("can't connect to {}: {error:#}", host.name())`) — **railway R6** (MUST), **railway R1** — "A failure of a session, tab or endpoint MUST become that unit's visible state … Not … a log line alone." — When `shared(&host)` fails in the eager-connect thread (`:218`) and in `when_listed` (`:247`), the failure is only logged. Nothing is reported to `Hosts`, so the sessions palette doesn't show the endpoint offline. A local `shared` failure is the more likely case there. — Fix: report `LinkState::Offline(error)` through `WATCHER` on those failures too (or return the error to the caller that opens the tab).
12. `src/remote/local.rs:281-291` (`host_token`: `Host::Local => client_token().to_string()`, `format!("{}-{hash:016x}", client_token())`) — **fcis R3** (MUST: pure code "MUST NOT read … mutable statics"; it is tested as a pure function in `each_remote_endpoint_has_a_token_of_its_own`) — The token derivation reads the process's `OnceLock` token inside the function instead of taking it as an argument. The test then needs the global. — Fix: `fn host_token(base: &str, host: &Host)`; the shell passes `client_token()`.
13. `src/remote/local.rs:119-124` (`static CONNECTIONS: LazyLock<Registry>`, `static EAGER: Mutex<Vec<Host>>`; `static TOKEN` in `client_token`) — **ports R11** (SHOULD) — "GPUI globals and other process-wide state SHOULD be created in `main.rs` before the window opens." — The registry and the eager list are statics made on first use. Only `WATCHER` is set by `main`. They are what the tests work around with `Registry::default()`. — Fix: create the registry in `main` and pass it (or make it a GPUI global), as the doc suggests.

## Design smells
- `src/remote/local.rs:105-112` — `client_token` silently falls back to the clock (`unwrap_or_default()` gives nanos 0 on a clock error) when `getrandom::fill` fails. Nothing is logged, and the token's only uniqueness is the pid.
- `src/remote/local.rs:531` — `connect_started` retries with `std::thread::sleep(20 ms)` for up to `CONNECT_RETRY`. It runs on a session start thread, so the rule on UI blocking isn't broken, but it is a sleep-retry loop.
- `src/remote/local.rs:431` — `std::env::var_os("LOCALAPPDATA").unwrap_or_default()` turns a missing variable into an empty path (a sentinel) before it reaches `server_dir::helper_copies`.
- `src/remote/hosts.rs:60` — the pure `Hosts` model implements `gpui::Global`. This isn't an `fcis R5` item (the rule names Entity, Window, App, Context), but it ties the model to GPUI. A newtype wrapper in the shell could carry it.
- `src/terminal/server.rs:116-120` — `lost` calls `self.output(..)`, so if a replay is being held (`self.replay.is_some()`), the "Session lost" line is appended to the replay bytes and fed later, ahead of `ChannelEvent::Lost`.
- `src/terminal/server.rs:67, 136-138` — `term.columns() as u16`, and `replay_size(cols: u16, rows: u16)` using zero as "invalid" (filtered at `:68`). A `GridSize` constructor that refuses zero, parsed where the listing arrives, would keep the check out of the feed path.
- `src/terminal/server.rs:58` — `unbounded_send(event).ok()` drops the send error silently (receiver gone); there is no log line.
- `src/terminal/search.rs:8-11` and `server.rs:13-15` — the app imports `alacritty_terminal` directly (a declared dependency in `Cargo.toml`) next to `brindle-term-core`'s re-export. The README rule doesn't forbid it, but the layers in the dependency diagram suggest one route.
- `src/remote/local.rs` — `Endpoint`'s fields differ per platform (`copies` on Windows, `scope` elsewhere), so the struct isn't "the same items on every platform"; this is covered by the ports R4 exception today.
- `src/remote/local.rs:1000-1006` (and `:951-955`, `:1088-1092`, `:886-890`) — the polling `eventually` helper is copied four times in one test module, each with its own 10 s deadline and 5 ms sleep.
