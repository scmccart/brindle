### fcis

1. `src/remote/local/connection.rs:1339-1383` (`Connection::failed_to_connect`) — fcis R1 (MUST) — "A decision MUST be a pure function or a method of a GPUI-free model: what to show, send, open, keep or drop". The reader thread's method decides which requests fail (`filter(|(_, pending)| !pending.is_attach())`), which attaches are told (`pending.told`), and whether to keep trying or end for good (`let keep = eager || (!refused && (state.requests.values().any(Pending::is_attach) || !state.on_listing.is_empty()));`, then `state.ended = Some(...)`). Gathering, deciding and applying are one block. Fix: a `State` method (or free fn) `connect_failed(&mut State, refused, eager) -> Failed { failed, told, keep }` with unit tests; the thread method only sends the results.
2. `src/remote/local/connection.rs:621-650` (`Connection::end_when_unused`) — fcis R1 (MUST) — same rule. The idle policy lives in the idle thread's loop: `state.idle_since.get_or_insert_with(Instant::now).elapsed() >= idle`, the give-up of closes, the `wait` computation and setting `state.ended`. Fix: a pure `idle_step(&mut State, now, idle, close_limit, eager) -> Step { Given(Vec), End(reason), Wait(Duration) }`; the loop reads the clock and waits.
3. `src/remote/local/connection.rs:1294-1320` (`Connection::disconnected`) — fcis R1 (MUST) — "what to ... keep or drop". The choice of which written requests fail and which attaches are carried (`if pending.is_attach() { pending.written = false; pending.carried = true; } else if let Some(pending) = state.requests.remove(&req) { failed.push(pending); }`) is inline in the reader's handler. Fix: `State::link_lost(&mut self) -> Vec<Pending>` with a unit test.
4. `src/remote/local/connection.rs:1387-1393` (`Connection::retry_cap`) — fcis R1 (MUST) — a backoff-cap policy (`if self.eager.load(..) && idle { timings.eager_cap } else { timings.retry_cap }`) chosen inside the connection from locked state. Fix: a pure `retry_cap(eager, idle, &Timings)` next to `relay::backoff`.
5. `src/remote/local/connection.rs:1115-1130, 1159-1177, 1188-1200` (`Connection::handle`: `SPAWNED`, `REPLAY_START`) — fcis R10 (SHOULD) — "A new conditional in a ... loop handler SHOULD be questioned ... If it chooses between outcomes from state, it moves into the model". The reader's handler decides from the request map whether a session is shown, closed (`self.send_close(spawned.session)`) or detached (`ToCore::Detach(Detach { session, layout: None })`). Fix: one `State::route_replay_start(...) -> Routed` / `State::route_spawned(...)`, the handler dispatching on the result.
6. `src/remote/local/connection.rs:331, 338` (`State::closing`, `State::give_up_closes`) — fcis R2 (MUST) — "Pure code MUST take time as an argument ... and MUST NOT call `Instant::now()`". `State` is the GPUI-free model whose methods decide (`give_up_closes` returns the closes to drop), yet `self.closing.push((session, Instant::now()))` and `queued.elapsed() >= limit` read the clock, so the policy can only be tested by waiting. Fix: take `now: Instant` in both, passed by the caller (`send_close`, `forget`, `end_when_unused`).
7. `src/remote/local/connection.rs:1737-1755, 1742` (`relay_link_ended(.., why: impl FnOnce() -> String)`) — fcis R5 (MUST; R9 SHOULD) — "no callback that reaches the world". The pure picker of a link's reason takes a closure that calls `wire.why()`, which "may wait for the exit" of the relay's process. The test needs a panicking closure to prove it isn't called (3102). Fix: the caller gathers `let why = (!stamp.expired()).then(|| wire.why());` and passes `Option<String>`.
8. `src/remote/local/connection.rs:1812-1849` (`carried_attaches`) — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests ... that need no ... server, clock or sleep". It decides which attaches are sent again or fail, in seven match arms, and has no direct test: it is reached only through threaded `fake::link` tests that use timeouts and sleeps (2613, 2659, 3208, 3246). Fix: add table tests that call it with a `HashMap<RequestId, Pending>` and a `SessionInfo` slice.
9. `src/remote/local/connection.rs:326-354` (`State::in_use`, `give_up_closes`, `closes_due`, `waits_for_listing`) — fcis R8 (MUST) — pure decisions on the model with no unit test in the file; covered only by tests that sleep and poll (2851, 2894, 2923). Fix: direct tests that build a `State` and pass `now` (after fixing item 6).
10. `src/remote/local/connection.rs:378-419` (`Stamp`: `touch`, `hold`, `deadline`) — fcis R8 (MUST) — the liveness deadline arithmetic (the `HELD` case, the `try_from` fallback) has no direct test. Fix: tests for the touch/hold/deadline transitions, with the clock injected.

### types

11. `src/remote/local/connection.rs:240-252` (`Pending { written, told, carried }`) — types R1 (MUST) — "States that exclude each other MUST be one enum ... Not two `bool`s". `carried` is "an attach that went out on a link that ended before its answer, or a recorded one not sent yet", set only with `written = false` (1309-1310, 768: `carried: listed`), and `told` is meaningful only when `waiting` is `Attach`. Lifecycle (queued, written, carried; told) is spread over three flags. Fix: `enum Sent { Queued, Written, Carried }` plus `told` on the `Attach` variant.
12. `src/remote/local/connection.rs:288-291` (`State { connected, linked }`) — types R1 (MUST) — two bools for one lifecycle (never up / up / down after having been up); `linked` implies `connected` (1055-1056 set together; `disconnected` clears only `linked` at 1302). Fix: `enum Link { NeverUp, Up, Down }`.
13. `src/remote/local/connection.rs:276-281, 1217-1233, 1279-1282, 1836-1842` — types R3 (MUST) — "An identity MUST be the value that stays stable ... Sessions are named by endpoint, id and key"; anti-pattern "Looking a session up by id alone after a reconnect". `State.sessions`, `parents` and `foreground` are keyed by bare `SessionId`, and after a link loss `kept` is built from `s.session` alone (`sessions.sessions.iter().filter(|s| s.attached).map(|s| s.session).collect()` then `missing(&mut state.sessions, &kept)`). `attached_by_replay` matches `attach.session == session`, and carried non-recorded attaches match `info.session == session` with no key check (`(None, Some(info))`). Ids restart at 1 in a fresh core and the `LIST` carries `key`, so the sink of a lost session can be given another session's replay. The comment at 1809-1811 ("the id may be another session's now") shows the hazard is known, but only a recorded attach is protected. Fix: keep the key beside each shown session (`Running` already has it) and compare id and key when pruning and when a replay arrives.
14. `src/remote/local/connection.rs:1822, 1879, 207` (`!key.is_empty() && info.key == key`; `Running::key` "empty from a core that predates keys") — types R7 (MUST) — "no empty string for 'none'". Fix: `key: Option<String>` at the protocol boundary.
15. `src/remote/local/connection.rs:1826` (`if info.cols > 0 && info.rows > 0`) — types R7 (MUST) — zero size as "not listed"; `SessionInfo.cols/rows` are a wire struct, but the sentinel is read here, not at the boundary. Fix: map it to `Option<(u16, u16)>` where the listing is decoded.
16. `src/remote/local/connection.rs:306-308, 1931` (`protocol: u32`, "0 before the first"; `if self.conn.state.lock().protocol < 3 { return; }`) — types R7 (MUST) — a zero version for "no link yet". Fix: `Option<Negotiated>`, or the `Link` enum from item 12 carrying the protocol.

### railway

17. `src/remote/local/connection.rs:1625-1636` (`Connection::write`, encode failure) — railway R6 (MUST) — "A failure of a session ... MUST become that unit's visible state ... not a log line alone". `Err(error) => { log::warn!("terminal server message not sent: {error}"); ... return true; }` only fails the pending request, if there is one. A failed encode of `DATA`, `SET_LAYOUT`, `DETACH`, `CLOSE` or `RESIZE` is a log line and the message is dropped; `Running::set_layout` has already recorded it as sent (1938), so it is never retried. Fix: return the error to the sender for these messages, or mark the layout as not sent.
18. `src/remote/local/connection.rs:1459-1476` (`reconnect_local`) — railway R8 (MUST) — "one that drops the cause the system already had". `log::debug!("reconnecting: {error:#}")` (1466, 1476) and `log::warn!` on a failed `start_core` (1471) hold the real cause, but the reason that reaches the tabs is only `"no terminal server came back within {} s"`. Fix: keep the last error and append it: `no terminal server came back within 15 s: <last error>`.

### process

19. `src/remote/local/connection.rs:442, 690-693` (`outgoing: mpsc::Sender<ToCore>`, `Connection::send`) — process R9 (MUST) — "Every queue between a producer and a slower consumer MUST have a high and a low mark". The UI thread's `Running::input`/`resize` and every other sender push into an unbounded channel that the writer holds while the link is down ("holds them"), with no limit on a relay that is never reached; a large paste queues in full. Fix: a byte count with a high mark that makes `input` drop or refuse (and say so in the tab), and a low mark that resumes.

### testing

20. `src/remote/local/connection.rs:2463, 2867, 2938, 2980, 3339, 3431` — testing R7 (MUST) — "no fixed sleeps ... To wait, poll for the condition". Six `std::thread::sleep(..)` padding calls (`sleep(Duration::from_millis(300))`, `sleep(idle * 3)`, `sleep(idle * 5)`, `sleep(Duration::from_millis(200))`) wait for something not to happen. ## Design smells

- `connection.rs:920, 937`: `run_local` and `run_relay` re-match `self.transport` and `unreachable!` on the other arm; a local-only method on a type that can be either is an illegal state kept out only at run time.
- `connection.rs:1905-1908`: `Running::reparent` guards "this machine only" with `self.conn.is_relay()` (a bool test on `Transport`) instead of a match on `Host::Local`; it works, but `types R8` names a `Host::Local` arm, and `Transport` duplicates `Host`.
- `connection.rs:366-374, 421-426`: `Slot { link: Option, closed: bool }` and `Watch { link: Option, closed }` pair an `Option` with a flag (`closed` implies no link); one enum would say so.
- `connection.rs:387, 398`: `Stamp::HELD = u64::MAX` is a sentinel inside an atomic (converted to `Option` in `deadline()`, so only a smell), and `Stamp::new`/`touch` read the clock themselves.
- `connection.rs:137`: `static NEXT_CONNECTION` is a process-wide mutable static that feeds report ids; an argument to `made` would keep tests independent.
- `connection.rs:135, 672-683`: `Report` is called under the state lock and "must not block"; a callback that runs with a lock held is a standing hazard for a UI-side `Hosts` handler.
- `connection.rs:1139-1140`: the `SESSIONS` arm locks `state` in a match guard and again in its body; two acquisitions with a gap between them (benign today, because only the reader removes `list`).
- `connection.rs:1093-1099`: an undecodable server frame is logged and skipped (allowed by `railway R5`), but a skipped `DATA` or `EXIT` frame is invisible to the tab; no unit shows it.
- `connection.rs:1126, 1145, 1155, 1173, 806`: failure texts such as `answered with SPAWNED` and `closed before it started` name neither the action nor a cause; the session layer is relied on to add them.
- `connection.rs:1896-1898`: `Running::foreground` takes the connection's `state` mutex from the UI thread (title poll); short, but it shares a lock with the reader thread.
- `connection.rs:140`: `SessionSink` and `Dial` (a fake in tests) are traits with test stand-ins; they sit at real seams (the terminal, the relay launch) rather than around a decision, so `ports R6` is not violated.
- `connection.rs:133-136`: `SessionId`, `RequestId` are plain integer aliases (tests do `spawn.req as SessionId`, 2192), so a request id and a session id can be swapped without a compile error (`types R4`, SHOULD, for ids crossing a module boundary; wire structs stay integers).
- `connection.rs` is 3457 lines with about 1950 of production code and one thread-owning type mixing transport, request bookkeeping, liveness and reporting; the `ports R13` organisation rule (one module per concern) would split request bookkeeping, liveness and state reporting.
