## Violations

1. `ui/src/text_input.rs:529` — railway R5 (MUST) — "Code that reads bytes from another process, a file, the user or the wire MUST NOT panic on any input" (the input method is another process; `range_utf16` comes from the platform). `text_for_range` does `let range = self.state.range_from_utf16(&range_utf16);` then `Some(self.state.text()[range].to_string())`. `range_from_utf16` doesn't order its ends, so a reversed UTF-16 range (start > end) makes the slice panic. `replace` and `replace_and_mark` avoid this with `.max(start)`. Smallest fix: `self.state.text().get(range)?.to_string()`, or clamp `end` to `start` in `range_from_utf16`.

2. `ui/src/text_input.rs:705-733` — fcis R1 (MUST) — "A decision MUST be a pure function or a method of a GPUI-free model: what to show". `TextInputElement::prepaint` decides inside the element: placeholder or text (`state.text().is_empty() && state.marked().is_none()`), and how the composition splits into runs (`Some(marked) => [TextRun { len: marked.start, .. }, TextRun { len: marked.end - marked.start, underline: .. }, TextRun { len: text.len() - marked.end, .. }] ... .filter(|r| r.len > 0)`). That logic has no unit test, and the `text.len() - marked.end` subtraction depends on an invariant checked nowhere there. Smallest fix: a pure `fn run_lens(text_len, marked: Option<Range<usize>>) -> Vec<(usize, bool /*underlined*/)>` and a pure `show_placeholder(&EditState)` in the editing core, with tests, and prepaint maps them to `TextRun`s.

3. `ui/src/text_input.rs:481-505` — fcis R10 (SHOULD; R1 for the click rule) — "A new conditional in a view ... SHOULD be questioned ... If it chooses between outcomes from state, it moves into the model or a pure function". `offset_for_position` chooses an outcome from the pointer position (`if position.y < bounds.top() { return 0 }`, `if position.y > bounds.bottom() { return self.state.text().len() }`, else `line.closest_index_for_x(..)`). `mouse_down` chooses the selection from the click count (`if e.click_count >= 2 { select_word_at } else { move_to(offset, shift); selecting = true }`). Neither is tested. Smallest fix: a pure `fn target_for_y(y, top, bottom, len) -> Hit { Start, End, Line }` and a model method taking the click count (`EditState::press(offset, clicks, extend)`), with unit tests.

4. `ui/src/text_input.rs:315` — types R10 (MUST) — "A cached or stored derived value MUST name what refreshes it, in the code beside it". `scroll_x: f32` is derived from the caret, text width and field width, and is refreshed only in `TextInputElement::prepaint` (`self.input.update(cx, |input, _| input.scroll_x = scroll)`). Its doc says only "Horizontal scroll of the text, in pixels." (`last_line`, `last_bounds` and `text_origin_x` do say they are the last painted values.) Smallest fix: extend the comment to "recomputed by `scroll_for_caret` in `prepaint` on every frame".

5. `ui/src/theme.rs:17-52` — types R11 (SHOULD) — "A type with an invariant SHOULD have private fields and constructors that enforce it". `Tokens` has all-public fields and an unenforced invariant: `dark` must agree with the background ("set by the token source, from the background's luminance for derived sets"). Any struct literal, or the app's token mapping, can make `dark` contradict `background`. Only the two built-in sets are checked, by `the_dark_hint_matches_the_background`. Smallest fix: a constructor (`Tokens::new(..)`) or a builder that derives `dark` from `background.l`, or drop the field and compute it from `background`.

## Design smells
- `ui/src/text_input.rs:1-8, 281, 383` — doc comments name app concepts ("the palettes' filter", "settings dialog's fields", "`--dump-screen-after`", "the `--send` debug hook"), and `describe()`/`insert()` exist for the app's debug hooks. This is not a code dependency, but it sits against `ports R2`'s "knows nothing of ... the app".
- `ui/src/text_input.rs:317-321` — `last_line: Option<ShapedLine>`, `last_bounds: Option<Bounds>` and `text_origin_x: Pixels` are always set together in `paint` and read together in `offset_for_position`. That is three fields for one fact (a `Option<LastPaint>` would be one). It is close to `types R1` but not clearly covered by it.
- `ui/src/text_input.rs:482, 321, 315` — `offset_for_position` returns `0` when there is no painted line yet, and `text_origin_x` and `scroll_x` start at `0`: `0` stands for "unknown" (close to `types R7`). An `Option<usize>` return would make the caller decide.
- `ui/src/text_input.rs:291-302, 738` — `scroll_for_caret` takes and returns bare `f32` pixels, and the call site converts with `.into()`. Taking `Pixels` would make the unit visible, though only one unit is involved.
- `ui/src/text_input.rs:774` — `line.paint(...).ok()` silently drops a paint error. It is an expected failure value discarded with no trace (touches `railway R1`/`R6`, but a per-frame paint has no unit to show it on).
- `ui/src/text_input.rs:752` — `prepaint` mutates the entity (`input.scroll_x = scroll`) without a notify. This is an idiom GPUI allows, and it makes the render pass stateful.
- `ui/src/text_input.rs:244` — `let word = |c: char| is_word_char(c);` is a redundant closure.
- `ui/src/theme.rs:163-171` vs `197-208` — `ui_theme()` panics when `UiTheme` is unset (documented, a Brindle bug, so within `railway R9`), while `ui_font()` falls back to `SYSTEM_UI_FONT`. The two accessors are inconsistent. `ui_font`'s fallback arm is not unit-tested, because it needs an `App`.
- `ui/src/theme.rs:55-57` — `hex` returns `Hsla` via `rgb(..).into()`, so the "source" hex values are only checked through the `bytes()` round trip in tests. That is fine, just noting that the equality tests all go through float conversion.
- `ui/Cargo.toml` — no findings. The only dependency is `gpui = "0.2.2"` (`ports R2`, `R3`), with no dev-dependencies. The `text_input.rs` and `theme.rs` imports are `std::ops::Range`, `gpui` and `crate::` only.

Checked and clean: no IO, env, fs, clock or global reads in `EditState` or `scroll_for_caret` (`fcis R2`, `R3`, `R5`); no `cfg` attributes in the three files (`ports R4`); no `anyhow` (`railway R2`); no `_ =>` arm on `Motion` (its `match` names every variant, so there are no `[EXCEPTION railway R3]` instances); no non-test `unwrap` or `expect`; no key binding; UTF-16 and byte offsets are converted only by `EditState` methods (`types R5`); `EditState`, `single_line` and `scroll_for_caret` have deterministic unit tests in-file with no sleeps or env (`fcis R8`, `testing R7`, `R8`); the `Tokens` methods and constructors have in-file tests.
