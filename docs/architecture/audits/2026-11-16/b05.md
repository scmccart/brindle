## Violations

### fcis (placement, purity)
- fonts.rs:196 — fcis R3 (MUST) — "Pure code MUST NOT read the environment, files..." — `FontsState::reload` does `std::fs::read_to_string(path)` inside the GPUI-free model (also reached from `new`, and from settings_dialog.rs:844 on a section switch). Fix: the shell reads the text and passes `Option<&str>` / `Result<String, ReadError>` to `FontsState::new/reload`.
- profiles.rs:558 — fcis R3 (MUST) — same rule — `ProfilesState::reload` does `std::fs::read_to_string(path)` in the model. Fix: same, pass the file text in.
- fonts.rs:293 — fcis R9 (SHOULD) — "A function that decides and acts SHOULD be split" — `FontsState::apply` validates, computes `preview()` changes and writes the file through `config_edit::save(path, ...)` in one call. Fix: return the edit to make (the changes) and let the shell call `config_edit::save`.
- profiles.rs:715 — fcis R9 (SHOULD) — `ProfilesState::save` validates, builds the edit and calls `config_edit::save(path, ...)`, then reloads from disk, mutates `mode`, `renames`, `selected`. Fix: as above.
- profiles.rs:769 — fcis R9 (SHOULD) — `delete_selected` decides and writes (`config_edit::save(path, ...)` then `reload`). Same fix.
- profiles.rs:778 — fcis R9 (SHOULD) — `move_selected` decides (edge check) and writes (`config_edit::move_profile` inside `save`, then `reload`). Same fix.
- profiles.rs:905-918 (`choice_labels`) — fcis R1 (MUST) — "A decision MUST be a pure function or a method of a GPUI-free model: what to show..." — the view method decides the labels: `None => "follow global".into()` and `Some(name) if known(name) => ... else format!("{name} (missing)")`, with `known` reading `self.model.entries` inside `SettingsDialog`. Untested. Fix: a `ProfileEditor::theme_labels(&self, known: &[String]) -> Vec<String>` (or a function) with a unit test; the view maps strings to `SharedString`.
- fonts.rs:541-547 — fcis R10 (SHOULD) — "A new conditional in a view ... SHOULD be questioned" — the combobox handler decides `match ix { 0 => FamilyChoice::Default, _ => option(ix) ... }`, relying on knowledge that option 0 is Default (the layout `family_groups` builds). Fix: `family_options(&groups)[ix]` in a model function (`choice_at(groups, ix)`), tested.
- profiles.rs:1068, 1040-1043, 1206-1209, 1281-1285 — fcis R10 (SHOULD) — small show-decisions in render code: `ix < 9` for the ctrl-alt-N hint, `Ok(p) => p.description(), Err(e) => e.clone()` row detail, "Edit {name:?}" vs "New profile" title, locked/unlocked default note. Fix: a row/title/note value from the model.
- profiles.rs:627 — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`" — `ProfilesState::move_selection` has no test in profiles.rs (it is exercised only from settings_dialog.rs:2090+). Also `describe` for `Mode::ConfirmDelete` (profiles.rs:829) has no test in the file. Fix: add tests here.
- fonts.rs:478 — fcis R8 (MUST) — `command_groups` is a pure function (groups to `CommandGroup`s, headings, unnamed group) with no test in fonts.rs. Fix: test it or drop it into `family_groups`'s output type.

### types
- profiles.rs:249-251 (assigned at 277) — types R1 (MUST) — "not an Option whose meaning depends on another field" — `ProfileEditor.at: Option<ProfileRef>` and `original_name: Option<String>` are `Some` together by construction (`let original_name = at.as_ref().map(|_| profile.name.clone())`); both mean "editing a saved profile". Fix: one `enum Target { New, Saved { at: ProfileRef, name: String } }`.
- profiles.rs:520-530, 595, 744, 843-844 (parent) — types R3 (MUST) — "An identity MUST be the value that stays stable, never a position... An index is valid only within the render or the call that computed it" — `ProfilesState.selected: usize` (and `ProfileEditor::return_to: usize`, line 253) is kept across `reload`, which rereads the file (`self.selected = self.selected.min(self.entries.len() - 1)`); a file changed between reloads moves the selection to another profile. `save` re-finds by name (737), but `reload` from a section switch, `delete_selected` (773) and `discard` (744) do not. Fix: keep the selected profile's name (or `ProfileRef` name) and resolve to an index after each reload, as `SessionsModel` does with `RowKey`.
- profiles.rs:575-579 — types R7 (SHOULD-level reading of MUST) — "No sentinels: ... no empty string for 'none'" — an empty/blank profile name means "unnamed" and is rewritten to `Profile N` (`(Ok(p), _) if !p.name.trim().is_empty()`). It is at the boundary and mirrors `Config`, so mild. Fix: `Option<String>` name from `config_edit::profiles`.
- profiles.rs:520-530 — types R11 (SHOULD) — "A type with an invariant SHOULD have private fields" — `ProfilesState` has `pub entries`, `pub selected`, `pub mode`; the invariant `selected < entries.len()` (and entries never empty) is held only by `reload`/`select`, and any caller can write `selected`. Fix: private fields with accessors.
- fonts.rs:402-433 (`MonospaceProbe`, created by `cx.default_global` at 418) — ports R11 (SHOULD) — "GPUI globals ... SHOULD be created in main.rs before the window opens" — the global is created lazily inside a section's sync code. Fix: `cx.set_global(MonospaceProbe::default())` in main.rs (or the dialog's open path in the composition root).

### railway
- profiles.rs:558 — railway R7 (MUST) — "'no' MUST be an ordinary answer, not an error" — a missing config file is an `Err` here (`read_to_string(path).map_err(|e| e.to_string())`), so the section goes read-only with "No such file or directory (os error 2)" and the user can't add a first profile; `FontsState::reload` (fonts.rs:198) treats `NotFound` as the default config. Fix: same `NotFound` arm.
- profiles.rs:558 — railway R8 (MUST) — "Error text MUST name the action that failed and then its cause... drops ... a path" — `map_err(|e| e.to_string())` gives the bare OS text with no action and no path (fonts.rs:199 does it right: `reading {path}: {e}`). Fix: `format!("reading {}: {e}", path.display())`.
- profiles.rs:166, 170 — railway R1 (MUST) — "An expected failure MUST be in the return type ... not ... a default returned in its place" — `shlex::try_join(...).unwrap_or_else(|_| words.join(" "))` and `try_quote(...).unwrap_or_else(|_| word.to_string())` swallow the failure (a word with a NUL) and substitute text that no longer round-trips through `split_words`, so a saved profile can change. Fix: return the failure (or show the field as unreadable).
- profiles.rs:672, 688 — railway R9 (SHOULD) — "SHOULD be `expect("why this can't fail")`" — bare `.unwrap()` on `find` over an endless range (`(self.entries.len() + 1..)`, `(2..)`). Not outside data. Fix: `.expect("an unbounded range always finds a free name")`.
- fonts.rs:118-145 (`fonts_in`) — railway R10 (SHOULD) — "A bad config falls back to defaults and shows why" — a `[font]`/`[ui_font]` value that can't be read (`size = "big"`, a non-string family entry) silently takes its default; the section shows nothing (`read_only` stays `None`; the test at fonts.rs:763 pins `line_height = "tall"` giving "1.25" with no message). The load error may be shown elsewhere; the section itself doesn't say. Fix: return the findings with the values and show them in the section.

## Design smells
- fonts.rs:12-466 — model, the probe and the view in one file, with `use gpui::…` after the model code (lines 460-470); `FontsState` also imports `FontPreview` from `settings.rs`. Not covered by a rule as worded.
- profiles.rs:433, 504 and fonts.rs:54 — the 4..=96 font-size limit and its message `"use a number from 4 to 96"` are written three times (and again in `Config::normalized`); one owner would avoid drift.
- profiles.rs:186-216 — `Values.texts` is a positional array whose literal in `from_profile` repeats `TEXT_FIELDS` order by hand (seven bare `String::new()`), with `at()` using `.expect("text field")`; a reorder compiles and breaks silently.
- profiles.rs:186-197 — `remote`, `engine` and the SSH/container texts all kept at once so values survive a kind switch (documented for `connect_at_launch`); `engine: String` is a closed set (`ENGINES`) held as a string.
- profiles.rs:855-856, 939, 1170 — which fields are selects is a const list (`SELECT_FIELDS`) plus `f if ... contains` guards, not a property of `Field`; adding a select field needs three edits.
- profiles.rs:23-65 — `Field` doc says "in the editor's (and tab) order" but declaration order differs from `FIELDS`.
- profiles.rs:1020, 1160 — `render_profiles` clones the whole `ProfileEditor` and `render_profile_editor` recomputes `editor_result()` (shlex splits, allocations) on every render; `render_fonts` recomputes `errors()` and `render_profile_list` calls `p.description()` per row per render. No IO (so not process R14), but whole-window re-render makes it run often.
- fonts.rs:455, 430 — `catch_unwind(...).unwrap_or(false)` and `cx.update(...).ok()`: a family that can't be probed counts as proportional and a failed update is dropped; documented in the comments.
- profiles.rs:761, 805-806, 831 — `unwrap_or("")` for a missing selected profile; the dump text is display only, but `delete_question` would read `Delete ""?`.
- fonts.rs:196, profiles.rs:558, 715-796 — config-file reads and writes happen on the UI thread in event handlers (not in render; small files). process R13 speaks of connecting/starting, so not reported.
- fonts.rs and profiles.rs both define a `Done` enum (`Nothing`/`Written`); fonts' derives `PartialEq`, profiles' doesn't.
- profiles.rs:1055-1061 — a click handler captures a row index from the render and calls `select(ix)` later; valid while the list doesn't change between render and click.
