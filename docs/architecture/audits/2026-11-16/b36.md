## Violations

1. `tests/perf/cases.rs:31-40` (`spawn`) — `testing R4` (MUST). Rule words: "each case has its own config, state directory and server directory, touches nothing of the user's (… running `brindle-remote`) … and cleans up the processes it started."
   - Code: the command sets `BRINDLE_CONFIG` and `.env("BRINDLE_STATE_DIR", ctx.dir.join("state"))` and nothing else for isolation. There is no `BRINDLE_SERVER_DIR`, no `BRINDLE_NO_SCOPE=1`, and no `brindle-remote stop` afterwards.
   - Effect: local Linux tabs run in the terminal server, so both perf cases (`-p Shell`, `-e`) spawn sessions in the user's real server, found through `XDG_RUNTIME_DIR`. A `Keeps` tab detaches on quit and stays there. A core that the case started is never stopped, and a leftover `serve` or `hold` is not detected.
   - Fix: give each case a private `BRINDLE_SERVER_DIR` under `/tmp` with `BRINDLE_NO_SCOPE=1`, as the e2e harness does. Run `brindle-remote stop` after the case, and fail the case if a `serve` or `hold` is still running.

2. `tests/perf/main.rs:104-218` (`main` argument handling) — `testing R3` (MUST). Rule words: an expensive suite has "an environment variable to enable it, name filters, `--list`, a `--self-test` …, and `--shard K/N` taken round-robin after filters."
   - Code: the suite has the `BRINDLE_PERF` variable, filters (`:120-122`), `--list` (`:114`) and `--self-test` (`:110`), but nothing parses `--shard`. The non-`--` args are all treated as name filters.
   - Fix: add `--shard K/N` with the same round-robin-after-filters selection as `tests/e2e`. Alternatively, amend `testing R3` to exempt the perf suite, since numbers from sharded runs are not comparable.

3. `tests/perf/main.rs:209` — `railway R1` (MUST). Rule words: "An expected failure MUST be in the return type … Not … a log line with a default returned in its place."
   - Code: `std::fs::write(run_dir.join("summary.toml"), summary.to_toml()).ok();` throws the write error away. `summary.toml` is the suite's one durable output and the baseline for the next run (`testing R14`).
   - Effect: a failed write still prints the report and exits 0.
   - Fix: print the error and exit 1, or return it from a `run() -> Result` wrapper.

4. `tests/e2e/winproc.rs:28` (`all`) — `railway R1` (MUST). Rule words: "Not a panic, a sentinel value, or … a default returned in its place."
   - Code: `let Ok(snapshot) = CreateToolhelp32Snapshot(...) else { return found };` returns an empty list when the snapshot fails. That reads the same as "no processes".
   - Effect: `tests/e2e/main.rs:380` uses `all()` in the leftover-role check, so a failed snapshot would pass `testing R4`'s "a process still running fails the case". `parent()` has the same blind spot.
   - Fix: return `Result<Vec<Process>>`.

5. `tests/e2e/winproc.rs:204-206` (`elevated`) — `railway R1` (MUST), the same sentinel-default pattern.
   - Code: `if unsafe { OpenProcessToken(...) }.is_err() { return false; }` and `asked.is_ok() && ...` turn an error into "not elevated". A case branching on this would silently take the unelevated path.
   - Counter-case: `token_elevated` at `:240` deliberately fails the other way, treating an unreadable token as elevated, and documents it.
   - Fix: return `Result<bool>`.

6. `tests/perf/main.rs:133`, `:138`, `:162` — `ports R4` (MUST), untagged. This file is not named in the exception list.
   - Code: `cfg!(not(target_os = "linux"))`, `#[cfg(target_os = "linux")] if x11rb::connect(...)`, and `#[cfg(unix)] std::os::unix::fs::symlink(...)`.
   - Rule words: "code outside [the seam] MUST NOT carry a `cfg` for that concern."
   - Doubt: this is the test harness's own platform choice (X11 display, symlink), not an app concern. If `ports R4` is read to cover only the shipped code, these three are not violations.
   - Fix: none needed if the rule is scoped to the app. Otherwise move the platform-specific parts behind one helper module.

## Design smells

- `tests/perf/cases.rs:103`: the throughput script starts with a fixed `sleep 1` to wait for the first layout resize. Strictly `testing R7` covers unit and real-process tests, but a layout-resize wait is exactly the "poll the condition" case. The e2e `--wait-for` hook is not available here because the script is the `-e` command.
- `tests/perf/cases.rs:53`: the `try_wait` loop with a 100 ms sleep and a deadline is a bounded poll, which is fine. `limit` is not scaled by any slow factor, and the perf suite has no `BRINDLE_*_SLOW` equivalent (`testing R5` is worded for e2e).
- `tests/perf/cases.rs:73`: `ensure!(result.samples == ctx.samples)` fails the case on a count mismatch. It is not a numeric threshold, so it is consistent with `testing R14`. Exiting 1 for a case that "couldn't measure" (`main.rs:215`) is documented in a comment.
- `tests/perf/main.rs:157`: `date -u` shells out, and on failure falls back to the fixed directory name `run`. A second run would write into the first one's directory and overwrite its `summary.toml`. A shared name is a `testing R4`-flavoured hazard. Taking the time from `SystemTime` would be pure Rust.
- `tests/perf/main.rs:65`: `Ctx::save` swallows write errors with `.ok()`. The files are diagnostic artifacts, so low severity.
- `tests/perf/vtebench.rs:29-31`: `head()` ignores the exit status of `git rev-parse` and returns an empty string. A broken checkout therefore reads as "not at the pinned commit" and triggers fetch/checkout. The recorded `commit` could be `""`.
- `tests/perf/main.rs:120-122`: the filter and selection logic (`filters.iter().any(contains)`) sits inline in `main`. It is untested by `--self-test`, which covers only the report parsers and renderer. This is minor, since there is no libtest here.
- `tests/e2e/winproc.rs`: `first_argument` is a pure function, but its test is in `self_test()`, which only compiles and runs on Windows (`#[cfg(windows)] mod winproc`). The Linux CI therefore never checks it. That is acceptable under `testing R17` but worth knowing.
- `tests/e2e/winproc.rs:122` `alive` returns false when the process can't be opened (access denied), which is indistinguishable from "exited". `parent()` calls `all()`, which takes a full snapshot per call.
- `tests/perf/report.rs:64-65`: `field(...)? as u64` casts an `f64`. A negative or NaN value saturates silently. This is a harness parser of Brindle's own output, so low risk.
- Placement: `report.rs` is clean on `fcis`. `parse_*`, `cell`, `table` and `render` take values and read no clock, env or files. Only `Summary::load` does IO, as a shell function, and `render` is covered by the fixture self-test.
- Imports: nothing points the wrong way. `winproc` uses `brindle_remote_protocol::win` and `windows`, both allowed for the app's tests. The perf suite uses only std, serde, toml and x11rb.
