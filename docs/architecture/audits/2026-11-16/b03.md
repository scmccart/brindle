## Violations

1. `src/zone_view.rs:834-849` (`close_zone_by_id`) — fcis R1, MUST — "A decision MUST be a pure function or a method of a GPUI-free model: what to show, send, open, keep or drop; an ordering…". The choice of which zone gets focus after a close is an ordering policy (most recently focused leaf of the promoted subtree, else the first leaf). It is written inline in an entity method:
   `.filter_map(|id| self.zones.get(&id).map(|z| (id, z.last_focused))).max_by_key(|&(_, serial)| serial)...or_else(|| self.tree.leaves().into_iter().next())`.
   `last_focused`/`focus_serial` bookkeeping is also repeated by hand in `insert_terminal_zone`, `on_zone_focused`, `from_restored` (462-466), `close_zone_by_id` and `focus_zone`, so no model owns the focus order.
   Fix: a GPUI-free `FocusOrder` (or a function on `ZoneTree`) with `touch(id)` and `next_after_close(promoted)`, unit-tested. The entity would only call it.

2. `src/zone_view.rs:721-740` (`zone_outer_size`) — fcis R10, SHOULD — "A new conditional in a view… SHOULD be questioned… moves into the model or a pure function". A sizing computation with a fallback branch (measured grid, else an estimate from the window bounds and the zone's `UnitRect`) sits in an entity method and has no unit test. Only the later `can_split_zone` is pure.
   Fix: pure `outer_size_from_grid(grid, padding, has_header)` and `estimate_outer_size(rect, win, tab_bar, gap)`, tested; `zone_outer_size` only gathers `window`/`cx`.

3. `src/zone_view.rs:735-739` and `:725-731` — types R5, MUST — "Values in different spaces MUST NOT meet without a named conversion: cells and pixels (only through `cell_metrics()` and `fit_grid()`), normalised `UnitRect` and window pixels… One function owns each conversion."
   Inline: `px(content_w * rect.w as f32)` turns a `UnitRect` into pixels.
   Inline: `grid.cell_width * grid.cols as f32 + padding * 2.0 + border` turns cells into pixels.
   `f32::from(win_size.height) - crate::workspace::TAB_BAR_HEIGHT - ZONE_GAP * 2.0` mixes `Pixels` with raw `f32` pixel constants.
   Fix: one named conversion (`UnitRect::to_pixels(content: Size<Pixels>)`, and a cells-to-outer-size helper next to `cell_metrics`/`fit_grid`), used by `zone_outer_size`.

4. `src/zone_view.rs:343-355` (`ZoneContent`) — types R12, MUST — "A wrapper, variant or abstraction MUST exist for a meaning the code has today. Don't keep one 'for a future kind'". The doc says: "Starting with terminals; structured as an enum so future zone types (diff viewers, previews, etc.) can live in the same split tree." The enum has one variant (`Terminal`), and `as_terminal_view` matches only it.
   Fix: store `Entity<TerminalView>` directly in `Zone`. Add the enum when a second kind exists.

5. `src/zone_view.rs:594-604` (`zone_server_session`) — ports R4, MUST — "code outside [the seam] MUST NOT carry a `cfg` for that concern". `#[cfg(any(target_os = "linux", windows))]` / `#[cfg(not(any(target_os = "linux", windows)))]` select whether a terminal server session exists. `zone_view.rs` is not named in the ports R4 exception (the named files are workspace.rs, terminal/mod.rs, main.rs and remote/local.rs; "a few others" is not specific), so this is untagged.
   Fix: have `Terminal::server_session()` return `None` on platforms without a server, and drop the cfg here.

6. `src/settings.rs:238-259` (`platform_has_family`, plus the `#[cfg(windows)]` test at 349-355) — ports R4, MUST — a `#[cfg(windows)]` / `#[cfg(not(windows))]` pair for "does the platform have this font family" sits in `settings.rs`. That is a platform concern with a seam (`src/win.rs` owns `has_font_family`). `settings.rs` is not named in the exception, so this is untagged.
   Fix: move both bodies behind `win::has_font_family`-style items in a seam module, or give `win.rs` a non-Windows counterpart, so `settings.rs` carries no cfg.

7. `src/settings.rs:86-102` (`Settings::new(config, config_error, cx: &App)`) with `font()`, `font_size()`, `line_height()` and `set_font_preview()` — fcis R5, MUST — "Pure functions and models MUST take and return plain values: no `Entity`, `Window`, `App` or `Context`". The preview-over-config precedence, the 5..96 size clamp and the family resolution are decisions held in `Settings`, but the type can only be built from an `&App` (`installed_families(cx)` reads `cx.text_system()`).
   Fix: `Settings::new(config, error, installed: Vec<String>)`, with the shell computing `installed_families(cx)` and passing it in. This also resolves the next item.

8. `src/settings.rs:389-411, 441-481` (`in_headless_app`, `a_font_preview_overrides_the_config_until_cleared`) — fcis R8 / testing R1, MUST — "Every pure function and model MUST ship with unit tests… that need no display, server, clock or sleep" and "pure code MUST be tested directly: values in, assertions on the value out, no window". The preview/zoom/clamp rules are testable only through `Application::headless()` on a leaked thread with a 20 s `recv_timeout`; the test then overwrites `settings.installed` by hand. `font_size`'s 5..96 clamp has no assertion at all. Fix: as item 7.

9. `src/settings.rs:263-278` (`terminal_font`) — fcis R8, MUST — a pure function (it filters `FALLBACK_FAMILIES` by `installed` and excludes the family itself) with no test of its own. The headless preview test calls it without asserting the fallbacks. Fix: a plain `#[test]` asserting the fallback list for a given `installed`.

10. `src/settings.rs:14-16, 19, 47-48` (`font`, `ui_font_family`, `Preview.font`, `Preview.ui_font_family`) — types R10, MUST — "A cached or stored derived value MUST name what refreshes it, in the code beside it". These are stored values derived from `config.font`, `config.ui_font` and `installed`. `config` is `pub`, so a mutation would leave them stale. The comments say "Proportional font for tabs" and "A FontPreview with its families resolved" and name no refresh. The refresh (a rebuild of `Settings` on config load, and `set_font_preview` for `Preview`) is only in the module and `main.rs`. Fix: add "rebuilt by `Settings::new` on every config load" and "rebuilt by `set_font_preview`" beside the fields, or compute on read.

11. `src/zone_view.rs:359-360` (`Zone.title`, `Zone.status`) — types R10, MUST — same rule. They are cached derived values (title from `terminal_automatic_title`, status from `Terminal::status().summary()`) with no comment on the fields. The status refresh is only visible in `on_zone_terminal_event` (532-538). Fix: field docs naming `TitleChanged`, `Status` events and the 1 s poll (`refresh_titles`).

12. `src/zone_view.rs:691` (`.filter(|key| !key.is_empty())`) and `src/reattach.rs:173` (`!s.key.is_empty() && s.key == recorded.key`; test comment "an empty key never matches") — types R7, MUST — "No sentinels: no `-1`, no `0` id, no empty string for 'none'". The empty string stands for "core predates keys" on `ServerSession.key` and `SessionInfo.key`, and is re-checked in several readers instead of parsed once. Fix: parse at the boundary (`session.rs` and `SessionInfo` decoding) into `Option<Key>`, or a `Key` newtype whose constructor rejects empty. The wire field stays a string, since the encoding is frozen.

13. `src/reattach.rs:209-215` (`age`) — types R7, MUST — `if started == 0 { return None; }`, with doc "`None` when the core didn't say". A zero `u64` is a sentinel for "no start time". Fix: `SessionInfo.started: Option<u64>` parsed at the protocol boundary, or have the caller map 0 to `None` once. The same 0 sentinel is sorted on in `sweep` and `take_rest` (`sort_by_key(|s| (s.started, s.session))`), so an unknown start sorts first.

14. `src/zone_view.rs:136-156` (`ZoneTree::remove`) — types R7, MUST — "Absence that means something MUST be a variant". `None` means both "target not found" and "target was the root leaf". The doc says so, and `close_zone_by_id` treats both as `Exited`. Fix: return an outcome enum (`Removed(Vec<ZoneId>)`, `WasRoot`, `NotFound`).

15. `src/zone_view.rs:433-468` (`ZoneTreeView::from_restored`) — types R11, SHOULD — "A type with an invariant SHOULD have private fields and constructors that enforce it". The tree's leaves must equal the zones' ids and `active` must be a leaf. The constructor takes `tree`, `terminals` and `active` unchecked (`max_id ... unwrap_or(1)`; `if let Some(zone) = this.zones.get_mut(&active)` silently ignores a missing active). Fix: validate in a pure function (`ZoneTree` leaves vs terminal ids, active in leaves) that returns a `Result` or an outcome.

16. `src/reattach.rs:35-47` and `:56-63` (`local_profile`, `remote_profile`, `session_profile`, `swept_tabs`) — types R3, MUST — "An index is valid only within the render or the call that computed it". They return a bare `usize` index into `config.profiles`. In the audited files the index is consumed by the caller at once. Whether the caller keeps it across a config reload cannot be seen here, so this is flagged only as a risk. Fix: return the profile name (or a `ProfileId`) if any caller stores it. Listed as a violation only for the return type; needs the caller's confirmation.

17. `src/primary.rs:22-29` (`default_global::<Shared>()`) — ports R11, SHOULD — "GPUI globals and other process-wide state SHOULD be created in `main.rs` before the window opens". On non-Linux/FreeBSD platforms the `Shared` global is created lazily on the first `write_primary` via `cx.default_global`. Fix: set it in `main.rs` next to the other globals, and use `cx.global` on read.

## Design smells
- `src/zone_view.rs:543-547`, `504-513` and `887-899`: small `if id == self.active { emit } else if changed { notify }` conditionals in event handlers. The decision of when a title change is announced could be returned by a model method.
- `src/zone_view.rs:779-785` (`menu_anchor`): the decision "header bottom-left, else tree origin" is in the entity, but it only picks between two stored `Bounds`.
- `src/zone_view.rs:574-575`: double blank line. `:958`: `let card =Card::new`.
- `src/zone_view.rs:670-675`: two stacked, partly duplicated doc paragraphs ("Leaves every zone's program…" then "Brindle is quitting: …") on `quit_all`.
- `src/zone_view.rs:258-277` (`can_split_zone`): the `has_header` parameter is unused (`let _ = has_header;`).
- `src/zone_view.rs:35` (`ZONE_HEADER_HEIGHT: f32`) duplicates `brindle_ui::CARD_HEADER_HEIGHT`, guarded only by a test.
- `src/zone_view.rs:31`: `ZoneTreeView` imports `shortcut`, `terminal_automatic_title` and `TAB_BAR_HEIGHT` from `workspace`, which owns the tree view. That is a two-way module dependency, and `terminal_automatic_title` is a pure title decision that lives in the shell file.
- `src/zone_view.rs:540-547`, `626-635`, `607-614`: `refresh_zone_title` runs `terminal.foreground_process_name(snapshot)` (a `/proc` or Toolhelp read) on the UI thread inside the `TitleChanged` handler. This is the documented design (process R13/R14 are not breached in `render`), but on Windows cmd it runs once per command.
- `src/zone_view.rs:787-790` (`split_zone`): silently returns when the zone is too small. A key-bound split gives no feedback, while the menu disables the item.
- `src/zone_view.rs:1180`, `reattach.rs:519-521`: tests assert on error/label text. Fine while the error is `Result<_, String>` by exception.
- `src/settings.rs:292-307` (`resolve_family`): a configured family that is not installed falls back silently, with only `log::info!("using font family …")` in `Settings::new`. Compare railway R10 ("falls back to defaults and shows why"). Whether the Fonts section shows it is outside these files.
- `src/settings.rs:253-258`: `catch_unwind` around `resolve_font` to survive a panic inside GPUI. Acceptable as confinement of a foreign panic, but it is the only one in these files.
- `src/settings.rs:392-405`: two headless GPUI apps are spawned and leaked on threads, and may run in parallel with each other. Not shown to be a flake, but it is process-wide global GPUI state (testing R7 territory).
- `src/settings.rs:137-139` (`chrome_theme`): `cx.global::<ChromeTheme>()` panics if the global is unset. That is a bug-in-Brindle case, which railway R9 allows, but it carries no `expect` message.
- `src/reattach.rs:186-194` (`attach_target(id: u32, …)`): finds by session id alone. It is a user-typed id, within one listing, so types R3 does not bite.
- `src/primary.rs`: clean. The seam is thin, `PrimaryBuffer` is ungated and tested on every platform (fcis R7).
- `src/reattach.rs`: the best-placed file. It is pure, takes `now` as a parameter (`age`), and every function has a test.
