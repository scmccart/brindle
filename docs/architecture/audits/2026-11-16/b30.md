## Violations

1. `term-core/src/emulator.rs:71-76` — `types R7` (MUST) — "Absence that means something MUST be a variant, or an `Option` handled at the boundary. No sentinels: no `-1`, no `0` id, no empty string for 'none'." — `pub fn new(cols: u16, rows: u16, scrollback: usize)` documented "0 means [`DEFAULT_SCROLLBACK`]" and `let scrolling_history = if scrollback == 0 { DEFAULT_SCROLLBACK } else { scrollback };`. The 0 mirrors the wire's additive `SPAWN` default, but the sentinel travels into pure code, and `remote-agent/src/server/core/screen.rs:41` passes `scrollback as usize` straight through. Smallest fix: take `Option<NonZeroUsize>` (or `Option<usize>`) and map the wire's 0 to `None` where the SPAWN field is read.

2. `term-core/src/osc.rs:50-58` — `types R1` (MUST) — "States that exclude each other MUST be one enum, with data on the variants that have it. Not two `bool`s, and not an `Option` whose meaning depends on another field." — `Scanner { state: State, number: u32, digits: u8, payload: Vec<u8>, overflow: bool }`. `number` and `digits` mean something only in `State::Number`, and `payload` and `overflow` only in `State::Payload{collect: true}` / `PayloadEsc`. The code relies on the transitions at lines 112-113 and 132-133 to reset them. Smallest fix: move the fields onto the variants (`Number { number, digits }`, `Payload { collect: Collect }`, with the buffer and overflow flag inside the collecting variant). Borderline: the state machine is mostly an enum already and the fields are reset at every entry.

3. `term-core/src/notice.rs:16-22` — `fcis R8` (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`" — `impl Source { pub fn name(self) -> &'static str { … } }` has no `#[cfg(test)]` module in notice.rs. Nothing else in the batch tests it either. Smallest fix: add a test pinning the four names (they are config and log keys).

The manifest depends only on `alacritty_terminal`, `base64` and `parking_lot`. `base64` is used only in `replay/tests.rs` in this batch (`status.rs` is outside it). `parking_lot::Mutex` is used as data, with no thread spawned.

The `_ =>` arms (`emulator.rs:38` on alacritty `Event`, `osc.rs:121/136/163/188` on bytes and integers, `replay.rs:733` on a slice pattern) are on foreign types, bytes or integers, so they are not reported.

## Design smells
- `term-core/src/replay.rs:92-241` — `render` is a 150-line function that decides what to emit and writes it in one pass. It is pure (it returns bytes), so `fcis R9` doesn't apply, but it is hard to review in parts. Splitting out the mode, cursor and tail sections would help.
- `term-core/src/replay.rs:542-559` — `Out::char` and `Out::text` encode a char to UTF-8 in two near-duplicate ways.
- `term-core/src/replay/tests.rs:20-58, 73-92, 114-153` — the test harness re-declares `Size`, `Titles` and the stream-order status logic (a hand-rolled `status_events` scanner) that `emulator.rs` already provides through `Emulator`, `Titles` and `osc::Scanner`. It is test-only, but it is a second copy of "status lifetimes in stream order", which could drift from `Emulator::feed`. Driving the round trips through `Emulator` would remove it.
- `term-core/src/emulator.rs:74-76, 198-200` — `Emulator::new` and `resize` silently clamp 0 columns or rows to 1 (`size()`), where a typed non-zero size would show the invalid value at the boundary.
- `term-core/src/emulator.rs:138-142` — `Found::Notice(_) => {}` drops notices, which is intended (the server doesn't notify). The comment says only that the listener drops events, not that notices are dropped here.
- `term-core/src/replay.rs:304` — `char::from_u32(0xf0000 + l as u32).unwrap_or(' ')` silently degrades the scroll-region probe if the screen has more than about 65k lines. The failure is impossible at real sizes.
- `term-core/src/emulator.rs:46-49` — `Titles` exposes its inner `Arc<Mutex<Option<String>>>` to the whole module (`self.titles.0.lock()` in four places). A small accessor type would keep the title cell in one place.
