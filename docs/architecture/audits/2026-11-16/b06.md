## Violations

### fcis R1 (MUST): decisions inside the shell
- `src/terminal_element.rs:235-247` and `:564-570` — fcis R1 (MUST) — "A decision MUST be a pure function or a method of a GPUI-free model: what to show…" — `prepaint` decides the cursor's shape and visibility from focus, blink, IME state and rows (`if !focused && cursor_shape != CursorShape::Hidden { cursor_shape = CursorShape::HollowBlock; } else if !blink_visible { … Hidden }`, `cursor_visible = …`), and `paint` picks the mouse cursor style (`if frame.pointing_hand { PointingHand } else if frame.arrow_cursor { Arrow } else { IBeam }`). Neither has a unit test. Fix: a pure `cursor_shape(content_shape, focused, blink_visible, preedit, line, rows) -> CursorShape` and a `pointer_style(...)` beside `cell_highlight`, with tests.
- `src/terminal_element.rs:377-404` — fcis R1 (MUST) — "what to show … a grouping" — the batching policy lives in the per-cell loop of `prepaint`: skip blank undecorated cells, `isolated = !c.is_ascii() || is_cursor || width != 1 || …`, and "bridge undecorated blank gaps" up to 4 columns (`col - last.next_col <= 4`). It is untested except through e2e pixel checks. Fix: move the run-grouping into a pure function over (line, col, char, style, isolated) that returns batches, with unit tests.
- `src/terminal_element.rs:429-445` — fcis R1 (MUST) — failed-command bar geometry and clamping decided inline (`let width = if f32::from(padding) >= 6.0 { px(3.0) } else { px(2.0) }; let x = if padding >= width + px(1.0) { … }`, `(first - top).max(0)`, `((last - top) as usize).min(rows - 1)`). Fix: pure `mark_bars(spans, top, rows, padding)`.
- `src/terminal_view.rs:241-253` — fcis R1 (MUST) — the blink rule is written inside the blink task: `let visible = !window.is_window_active() || !idle || !this.blink_visible;` with `idle` from `last_activity.elapsed() > BLINK_INTERVAL`. Fix: pure `blink_visible(window_active, idle: Duration, was_visible) -> bool` (taking `idle` as an argument, `fcis R2` style), with tests.
- `src/terminal_view.rs:458-463` — fcis R1 (MUST) — "what to … open, keep": the selection type chosen in `mouse_down` from click count and modifiers (`0 | 1 if e.modifiers.alt || e.modifiers.control => SelectionType::Block, 0 | 1 => Simple, 2 => Semantic, _ => Lines`). Fix: pure `selection_type(click_count, &Modifiers) -> SelectionType` with a test.
- `src/terminal_view.rs:533-563` — fcis R1 (MUST) — wheel handling: the fractional-line accumulator (`scroll_remainder += lines; whole = trunc(); remainder -= whole`) and the routing choice between reporting to the program, alternate scroll and scrollback are written inside `scroll_wheel`. Fix: a model `WheelAccumulator::push(delta) -> i32` and a pure `wheel_action(lines, mode, shift)` returning what to do; test both.
- `src/terminal_view.rs:424-426, 428-531` — fcis R10 (SHOULD) — "A new conditional in a view … that chooses between outcomes from state moves into the model": `mouse_down`, `mouse_move` and `mouse_up` each choose between link press, reported press/motion/release, selection start/update/finish and edge-drag scroll from `MouseState` plus `TermMode`; `reporting(&self, mode, modifiers)` is a pure predicate written as a method of the view. Fix: a `MouseState` transition function (state, event, mode) returning an action enum; the view dispatches on it.
- `src/terminal_view.rs:353-374` — fcis R10 (SHOULD) — `hover` decides whether to look up a link (`wants_links`, `dragging`, `force`, cell-unchanged short-circuit) inline and mutates `MouseState` as it goes. Fix: pure `hover_decision(modifiers, dragging, cell, last_cell, force) -> Hover::{Clear, Skip, Lookup(cell)}`.

### fcis R8 (MUST): pure functions without unit tests in their own file
- `src/terminal_element.rs:52` — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file" — `pub fn fit_grid(size, padding, cell_width, line_height) -> (usize, usize)` is pure and the "single source" of grid size, with no test in `terminal_element.rs` (its `tests` module is `box_drawing`'s and covers only `rects`, `place` and `cell_highlight`). Fix: tests for the `.max(2)` floor, padding and rounding.
- `src/terminal_view.rs:141` — fcis R8 (MUST) — `fn wants_links(modifiers: &Modifiers) -> bool` (`modifiers.control && !modifiers.alt`) is pure and untested in the file. Fix: a four-row test.
- `src/theme.rs:153` — fcis R8 (MUST) — `Theme::indexed(index) -> Color` (the 6x6x6 cube and gray ramp) is pure and has no test in `theme.rs` (its only caller is `terminal/mod.rs:1122`). `Color::mix` (line 50), `Color::luminance` (89) and `impl Display for Color` (106) also have no direct test: `mix` appears in tests only as the expected value of other assertions, never against a known blend. Fix: tests for the cube corners (16, 21, 231), the ramp ends (232, 255), `mix` at t=0/0.5/1, and `Display` round-tripping `parse`.

### ports R4 (MUST): cfg outside a seam, not tagged (file not named in the exception)
- `src/terminal_view.rs:180` — ports R4 (MUST) — "code outside [the seam] MUST NOT carry a `cfg` for that concern" — `#[cfg(windows)] terminal.read(cx).parent_console_to(window);` in `TerminalView::new`. `terminal_view.rs` is not one of the files the exception names (workspace.rs, terminal/mod.rs, main.rs, remote/local.rs); it falls under "a few others" only by the exception's own wording, so reported untagged. Fix: make `parent_console_to` a no-op on other platforms behind the `Terminal`/seam side and call it unconditionally.
- `src/test_support.rs:60, 77` — ports R4 (MUST) — `#[cfg(target_os = "linux")] fn read_lease` / `#[cfg(not(target_os = "linux"))] fn read_lease` (plus `use std::os::unix` at line 5, gated by `#[cfg(all(test, unix))] mod test_support` in main.rs:24). ### types
- `src/terminal_view.rs:123-138, 585-589` — types R1 (MUST) — "States that exclude each other MUST be one enum… Not two `bool`s, and not an `Option` whose meaning depends on another field" — `MouseState` holds `selecting: bool`, `reported_button: Option<Button>` and `pending_link: Option<Link>`, which are alternative drag modes (a press is a link press, or reported to the program, or a selection; `is_dragging` ORs them and `mouse_down` returns after setting any one). Nothing prevents two being set (a missed release leaves one stale and the next press sets another). Fix: `enum Drag { None, Link(Link), Reported(Button), Selecting }`; `last_reported_cell` belongs with the reported variants.
- `src/terminal_view.rs:28-36` — types R11 (SHOULD) — "SHOULD NOT derive `Default` when its zero value is invalid" — `#[derive(Clone, Copy, Debug, Default)] struct GridLayout`: the zero value has `cell_width == 0` and `line_height == 0`, which makes `cell_at` divide by zero (NaN/inf). The derive is used only by a test (`..Default::default()` at :718). Fix: drop the derive; build the test value with all fields.

### railway
- `src/theme.rs:142` — railway R9 (SHOULD) — "`unwrap` and `expect` in non-test code … SHOULD be `expect("why this can't fail")`" — `builtin_theme("brindle-dark").unwrap()` in `impl Default for Theme`. Failure would be a bug in Brindle (not outside data), so it is permitted, but it has no message. Fix: `.expect("brindle-dark is a built-in theme")`.
- `src/win.rs:97` — railway R1 (MUST) — "Not … a log line with a default returned in its place" — `has_font_family`: `found().unwrap_or(false)` turns any DirectWrite error (factory creation, collection, `FindFamilyName`) into "the family is not installed", with no log and no distinction; the Fonts section then hides an installed family. Fix: return `windows::core::Result<bool>`'s Brindle-typed equivalent (or an outcome `Installed/Missing/Unknown`), or at least `log::warn!` the error.

### ports R8 (SHOULD): platform types leaving the seam
- `src/win.rs:45, 71, 101` — ports R8 (SHOULD) — "A seam's public items SHOULD take and return Brindle's own types or `std` types. Platform types (`HANDLE`, … `windows` crate types) stay inside the seam module" — `pub fn register_app_id(..) -> windows::core::Result<()>`, `pub fn unregister_app_id() -> windows::core::Result<()>` and `pub fn hwnd(window) -> Option<windows::Win32::Foundation::HWND>` return `windows`-crate types to callers. Fix: return `io::Result<()>` (via `io::Error::from(err)`) and, for `hwnd`, a plain `isize`/`NonZeroIsize` or have the seam do the `parent_console_to` call.

### testing (test_support.rs)
- `src/test_support.rs:42, 92` — testing R7 (MUST) — "no fixed sleeps" — `std::thread::sleep(WITHOUT_LEASE)` (a fixed 100 ms wait where leases are unavailable) and, in the test, `std::thread::sleep(Duration::from_millis(50))` before closing the writer, so the test only exercises the wait when the sleep happens to be shorter than the polling loop. The 1 ms poll at :53 is a poll for a condition and is fine. Fix: have the closer thread signal over a channel after the waiter has begun polling, and have the no-lease fallback poll `/proc/self/fdinfo`-style or retry the exec on `ETXTBSY` instead of a fixed wait.
- `src/test_support.rs:84, 103` — testing R7 (MUST) — "Each test has its own temporary directory with a cleanup guard" — the directory is `temp_dir()/brindle-test-support-<pid>` (a name shared by every run of the binary's process id, not per-test) and `remove_dir_all` is a trailing statement, so an assertion or `unwrap` panic leaves it behind. Fix: a guard type that removes on drop, or `tempfile::tempdir()` if already a dev-dependency.

## Design smells
- `terminal_element.rs:176-201, 210-446` — `prepaint` does the whole frame's work: a `view.update` for find highlights, a `terminal.update` that resizes (which may queue a server message), the term `FairMutex` lock held for the whole cell loop, and per-frame `Vec`/`String` allocation per batch. process R14 asks `prepaint` to stay free of "heavy allocation and lock contention"; none of these is IO, and the doc's table treats `TerminalElement`'s paint as shell, so not reported, but this is the hottest function in the app and is where the fcis R1 extractions above would also shrink the locked section.
- `terminal_element.rs:43-46` — `cell_metrics` replaces a failed `text_system.advance(font_id, size, 'm')` with `font_size * 0.6` silently; the cell grid then drifts from the real glyph advance with no sign why.
- `terminal_element.rs:536, 549` — `line.paint(..).ok()` discards a paint error with no trace.
- `terminal_element.rs:96-112` — `Frame` keeps `arrow_cursor: bool` and `pointing_hand: bool` that are folded into one `CursorStyle` at paint; one `CursorStyle` field decided in `prepaint` would remove the pair.
- `terminal_element.rs:67` — `cell_highlight(bool, bool, bool)` takes three positional bools; easy to transpose (the test has to name each position).
- `terminal_element.rs:876-881` — the `cell_highlight` test sits inside `box_drawing::tests` (via `super::super`), far from the function it tests.
- `terminal_element.rs:247`, `terminal_view.rs:41-47` — `(line, col)` in `cursor_cell` against `(col, line, side)` from `GridLayout::cell_at` and `(col, line)` in `last_reported_cell`/`hover_cell`: same-typed `usize` pairs in opposite orders in one pair of files.
- `terminal_view.rs:709-723` — a `use gpui::{point, px};` in the middle of the test module after the first test.
- `terminal_view.rs:572` — the debug hook reports a failure with `log::error!` and returns; debug-only, so not railway R6, but the step silently does nothing in the dump.
- `terminal_view.rs:152-153, 149` — `hovered_link` and `layout` are stored derived values; their refreshers (`refresh_hover`/`hover`, `prepaint`'s `layout_cell.set`) are named only by distant doc comments, not beside the field (types R10 is met by the `GridLayout` doc "of the last painted frame", marginal for `hovered_link`).
- `theme.rs:317-321, 142` — built-in themes are chosen by string name and `Default` depends on a runtime lookup of a literal; a `BuiltinTheme` enum (or a `const BRINDLE_DARK: Theme`) would remove the `unwrap` and the `_ => return None`.
- `theme.rs:89, 56` — two luminance definitions (`luminance`, gamma-encoded, for `is_dark`; `relative_luminance`, WCAG, for contrast); easy to use the wrong one.
- `theme.rs:23-34` — `Color::parse` passes `s` to `u32::from_str_radix`, which accepts a leading `+`, so `"+12345"` (length 6) parses as `#012345`; the boundary parse (types R6) is looser than the documented form.
- `win.rs:25-31` — `write_replacing` is plain `std::fs` logic with no Windows API, living in the Windows-only module; its temp name `path.tmp<pid>` collides between two threads of one process writing the same path. fcis R7 says helpers should compile on every platform, though this one does IO and is not pure.
- `win.rs:35-41, 116-153` — `set_app_id` logs a failure and continues; `attach_parent_console` swallows every failure by design (documented). No unit's state shows them; acceptable for process start-up, but nothing tells the user why toasts or console output are missing.
