## Violations
1. ui/src/components/checkbox.rs:108 — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`" — `pub(crate) fn click_key(event: &ClickEvent) -> Option<KeyboardButton>` is a pure function (a match over the click's variants) and `checkbox.rs`'s tests cover `toggle_request` and `toggles` but not it; it is used only through `toggles(&CHECKBOX_KEYS, click_key(event))` here and in switch.rs:121 (no test anywhere). Fix: add a test building a keyboard and a mouse `ClickEvent` and asserting `Some(button)` / `None`; or, if `ClickEvent` can't be built without a window, take the pieces `click_key` needs as plain values. Low severity.
2. ui/src/components/command.rs:415 — fcis R10 (SHOULD) — "A new conditional in a view ... SHOULD be questioned ... If it chooses between outcomes from state, it moves into the model" — in the entity method `Command::set_groups`: `let scroll = keep.map(|_| self.list.logical_scroll_top());` then `if let Some(scroll) = scroll { self.list.scroll_to(scroll); self.reveal_pending = self.rows.highlighted_row(); }`. The policy "keep the scroll offset and reveal the highlight only when `keep` named an item; otherwise reset to the top" is decided inside the entity and can only be tested with a window (the file's tests only cover `CommandRows`). Fix: have `CommandRows`/a small pure enum (`Reset` | `KeepScroll { reveal_row }`) return the policy; the entity applies it. Low severity.
3. ui/src/components/combobox.rs:222-229 — fcis R10 (SHOULD) — same rule — `sync_panel` decides which option stays highlighted after a refresh inside the entity (`let highlighted = command.highlighted().and_then(|ix| command.item(ix)).map(|item| item.label.clone()); let keep = highlighted.and_then(|label| option_labelled(&groups, &label));`). The lookup is a pure helper (`option_labelled`, tested), but the choice of the highlight's identity (its label) and the order "read the highlight, then rebuild" is in the shell and untested. Fix: a pure `fn keep_after_replace(old_groups, old_highlight, new_groups) -> Option<usize>` with a test. Low severity.
4. ui/src/components/combobox.rs:114 and :37-50 (also combobox.rs:57-65, 149-151, 204-205, 213-217) — types R3 (MUST) — "An identity MUST be the value that stays stable, never a position or a number that is reused ... An index is valid only within the render or the call that computed it." — `ComboboxEvent::Changed(usize)` and `selected: Option<usize>` name an option by its position across the groups, and `Combobox` stores that index (`selection: Selection`) between frames and hands it to the owner in an event that is delivered after the call that computed it. `set_groups` has to be given a new index by the owner each time (the code itself re-finds the highlight by label in `sync_panel`, which shows the index is not a stable identity). The module is documented to work this way (shadcn's `value` is a string); judged against the rule's words it is a position used as identity across a refresh. Fix: key options by an owner-supplied stable value (the label, or a `CommandItem` id) in `selected`/`Changed`, resolving to an index inside a call. Medium-low severity; the same index convention is in `CommandEvent::Confirmed(usize)` (command.rs:325, `Command::set_groups(.., keep: Option<usize>)`, command.rs:413), which the command.rs module doc says an owner "maps its own identities to".
5. ui/src/components/combobox.rs:450 and :291 — types R7 (MUST) — "Absence that means something MUST be a variant, or an `Option` handled at the boundary. No sentinels" — `let at = self.trigger.unwrap_or_default();` and `self.trigger.map_or(px(0.), |bounds| bounds.size.width)`: an unmeasured trigger (`None`) is turned into an all-zero `Bounds` / zero width and used to place and size the panel. Fix: only build the panel's `Anchored` when `self.trigger` is `Some`, and pass the width as `Option` to `panel_width`. Low severity (the panel normally opens after a frame has recorded the bounds).

## Design smells
- ui/src/components/card.rs:58 — `CardHeader::new` documents "A header with no title" as `SharedString::default()` (empty string for none) while `Dialog::title` uses `Option`; the header always renders `trigger_label(title)`. No rule covers it as it is display-only, but it is the pattern types R7 names.
- ui/src/components/combobox.rs:118 / :154 — `placeholder: SharedString::default()` is the "no placeholder" value, same pattern.
- ui/src/components/command.rs:350 — `reveal_pending: Option<usize>` keeps a row index across a frame; it is cleared by `rebuild`, so it is safe today, but it is a position held between calls (types R3's spirit).
- ui/src/components/button.rs:194 — `attach(button, self.tooltip.filter(|_| !self.disabled))` and :145 (`padding_x` with an icon) are small decisions made in `render` with no unit test; `button_style` carries the rest. Under fcis R10's "questioned in review"; harmless.
- ui/src/actions.rs:129,142 — the test pins `29` and `7` binding counts, so adding a binding breaks it; fine as a pin but brittle.
- ui/src/components/command.rs:565, 524-528 — the `let Some(item) = self.item(item_ix) else { return div() }` and "list asks for a row the filter has since removed" arms silently draw an empty row for a bug state; the code is defensive rather than wrong.
- ui/src/components/card.rs:196-199 — `on_header_bounds` runs a user callback during prepaint with the documented rule "must not notify"; that is a constraint on the owner, held by documentation only (process R14 concerns IO, which is not involved).
- ui/src/components/context_menu.rs — nothing to report; it is a thin shell over `Menu` and `menu_overlay` (its pure parts, `MenuAnchor::at` and `menu_item_release`, are in menu.rs, outside this batch). It has no unit tests of its own, and has no pure logic.
