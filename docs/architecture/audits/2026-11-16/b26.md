## Violations

1. `src/remote/local/link.rs:24` (also `src/remote/local/relay.rs:367-389`, the `ChildWire` impl) — types R7 (MUST) — "No sentinels: no `-1`, no `0` id, no empty string for 'none'." — `fn why(&self) -> String { String::new() }`, documented "empty otherwise". Callers branch on emptiness (`connection.rs:1747-1749`: `if !why.is_empty()`; `connection.rs:1762-1763`: `if why.is_empty()`). Fix: return `Option<String>`.

2. `src/remote/local/relay.rs:424` — types R7 (MUST) — same rule — `(profile.command.clone().unwrap_or_default(), profile.args.clone())` puts "" in `SpawnRequest.command` for "no command, use the login shell". The test at relay.rs:511 asserts `request.command == ""`. Fix: make `SpawnRequest.command` an `Option<String>` and map to the wire's empty or absent field at the encode boundary (types R9).

3. `src/remote/local/session.rs:134-143` (`id_and_key`, `running.key().to_string()`) — types R7 (MUST) — same rule — the doc says "the key is empty from a core that predates keys", and callers get "" for "no key". Fix: map the empty wire key to `None` where the `Running` is made, and return `Option<String>` or a `Key` type.

4. `src/remote/local/relay.rs:282` and `:286` — ports R4 (MUST) — "code outside [the seam] MUST NOT carry a `cfg` for that concern." — `#[cfg(unix)] { ExitStatusExt::from_raw(1 << 8) } #[cfg(windows)] { ... from_raw(1) }` in `failed_status()`. relay.rs is not a seam module. It is also not among the files the exception names (`src/workspace.rs`, `src/terminal/mod.rs`, `src/main.rs`, `src/remote/local.rs`), so this instance is untagged. Fix: add a `failed_status` item to `local/unix.rs` and `local/windows.rs`, or remove the need for it (see 6).

5. `src/remote/local/session.rs:175` — ports R4 (MUST) — same rule — `#[cfg_attr(not(windows), allow(dead_code))] pub fn reparent`. This is a `cfg` for the Windows console-owner concern, outside a seam, in a file the exception doesn't name. Fix: put the platform difference in the seam, or have the caller send `reparent` unconditionally. A Linux core answers `ERROR` to `REPARENT`, so the cleanest fix is the caller's `Host`/platform decision in a pure function.

6. `src/remote/local/relay.rs:249`, `:257`, `:280-290` — railway R1 (MUST), railway R8 (MUST) — "Not a panic, a sentinel value, or a log line with a default returned in its place"; "a message that ... drops the cause the system already had" — `state.status = Some(status.unwrap_or_else(|_| failed_status()))` and `process.state.lock().status = Some(failed_status())`. A failed `wait()` becomes a fabricated exit status of 1. `why()` and `start()` then report `"<program> exited with 1"` for a process whose status was never read, and the I/O error is dropped. Fix: hold `Option<io::Result<ExitStatus>>`, or a `Exit::{Status(ExitStatus), Unknown(io::ErrorKind)}`, and word the message "couldn't read how <program> ended: <error>". That also removes both `cfg` blocks in item 4.

7. `src/remote/local/upgrade.rs:49-50`, `:65-68`, `:70-73` — railway R6 (MUST) — "A failure of a ... endpoint MUST become that unit's visible state ... Not a modal, and not a log line alone." — `log::warn!("not offering an upgrade: ..."); return Ok(connected);` and `log::warn!("keeping the running terminal server: ...")`. A helper whose `--version` fails, a refused `check` and a refused `STEP_DOWN` each leave only a log line and fall back to the running core. This is a judgement call, because the old core keeps working by design; if the user should not be told, the rule's "visible state" does not fit. Fix: return an outcome such as `Offered::{Upgraded, Kept(reason)}` for the caller to surface, or state in the doc that a kept core is deliberately silent.

8. `src/remote/local/unix.rs:73-78` and `src/remote/local/windows.rs:129` (type at `src/remote/local.rs:539-550`) — types R1 (MUST) — "States that exclude each other MUST be one enum. Not two `bool`s" — `Start { ready: bool, signalled: bool, .. }`. `ready` implies `signalled` (the windows code computes `ready = ready == Some(true)` after `signalled = ready.is_some()`), so `ready && !signalled` is representable but invalid. There are three states: timed out, ended without the ready byte, ready. Fix: `enum Signal { TimedOut, Ended, Ready }`.

9. `src/remote/local/session.rs:338-343` (`temp_dir`) plus the tests at 459-492, 497-559, 561-591 and others — testing R7 (MUST) — "Each test has its own temporary directory with a cleanup guard." — the directory is removed by a `std::fs::remove_dir_all(&dir).ok()` as the last statement of the test (`a_reparent_waits_...` and `a_reparent_is_sent_again_...` never remove it), so any failed assertion leaves it behind. Fix: a guard type whose `Drop` removes the directory.

10. `src/remote/local/session.rs:961` — testing R7 (MUST) — "no fixed sleeps ... To wait, poll for the condition" — `std::thread::sleep(Duration::from_millis(200)); // Let the request reach the connection before the tab closes.` Fix: poll for the connection's request count, or use the fake's hook.

11. `src/remote/local/session.rs:716-718` and `:750-752` — testing R7 (MUST) — "poll for the condition within a scaled limit" — `while ended.pid().is_none() { std::thread::sleep(Duration::from_millis(10)); }` loops with no deadline, so a regression hangs the test binary. The file's own `eventually` (line 923) is bounded. Fix: use `eventually(|| session.pid().is_some())`.

12. `src/remote/local/session.rs:852` — testing R8 (MUST) — "assert the rule, not a number that depends on timing or machine speed" — `assert!(started.elapsed() < Duration::from_millis(200), ...)`. This is a wall-clock bound that a loaded machine can break. Fix: assert the rule, which is that `start_with` returns before the connect thread finishes, with a gate the fake core holds closed (as `a_tab_closed_while_attaching...` does).

13. Fixed 300 ms negative waits asserting that nothing arrives — testing R7 (MUST) — "no fixed sleeps ... poll for the condition". These are `recv_timeout(Duration::from_millis(300)).is_err()` at `session.rs:491, 589, 687, 727, 766, 830, 971, 972, 1031` and `relay.rs:701`. An absence cannot be polled, and these can pass falsely rather than flake. Fix: end each with a barrier the test controls (a later message whose arrival, in order, proves the earlier one wasn't sent), as `layouts_are_sent_once_per_change...` does with `DETACH`.

## Design smells

- `src/remote/local/session.rs` `Phase` and `run` (lines 31-283): what to queue, drop, and send in what order once a session starts (clear input on leave, resize then reparent then input, `End` then `Keep`) is a decision written as a mutex-guarded state machine inside the shell. A pure `Starting` model with `leave()` and `finish() -> Vec<Step>` would make it unit-testable without a fake core (fcis R1, R9, R10). It is tested today only through a scripted core.
- `src/remote/local/session.rs:37` and `:176`: `parent: Option<u64>` and `reparent(hwnd: u64)` pass a raw window handle as a bare integer across modules (types R4 would suggest a newtype). The wire struct keeping `u64` is fine.
- `Start.status: String` ("still running", "exit code: N", `"exit status: 1"`, which `unix.rs:313` asserts by text) is display text built in each seam. A typed exit would keep the seams thin (ports R7, R8).
- `src/remote/local/unix.rs:47-50`: the seam decides `scope::current()` versus `Plain("the endpoint uses no scope")` from `endpoint.scope`. That is a small decision in a seam (ports R7). `unix.rs:123-127` returns `None` for both a timeout and a read error, so a read error is reported as "didn't signal", with the cause dropped (railway R8, borderline).
- `src/remote/local/upgrade.rs:135`: `step_down` sets a 60 s read timeout on the stream and never restores it. On the `Err` path `offer` returns that same stream (line 72) as the running connection. Check that `Connection::start` resets it.
- `src/remote/local/upgrade.rs:113-130`: `run` leaks a thread per hung helper, and `sys::kill(pid)` runs after a timeout with no guard against pid reuse (relay.rs documents that window for its own kill).
- `src/remote/local/relay.rs:102` (`Dial`) and `link.rs:14` (`Wire`): traits whose production implementations are one (`Deployed`) and two (`Stream`, `ChildWire`), with in-memory fakes in tests (`fake::dialer`, `fake::link`). Ports R6 says a seam is `cfg`-selected modules, not traits, and testing R12 says "Brindle has no mocks". They wrap IO rather than a decision, so this is not a clear breach.
- `src/remote/local/relay.rs:140-194` (`start`): the post-marker decision (`ending`, `late`, `problem`, `code`) is inline with spawning and killing. `unstarted_message` and `exit_text` are pure and tested, but the choice of whether to wait for the exit is not (fcis R9, R10).
- `src/remote/local/relay.rs:392-397` (`Drop for ChildWire`): kills the relay process on drop. No quit effect depends on it (`DETACH` and `CLOSE` are flushed first), so process R16 is not breached, but it is a Drop-time effect worth keeping that way.
- `src/remote/local/session.rs:33-34`: the `Starting` phase's `input: Vec<Vec<u8>>` is unbounded while a connect or bootstrap (up to 120 s) is pending. Process R9 asks for marks on every producer to slower-consumer queue, so a large paste during a hung connect grows memory without limit.
- `src/remote/local/pipe.rs:241-253`: `ended` and `code` (pure mappings of Win32 codes to `io` results) have no unit test in the file, but they take `windows::core::Error` and can't be built on Linux (fcis R8 vs R7). `address` drops the `Endpoints::of` error and prints "the pipe of <dir>" (railway R8, borderline).
- Test-only `cfg(windows)` and `cfg(unix)` helpers (`relay.rs:539-595`, `:643`) and `cfg!(unix)` branches (`:665`, `:683`) are test code and allowed by testing R17's platform pairs. They are not reported under ports R4.
- Unix and windows `start` duplicate the "ready" and "signalled" computation and the log of the trampoline's stderr, since the logic sits in each seam. Hoisting it to a shared pure function would satisfy ports R7.
