## Violations
- remote-agent/tests/holder.rs:1449 — testing R7 (MUST) — "no fixed sleeps ... To wait, poll for the condition" — `std::thread::sleep(Duration::from_secs(2));` ("Long enough to print everything, if anything took it") in the Windows `without_a_core_a_program_blocks_instead_of_losing_output`; its Unix twin uses `stays_blocked` (a condition poll) instead — fix: wait on a condition (the program's console host asleep and the holder quiet), as `stays_blocked` does on Unix.
- remote-agent/tests/manage.rs:184 — testing R7 (MUST) — "no fixed sleeps" — `std::thread::sleep(std::time::Duration::from_millis(1100));` to let `detached_secs` reach 1 — fix: poll `listed()` with `eventually` until the detached column is not `0s` (and `detached_secs >= 1` in the JSON), dropping the sleep.
- remote-agent/tests/holder.rs:669 — testing R8 (MUST) — "assert the rule, not a number that depends on timing or machine speed" — `hung_up_at.elapsed() < Duration::from_millis(500)` — the rule is that SIGHUP, not the SIGKILL after the grace, ended it, and the `killed by signal Some(SIGHUP)` log count at :676 already proves that; fix: drop the elapsed bound.
- remote-agent/tests/holder.rs:1343 — testing R8 (MUST) — same — `assert!(hung_up_at.elapsed() < GRACE, "it took the grace")` (Windows) — fix: assert the exit code is not `TERMINATED` (already asserted on 1342) and drop the elapsed bound.
- remote-agent/tests/manage.rs:125 and :129 — testing R8 (MUST) — same — `assert!(age.ends_with('s') && !age.contains('m'), ...)` and `assert!(detached_for[1].ends_with('s') && !detached_for[1].contains('m'), ...)` require a session's age and detached time to be under one minute, which a loaded machine can exceed — fix: assert the columns parse as a duration (`\d+[smhd]...`) and that the detached one is not `-`.
- remote-agent/tests/relay.rs:166 — testing R8 (MUST) — same — `after < IDLE + Duration::from_secs(5)` upper bound on when the silent client's relay ended (`exits_within(IDLE + TIMEOUT)` already bounds the wait; the lower bound `>= IDLE / 2` at :164 is fine) — fix: drop the upper bound.
- remote-agent/tests/holder.rs:809 (`what_a_core_sent_before_it_went_counts_while_the_holder_had_output_for_it`) and :908 (`everything_a_core_sent_before_it_went_counts_however_much_it_was`) — testing R17 (SHOULD) — "a test that can only compile or run on one platform SHOULD have its counterpart on the other where the property matters there" — both are `#[cfg(unix)]` only; the holder's handling of a core's last messages after a failed write is platform-neutral holder logic (CLAUDE.md describes it with no platform qualifier) and Windows has no counterpart in `on_windows` — fix: add a pipe-based Windows counterpart, or state in a comment why the property is Unix-only.

## Design smells
- holder.rs:398-403 `Throttled::read` calls `std::thread::sleep(self.pause)` (25 ms) before every read: a fixed sleep, but it is the stimulus (a slow core), not a wait; the rule's words ("no fixed sleeps") read broadly, so flagging it for a decision. The test's own assertion (all bytes and the exit) is rule-based.
- holder.rs:1477 `core.quiet_for(Duration::from_secs(1))` and relay.rs:197, :288-290 (`client.next(HEARTBEAT)` / `next(300ms)` expecting `Recv::TimedOut`) wait a fixed time to show an absence; unavoidable for a "nothing arrives" check, but each is a fixed wait that a slow machine only makes less sure.
- relay.rs:201 `client.heartbeats >= 3` and relay.rs:222 `blocked < 10` (10 consecutive 20 ms looks) derive counts from timings; loose enough to hold today, but they are timing-based counts.
- relay.rs:241 `relay_rss < 32 * 1024` KiB is an absolute memory figure that depends on allocator and platform, not on speed.
- holder.rs:1051 `adopted.tails[&1].len() < 4096` (Windows) is a size bound on what the console says, depending on the host's own output.
- support/mod.rs:47 `TIMEOUT` is a constant 30 s and holder.rs:1179 uses a literal 60 s, neither scaled by a factor (testing R7 says "a scaled limit"; `BRINDLE_E2E_SLOW` only reaches the e2e suite).
- holder.rs:183, :799, :877 hold raw `libc` calls (`pipe2`, `FIONREAD`, `setsockopt`) inline in the test file instead of `support/unix.rs`; test code, not a seam violation under ports R4 as worded, but the support module already holds the unix helpers.
- holder.rs:1492-1495 `reparent_...` returns early with "skipped: no packaged ConPTY" and still counts as passed; a capability skip, not a flake skip (testing R9), but the test reports green without running.
- holder.rs:238-245 and relay.rs:316-341 assert on error message text (`starts_with("hold wasn't ready")`, `contains("refusing the server directory")`); fine in tests, but they pin wording the code has no typed outcome for.
- launch.rs sets no `BRINDLE_SERVER_DIR` for its child runs; the commands fail on argument checks (daemon.rs) before any server directory is touched, so it is hermetic in practice, not by construction (testing R4).
- holder.rs:841-848 / :939-946 treat "the socket is full" as two consecutive polls with the same unread count, which depends on the poll interval.
