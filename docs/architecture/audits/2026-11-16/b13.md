# Audit b13: remote-agent/src/server/platform/windows/{conn,daemon,dir,event_loop}.rs

All four files are inside a seam (`server/platform/windows`), so `windows::`, `std::os::windows` and `cfg(windows)` here are allowed (ports R4, R5). No forbidden crate, no `anyhow`, no `gpui`. Imports from the other crates are only `brindle_remote_protocol::{ready, win, server_dir}` and `crate::{conpty, server}`, which point the right way.

## Violations

1. `daemon.rs:155` (`parse_ready_handle`) and `daemon.rs:170` (`role_args`) — fcis R7 (MUST) — "A pure helper MUST compile and be tested on every platform, whichever platform's data it handles. Don't `cfg`-gate logic." — `fn parse_ready_handle(role: &str, args: &[String]) -> Result<Option<usize>, String>` is pure argument parsing, but it lives in the Windows-only module, so its test `ready_handle_arguments` (daemon.rs:905) runs only on Windows CI. `role_args` is the same. — Fix: move the pure parser and `role_args`, or a handle-number parser, into an ungated module such as `server/daemon.rs` or `remote-protocol`'s ready module, and test it on every platform. The Windows module keeps only the `HANDLE` calls.

2. `event_loop.rs:81` (`win32`) and `event_loop.rs:96` (`millis`) — fcis R8 (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`" — `win32` maps an HRESULT to a Win32 code with a bit mask, and `millis` rounds up and caps at `INFINITE - 1`. Neither has a direct test, and the file's tests never assert their boundaries (HRESULT with and without the 0x8007 facility, a zero timeout, a huge timeout). `daemon.rs:97` (`wide`) is a pure helper with no test either, but it is trivial. — Fix: add table tests for `win32` and `millis` in `event_loop.rs`. They are also pure logic that fcis R7 wants tested on every platform, so splitting them out of the Windows-only file would meet both rules.

3. `daemon.rs:195` (`ReadyPipe::read`) — railway R8 and R1 (MUST) — "a message … that drops the cause the system already had", and an expected failure must not be replaced by a default — `Err(_) => Some(false)` turns any read error other than `WouldBlock` into "the role ended before listening". The starter then reports only that the role failed, and the OS error is lost. — Fix: return an outcome enum such as `Pending | Listening | Failed(io::Error)`, and let the caller put the cause in its log or error line.

4. `daemon.rs:189` (`ReadyPipe::read -> Option<bool>`) — types R7 (MUST) — "Absence that means something MUST be a variant … No sentinels" — `Option<bool>` carries three states: `None` (not known yet), `Some(true)` (listening) and `Some(false)` (ended). The caller `holders.rs:591` and `holder.rs:943` must remember the encoding. — Fix: `enum ReadyState { Pending, Listening, Ended }`. This pairs with item 3. The contract is shared with the Unix module, so both change together.

5. `daemon.rs:553-558` (`daemonize`) — railway R1 (MUST) — "An expected failure MUST be in the return type … Not … a log line with a default" — `SetConsoleCtrlHandler(None, false)` ends in `.ok()`, and `let _ = std::env::set_current_dir(dir);` ignores its result, with no log line. If `SetConsoleCtrlHandler` fails, the role's programs inherit a Ctrl+C-ignoring flag, which the comment says is the reason for the call. — Fix: return the `SetConsoleCtrlHandler` error from `daemonize`, or write one line to the role's log. The directory change can stay best effort, but should be logged.

6. `dir.rs:38-67` (`ensure_with`) — ports R7 (MUST) — "Seam code MUST be thin … A decision it needs … comes from a pure helper that is tested on every platform" — the choice among "refuse (not a directory)", "re-protect the existing directory", "leave it" and "create it, then re-check" is made inline from live `symlink_metadata` results. `ensure` (line 34) also decides which directory counts as "the default" from `LOCALAPPDATA` (`default_dir`, line 25). That decision can be tested only on Windows, with real directories and DACLs. — Fix: a pure `plan(kind: Missing | Dir | NotDir | Unreadable, is_default: bool) -> Plan` in `remote-protocol::server_dir` or an ungated module, with unit tests. `dir.rs` would then just run the plan.

7. Fixed sleeps in tests — testing R7 (MUST) — "no fixed sleeps … To wait, poll for the condition" —
   - `conn.rs:428` `thread::sleep(Duration::from_millis(1))` paces the reader in `shutting_down_writes_delivers_everything_and_then_the_end`.
   - `conn.rs:508` `thread::sleep(Duration::from_millis(50))` delays a writer in `blocking_reads_wait_and_time_out`.
   - `conn.rs:609` `thread::sleep(Duration::from_millis(30))` delays a peer's write in `a_wait_takes_streams_with_and_without_a_loop`.
   - `event_loop.rs:675` `thread::sleep(Duration::from_millis(50))` delays the wake in `a_waker_wakes_a_wait_from_another_thread`.

   The 1 ms sleep is deliberate throttling, not waiting for a condition. The others only need the thread to start late, and the tests still pass if it starts early, so they check little. `daemon.rs:702` `eventually` polls, which is allowed. — Fix: replace the delay with a channel or barrier handshake (the thread signals once it is about to block) so the ordering is explicit.

8. Timing-dependent assertions in tests — testing R8 (MUST) — "assert the rule, not a number that depends on timing or machine speed" —
   - `conn.rs:496` `elapsed() >= 45ms`
   - `conn.rs:602` `elapsed() >= 50ms`
   - `event_loop.rs:536` `elapsed() >= 25ms`
   - `daemon.rs:988` `elapsed() >= READY_LIMIT`
   - Negative assertions with a fixed window: `daemon.rs:966` and `daemon.rs:1073` `!role.ends_within(500ms/1s)`, and `daemon.rs:1088` `!role.ends_within(1s)`. These hold only if the role is not killed within that window, which says nothing about the real property ("the role survives").
   - Upper bounds `conn.rs:618` and `event_loop.rs:680` (`< 5s`/`< 20s`) are loose but still clock-based.

   The lower bounds are mostly deterministic, because `millis` rounds up. The negative windows are the weaker ones. — Fix: for the survival checks, assert that the process is alive after the starter ends (a handle query) without a window, and drop the elapsed lower bounds in favour of the returned `TimedOut` or `false`.

## Design smells
- `daemon.rs:143` and `Ready::signal`: any first byte counts as "listening" (`Ok(read) => Some(read > 0)`), where the Linux side counts the role ready only on exactly `ready::BYTE`. The doc explains that Windows reads the first byte, but the byte's value is never checked.
- `daemon.rs:81` and `:309`: the ready-handle placeholder is a string (`{ready_handle}`) substituted into arguments with `arg.replace`. This is an in-band sentinel, and an argument containing that text would be rewritten.
- `daemon.rs:937,941,1013` and `dir.rs:135,140`: tests assert on error text (`contains("inherited pipe")`, `starts_with("usage: …")`). This is acceptable while the text is a single-consumer message (railway R4), but it pins wording.
- `conn.rs:65-69`: `read_timeout: Option<Duration>` has meaning only while `nonblocking` is false, so the two fields are linked. It mirrors the std socket API, so not clear-cut types R1.
- `conn.rs:45-61` and `Need { readable, writable, sent }`: three bools, but not exclusive, so not a types R1 case.
- `event_loop.rs:459-492` (`Loop::wait`): the readiness policy (pump first so a busy source can't starve the others, poll interval while an operation reports through an event, wake handling) is inline in the loop handler. It is the seam's own job and is tested through real pipes, but it is not a pure function.
- `event_loop.rs:346` `Waker::wake_on_exit(BorrowedHandle)` is `pub` and takes a platform type. The only caller is `platform/windows/pty.rs:179`, so it does not leak to the holder (ports R8 holds in practice). It could be `pub(super)`.
- `event_loop.rs:410` `unsafe impl Send for ExitWatch` and the `Arc::into_raw` leak path in `Drop` (`UnregisterWaitEx` failure leaks the reference and the handle). This is documented and bounded.
- `event_loop.rs:262-279` (`Port::shut_down`): a 5 s `DRAIN_LIMIT` blocking wait inside `Drop for Loop`. It is not a quit-time dependency (process R16 concerns Brindle's UI quit), but a stuck packet blocks the role's exit for 5 s.
- `daemon.rs:206` `SystemTime::now()` and `dir.rs:18` `std::env::var_os` are in shell/seam code, so fcis R2/R3 do not apply. `dir.rs` passes the values to the pure `resolve_windows`, as it should.
