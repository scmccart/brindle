## Violations

1. `remote-protocol/src/win.rs:346` — `fcis R8` (MUST) — "Every pure function and model MUST ship with unit tests in its own file's `#[cfg(test)] mod tests`". `Dacl::allows_only` is pure (`self.protected && self.others == 0 && found == wanted`) but its only test use is one positive assertion on a real DACL (`assert!(dacl.allows_only(&[&own, SYSTEM_SID]), ...)`, lines 666, 743, 767). No test builds a `Dacl` by value and checks the refusals: unprotected, `others > 0`, an extra SID, a missing SID, a duplicated SID. Smallest fix: add a test that builds `Dacl { protected, allowed, others }` values and asserts each case.

2. `remote-protocol/src/win.rs:346` (the whole `Dacl`/`allows_only` set, in a windows-only module) — `fcis R7` (MUST) — "A pure helper MUST compile and be tested on every platform ... Don't `cfg`-gate logic". `allows_only` uses only std types but sits in the Windows-only `win` module, so it compiles and is tested only on Windows. Smallest fix: move `Ace`, `Dacl` and `allows_only` (or just the comparison) next to `access.rs`'s pure helpers and test them there on every platform. The OS readers `Dacl::read`, `of_handle` and `of_path` stay here.

3. `remote-protocol/src/win.rs:504-584` (`ensure_helper_copy`, `place_copy`, `prune_helper_copies`) — `ports R7` (MUST) — "Seam code MUST be thin ... A decision it needs ... comes from a pure helper that is tested on every platform". These functions hold decisions: whether an existing copy is acceptable (`build_of(&copy) == Some(&build)`), how a lost rename race resolves (keep the winner's copy, or replace a wrong file), and which directories to prune (`entry.file_name() == keep`, directories only, image removed before the directory). Only `MoveFileExW` is Windows-specific. They are tested only on Windows (the race, wrong-file and prune tests). Smallest fix: extract pure decision functions (for example `after_failed_rename(copy_build, expected, copy_exists) -> Keep | Replace | Fail`, and `prune_candidates(entries, keep)`) into a platform-neutral module with unit tests. Leave the file calls here.

4. `remote-protocol/src/win.rs:266` — `ports R8` (SHOULD) — "A seam's public items SHOULD take and return Brindle's own types or `std` types. Platform types (`HANDLE`, `RawFd`, ... `windows` crate types) stay inside the seam module". `pub fn attributes(&self) -> *const SECURITY_ATTRIBUTES` returns a `windows` crate type from a public item. The consumers are other Windows seams (remote-agent `platform/windows`), so impact is small. Smallest fix: return `*const c_void`, or keep `Security` handing out only what the seam's callers need (`create_pipe`, `create_dir` taking `&Security`).

5. `remote-protocol/src/wire.rs:26,30,34` (`unknown_type`, `json`, `from_json`) — `fcis R8` (MUST) — "Every pure function ... MUST ship with unit tests in its own file". The module's own tests cover only `session_bytes`, `split_session` and `session_fixed`. `from_json` is the boundary decoder the header describes ("unknown fields ignored and missing optional fields defaulted"; error `bad {name}: ...` with `InvalidData`), and no test in this file pins that. `unknown_type`'s message and `json` are also untested here. They are exercised only through the client and holder transcript tests. Medium confidence: those transcript tests partly cover them. Smallest fix: add tests in wire.rs, such as an unknown field ignored, a missing optional defaulted, malformed JSON giving `InvalidData` with the name, and the `unknown_type` text.

## Design smells
- win.rs:554 — in `place_copy`, when another process won the rename, `return std::fs::remove_file(temp)` returns that cleanup error as the function's result even though a valid copy exists. A failed temp cleanup then fails `ensure_helper_copy`. Cleanup elsewhere (line 523) ignores errors. Make the two consistent.
- win.rs:509, 560 — the error text names only the path (`context(installed.display(), error)`, `context(copy.display(), os(error))`), not the action that failed. `railway R8` asks for action then cause. These are borderline; the other `context` calls in the file name the action ("can't open its token"). I did not count them.
- win.rs:208-211 — `check_server` flattens `Refusal` into a string-wrapped `io::Error` of kind `PermissionDenied` (`refuse(refusal.into())`). The typed `Refusal` (`OtherUser`, integrity mismatch) is lost to callers. `ports R9` names "a peer with another identity is a `Refusal`". The kind is a usable value, so I did not count a violation. Keeping the `Refusal` as the error source would let callers branch.
- win.rs:567-584 — `prune_helper_copies` returns `()` and swallows every failure (`let Ok(entries) = ... else { return }`, `let _ = remove_dir_all`). This is documented ("Nothing here fails"), but it is an expected failure with no return value or log (`railway R1`, `R6` spirit). A caller cannot tell a failed prune from nothing to prune.
- win.rs:586-587 — `SYSTEM_SID` is a pub const placed after all the code, used only for DACL checks and tests. It is likely duplicated with the SDDL string in `access.rs` (not read here).
- win.rs:955 — a test polls with `thread::sleep(50ms)` against a fixed 20 s deadline. That is a poll-with-limit as `testing R7` allows, but the limit isn't scaled. No violation.
- win.rs:490 and 507 — `build_of` and `ensure_helper_copy` read the whole helper into memory (twice per call, plus the temp copy). Fine for a few-MB exe, but unbounded.
- wire.rs:16-18 — `SessionId` and `RequestId` are plain aliases, so a session id and a request id can be swapped without a compile error. `types R4` accepts integers inside protocol structs, but these helpers' signatures (`session_bytes`, `split_session`) are the module boundary where a newtype would help. Not counted.
- wire.rs:72-84 — `use super::*;` sits after the first test in the test module, and the first test has an unrelated name style (`fixed_payloads_reject_other_lengths` is fine, the layout is odd). Style only.
- Not checked: whether `fuzz.rs` exercises `split_session`/`session_fixed` directly (`process R6`). Fuzz coverage of decoders that call them is outside the batch.
