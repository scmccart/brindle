## Violations

### Exception-tagged
- [EXCEPTION railway R4] holder.rs:102 — `pub fn run(args: &[String]) -> Result<(), String>`; the consumer is the role's log and exit.
- [EXCEPTION railway R4] platform/unix/daemon.rs:68 — `pub fn ready_from_args(...) -> Result<Option<Ready>, String>`.
- [EXCEPTION railway R4] platform/unix/daemon.rs:75 — `fn parse_ready_fd(...) -> Result<Option<RawFd>, String>`; the usage text is shown by the CLI.
- [EXCEPTION railway R3] holder.rs:447 — `_ => { ... "the first message must be HELLO" ... }` in `match ToHolder::decode(&frame) { Ok(ToHolder::Hello(hello)) => ..., _ => ...}`. The wildcard covers every other `ToHolder` variant, a Brindle-owned enum. Fix: name `Ok(other)` and `Err(_)` apart, or add a `ToHolder::is_hello`.

### Untagged
- `remote-agent/src/server/mod.rs:17` — ports R4 (MUST) — "code outside [a seam] MUST NOT carry a `cfg` for that concern" — `#[cfg(unix)] pub mod relay;`. The relay is a Linux-only platform concern (Windows refuses it). `server/mod.rs` is outside `server/platform/` and is not among the files the exception names. Fix: keep the module unconditional and have the seam supply the one item it needs, or add the file to the exception list.
- `holder.rs:731-741` — fcis R1 (MUST) — "A decision MUST be a pure function ... what to ... send ... or drop; ... a policy" — the spawn-refusal chain is written inline in the loop handler: `let refusal = if self.draining { Some("the holder is draining ...") } else if self.sessions.contains_key(&id) {...} else if spawn.command.as_deref() == Some("") {...} else if spawn.cols == 0 || spawn.rows == 0 {...}`. It has no unit test (fcis R8), only the real-process tests. Fix: `fn refusal(draining, exists, &Spawn) -> Option<Refusal>`, tested in holder.rs.
- `holder.rs:874-880` and `holder.rs:1091-1095` — fcis R1 (MUST) — same words — the backpressure policy (read a session or not, how much) is written twice, inline in `read_output` and `update_interests`: `Some(core) if core.conn.queued() >= CORE_QUEUE_HIGH || session.paused => break` and `Some(queued) => queued < CORE_QUEUE_HIGH && !session.paused, None => session.tail.room() > 0`. The two copies must agree and can drift. Fix: one pure `fn read_budget(queued: Option<usize>, paused: bool, tail_room: usize, chunk: usize) -> usize`, with tests.
- `holder.rs:1000-1005` — fcis R1 (MUST) — same words — when a reaped session's output counts as drained: `session.pty.is_none() || session.output_closed || now >= quiet_since + OUTPUT_DRAIN_IDLE || now >= reaped_at + OUTPUT_DRAIN_LIMIT`. It is inline in `tick` and takes `now`, so it is purely computable. Fix: `fn drained(now, reaped_at, last_output, pty_open, output_closed) -> bool`, with tests.
- `holder.rs:1044-1050` — fcis R1 (MUST) — same words — the core start schedule (grace, then a backoff that doubles up to the max): `let due = *self.next_core_start.get_or_insert(now + CORE_GRACE); if now >= due { ...; self.backoff = (self.backoff * 2).min(CORE_BACKOFF_MAX); }`. Fix: a pure `step(now, next, backoff) -> (start_now, next, backoff)`, with tests.
- `holder.rs:826-831` and `holder.rs:875-880` — process R9 (MUST) — "Every queue between a producer and a slower consumer MUST have a high and a low mark" — the holder-to-core queue has only a high mark, `CORE_QUEUE_HIGH`: reading resumes the moment `queued < CORE_QUEUE_HIGH`, with no low mark or hysteresis. The per-session input queue has only a hard cap: `if session.input.len() + data.bytes.len() > INPUT_QUEUE_LIMIT { ... "dropped some" }`. It drops input instead of pausing the producer. Fix: add a `CORE_QUEUE_LOW` that readers resume under. For input, either pause the core's client or state in the doc that input is lossy past the cap.
- `holder.rs:456` and `holder.rs:477` — process R10 (MUST) — "Closes MUST be graceful: send the whole queue, shut down the write side, read to the peer's end within a bound" — a refused connection gets `let _ = conn.flush();` (once, non-blocking) or `conn.flush_for(1s)`, then `drop_source`. There is no `shutdown_write` and no read to the end, so a peer's unread input can reset the connection and lose the error frame (the failure `shutdown` at 1135 avoids with `close_for`). Fix: use `close_for(small bound)` as `shutdown` does.
- `holder.rs:244-254` (`Core { handover: bool, goodbye: bool }`, set at 696-697) — types R1 (MUST) — "States that exclude each other MUST be one enum" — the states are none, goodbye, goodbye with handover. `handover` is true only if `goodbye` is, so the type allows an impossible `(false, true)`. Fix: `enum Farewell { None, Goodbye, Handover }`.
- `holder.rs:224-242` (`Session`: `pty: Option<Pty>`, `output_closed: bool`, `reaped: Option<(Option<i32>, Instant)>`, `held.exit: Option<ExitStatus>`) — types R1 (MUST) — "Not two bools, and not an Option whose meaning depends on another field" — one lifecycle (running, hung up, reaped, draining, finished) is spread over four fields. `tick` and `hang_up` must keep them consistent (e.g. 1001 reads `pty.is_none() || output_closed`). Fix: `enum Life { Running{pty}, HungUp{...}, Reaped{...}, Finished{exit} }`.
- `platform/unix/pty.rs:70-75` (`pub struct Exit { code: Option<i32>, signal: Option<i32> }`, read as `match (exit.code, exit.signal)` at holder.rs:973) — types R1 (MUST) — same words — exit code and killing signal exclude each other. Fix: `enum Exit { Code(i32), Signal(i32) }`, the same on both platforms.
- `holder.rs:982` — types R7 (MUST) — "Absence that means something MUST be a variant" — `Err(error) => { ... session.reaped = Some((None, now)); }`. `None` for the code means both "killed by a signal" (line 975) and "couldn't wait for the program", so the core is told the same `ExitStatus { code: None }` for both. Fix: carry an `Exit::Unknown` variant, or report it as an error.
- `platform/unix/event_loop.rs:67` — types R7 (MUST) — "No sentinels: no `-1`" — `static SIGNAL_WAKE_FD: AtomicI32 = AtomicI32::new(-1);`, with `if fd >= 0` in the handler. This is forced by async-signal-safety (a handler can't read an `Option`). Fix: say that beside the static, or hold the fd in a `OnceLock<RawFd>`, whose read is also signal-safe.
- `platform/unix/daemon.rs:410` — testing R7 (MUST) — "no fixed sleeps" — `std::thread::sleep(Duration::from_millis(50)); drop(role);` in `a_starter_without_a_loop_waits_for_the_pipes_end`, to order the close after the wait begins. Fix: close from the thread after a channel signal that the reader is waiting, or accept either order explicitly.
- `platform/unix/event_loop.rs:367` and `:393` — testing R7 (MUST) — same words — `std::thread::sleep(Duration::from_millis(50))` before `waker.wake()` and before `kill(SIGUSR2)`, to make the wake come after the wait started. Fix: the thread waits on a channel or barrier that the main thread releases just before `ev.wait`. The wake is level-triggered and survives either order, so this is only the "wait actually blocked" case.

## Design smells
- holder.rs:441 — `pending.conn.read_available().unwrap_or(true)` turns a read error into EOF with no log. The cause is lost (railway R8 spirit).
- holder.rs:1160-1165 — `queue` logs an encode failure and drops the message; the core is never told. The only caller-visible effect is a missing reply.
- holder.rs, `handle` and `spawn` — the single holder thread has no `catch_unwind`, unlike the core's feed. `pty::spawn(&request)` on core-supplied command, args and env lives in `crate::pty` (not audited here); if it can panic, every session dies (process R3's reason for confinement). The holder gives no "why this can't panic" comment.
- holder.rs:665, 671, 677 — `.expect("a core sent this")` rests on `process_core_frames` calling `handle` only while `self.core` is Some. That is true today, but nothing in the type says so; passing `&mut Core` into `handle` would remove the expects.
- holder.rs, `Core::interest` and `Session::interest` — a stored derived value (types R10) refreshed each turn in `update_interests`; the field docs don't name the refresher.
- holder.rs:557-561 — `previous = if core.handover { Handover } else { Crash }` is a tiny decision inline in `lose_core`; the same applies to the `should_exit` rule (1115, takes `now` but is a method on `Holder`).
- platform/unix/dir.rs:37-67 — `ensure_for` decides what is an acceptable directory (owner, mode & 0o077) inside the seam (ports R7 spirit). It is Unix-only by nature, so not testable everywhere, but a pure `fn refusal(is_dir, uid, mode, own_uid) -> Option<String>` would be.
- platform/unix/conn.rs:36-41 — `input_waiting` turns an ioctl failure into `false`, and `wait` (86-106) ignores `poll`'s result; a failed `FIONREAD` or `poll` looks like "nothing waiting".
- platform/unix/daemon.rs:140-144 — `ReadyPipe::read` turns a read error on the pipe into `Some(false)` ("not listening"), no log. Documented in a comment.
- platform/unix/daemon.rs:299-304 — the results of `chdir` and the `dup2`s in `daemonize` are ignored.
- platform/unix/event_loop.rs:33 — `#[allow(dead_code, reason = "for the core's worker threads (task group 4)")]` on `Waker::wake` is a stale planning comment, used in tests only.
- platform/unix/event_loop.rs:388-399 — the signal test installs a process-wide SIGUSR2 handler and overwrites the static `SIGNAL_WAKE_FD`; it runs in parallel with other tests in the binary. Fine today (no other test registers a signal), but nothing guards it (testing R7 spirit, ports R10 is about env vars).
- platform/unix/pty.rs:42-49 — `Pty::write` with an empty slice returns `Err(last_os_error())` (stale errno). The holder never writes empty, but the seam contract is loose.
- holder.rs:1167-1250 — the tests are good (`Tail`, `Slot::claim`), but the policy functions listed under fcis R1 have none.
