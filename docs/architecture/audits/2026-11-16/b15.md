## Violations

### types

- relay.rs:572-577 — `types R1` (MUST) — "Not an `Option` whose meaning depends on another field." — `struct ScopeChoice { decision: scope::Decision, /// Some exactly when decision is Plain  note: Option<String> }`. The doc comment says the Option is `Some` exactly when `decision` is `Plain`, and `decide_scope` (589-610) builds it that way. — Fix: one enum, `Scoped(path)` or `Plain { reason, note }`, or compute the note from `Plain` at the call site (relay.rs:357-362).
- pty.rs:156-161 — `types R1` (MUST) — "States that exclude each other MUST be one enum." — `pub struct Exit { pub code: Option<i32>, pub signal: Option<i32> }`. A program ends by an exit code or by a signal, never both, and the doc says "never on Windows". The unix module set presumably has the same shape, since the item names must match. — Fix: `enum Exit { Code(i32), Signal(i32) }` in both module sets, or a core-side type.
- relay.rs:216-217, 270 — `types R7` (MUST) — "No sentinels: no `-1`, no `0` id, no empty string for none." — `/// 0 when the core shares no protocol version with the relay: core_pid: u32` and `let core_pid = probe.welcome.as_ref().map_or(0, |welcome| welcome.pid);`. In memory, absence of a core pid is 0. At the wire `RelayHost`, `build: self.build.clone().unwrap_or_default()` (238) and `shell`/`home` `unwrap_or_default()` (232, 235) turn "none" into "". Those are frozen wire fields, so the in-memory 0 is the clear case. — Fix: `Reached.core_pid: Option<u32>`, mapped to 0 only when building `RelayHost`.
- relay.rs:429, 439, 546 — `types R3` (MUST) — "never a position or a number that is reused" — `wait_gone(old, EXIT_LIMIT)` waits for the old core by bare pid, and `runs(pid)` only checks that `/proc/<pid>/stat` exists. A reused pid reads as "still runs" for the whole 10 s and logs a false line. Impact is small. — Fix: identify the core by pid plus the start time in `/proc/<pid>/stat`.

### fcis

- relay.rs:560-568 — `fcis R1` (MUST) and `fcis R8` (MUST) — the decision "is this process alive or a zombie" sits inline with the `/proc` read in `runs`: `let Ok(stat) = fs::read_to_string(format!("/proc/{pid}/stat")) ... stat.rfind(')') ... !matches!(state, None | Some('Z' | 'X'))`. No unit test feeds the parse a zombie line. The test `a_zombie_or_a_missing_pid_doesnt_run` (827) only uses the live pid and `u32::MAX`. — Fix: `fn state_runs(stat: &str) -> bool` with tests for `R`, `S`, `Z`, `X` and malformed lines.
- relay.rs:221-245 — `fcis R1` (MUST) and `fcis R8` (MUST) — `Reached::host` decides what to send (login shell from `SHELL`, else passwd, else empty) while reading `std::env::vars_os`, passwd and home in the same body, and has no unit test: `env.get("SHELL").filter(|shell| !shell.is_empty()).cloned().or_else(|| crate::pty::passwd_entry()...)`. — Fix: pure `fn login_shell(env: &BTreeMap<..>, passwd_shell: Option<String>) -> String` with tests, and `host()` only gathers.
- relay.rs:308-350 — `fcis R10` (SHOULD), and `fcis R1` — a retry/start state machine written in the `probe` loop body (`deadline`, `started`, `start_error`, `after_upgrade`, `waiting`), interleaved with `UnixStream::connect`, `start_core`, `log.line` and `thread::sleep`. The transitions can only be tested with a real socket and core (`tests/relay.rs`). `started` and `deadline` are two variables for one phase. — Fix: a pure `next_step(state, outcome, now) -> Step` (Return / Start / Wait / Fail) that the loop dispatches on.
- relay.rs:389-394 — `fcis R1` (MUST) — the failure reason for a core that didn't start is decided inline: `match (said.as_str(), ready, &output) { ("", None, _) => format!("no ready signal within ..."), ("", _, Ok(output)) => ..., ...}`. Untested. — Fix: `fn start_failure(stderr: &str, ready: Option<bool>, status: &io::Result<Output>, limit) -> String`.
- relay.rs:613-619 — `fcis R5` (MUST) — "no callback that reaches the world"; `fcis R9` (SHOULD) — `fn lingers(user: Option<&OsStr>, exists: impl Fn(&Path) -> bool) -> bool` takes a callback, and production passes `|path| path.exists()` (356). The output does not interleave with a stream. — Fix: pure `linger_path(user) -> Option<PathBuf>`, with the caller doing `.exists()`.
- relay.rs:449-454, 502-507 — `fcis R8` (MUST) — `no_listener` and `timed_out` are pure decisions on `ErrorKind` with no unit test in the file. (The module's test list covers `decide_scope`, `lingers`, the timing defaults and `runs` only.) — Fix: add a test for each kind.
- pty.rs:257-276, 289-317 — `fcis R1` (MUST) — "what to ... drop; an ordering, a grouping or a policy." Which processes to terminate is decided inside OS-calling loops. `Group::host` compares start times (`started >= start_time(self.root.handle())` means not ours). `Host::end_its_programs` selects victims by `pid != own && pid != self.pid`, `console_host(..) == Some(self.pid)` and `started >= self.started`. These can only be tested with real processes (the tests are real `cmd`/`ping` sessions). — Fix: a pure `fn victims(snapshot: &[Candidate{pid, console_host, started}], host: Host, own: u32) -> Vec<u32>` with unit tests, and the seam only gathers the snapshot and terminates.
- pty.rs:374-379, 398-408, 412-426, 429-434 — `fcis R7` (MUST) — "A pure helper MUST compile and be tested on every platform ... `cfg` belongs to the seam that calls it." `plain` (HRESULT to Win32 code), `program_name` (the COMSPEC fallback), `environment` (merge by case-insensitive name) and `wants_inbox` are pure decisions that live in a Windows-only module. They are not compiled or tested on Linux CI. — Fix: move them into a platform-neutral module such as `conpty::cmdline` beside `launch_line`.
- pty.rs:374-426 — `fcis R8` (MUST) — `environment` and `plain` have no unit test anywhere. `program_name` and `wants_inbox` are tested at 1309-1335. `environment` is only exercised indirectly (and the tests always pass `exact_env: true`, so the merge branch is never run). — Fix: unit tests for `plain` (0x8007xxxx, other codes) and the non-exact merge path.

### ports

- pty.rs:374-426, 257-317 — `ports R7` (MUST) — "Seam code MUST be thin ... A decision it needs (what to run, the environment, the quoting, a name) comes from a pure helper that is tested on every platform." — the seam itself decides the default program (`unwrap_or("cmd.exe")`), the environment merge, the inbox switch and which processes to kill (see the `fcis R1` and `fcis R7` entries above). — Fix: same as above.

### railway

- relay.rs:256 — `railway R1` (MUST) — "Not ... a log line with a default returned in its place." — `build: build_id::current().ok()`. A failure to read the own build id becomes `None`, which silently disables the upgrade offer and sends `build: ""` to the client. It isn't logged or shown. — Fix: keep the `io::Error` and write one `core.log` line through `server.log` when it fails.
- pty.rs:290-292 — `railway R1` (MUST) — `let Ok(processes) = processes() else { return; };`. `kill_remaining` is documented as ending every process on the host, but when the Toolhelp snapshot fails it quietly ends none, and nothing tells the holder. — Fix: have `kill_remaining`/`end_its_programs` return the `io::Error` (or a count) so the holder can log it.

### testing

- pty.rs:884, 912 — `testing R7` (MUST) — "Each test has its own temporary directory with a cleanup guard." — `std::env::temp_dir().join(format!("brindle-pty-flood-{}.txt", std::process::id()))` and `brindle-si-{pid}.ps1` are files in the shared temp directory, removed with `remove_file(..).ok()` only on the success path (an assert before it leaks them). — Fix: a per-test temp directory with a drop guard.
- pty.rs:1298-1302 — `testing R7` (MUST) — "no fixed sleeps ... poll for the condition." — `the_inbox_host_ignores_a_reparent` pumps for a fixed `Instant::now() + Duration::from_secs(1)` and then asserts `owner(..) == 0`. This is a negative check, but the length is padding. — Fix: send a probe that proves the host has processed the reparent (such as a following resize round-trip), then assert.
- pty.rs:1030, 1128, 1223 — `testing R8` (MUST) — "assert the rule, not a number that depends on timing or machine speed." — `assert!(hung_up.elapsed() < Duration::from_millis(500), "the hang-up waited")`. The rule is "hang-up never waits for the host"; 500 ms is a machine-speed number. Lines 1133 (`grace + 2 s`) and 1258/1275 (`5 s`) are also fixed limits that are not scaled. — Fix: assert that `hang_up` returns while the close thread is still pending (a state flag), not an elapsed time.

## Design smells

- relay.rs is Linux-only and names `std::os::unix::net::UnixStream`, `std::os::fd::AsFd`, `/proc/self/exe` and `/proc/<pid>/{exe,stat}` directly, outside the server platform seam. It connects with `UnixStream::connect` (299, 314, 475) although the unix module set already exports `connect`. It has no `cfg` of its own, so `ports R4` is not strictly broken. The gate is outside this batch: `#[cfg(unix)] pub mod relay;` in server/mod.rs:17, while main.rs:62-70 gates `relay` on `target_os = "linux"`. The two gates disagree, so a macOS build would compile relay.rs under `cfg(unix)` and hit the missing `/proc`. Not covered by the README's `ports R4` exception file list (remote-agent/src/server/mod.rs and remote-agent/src/main.rs are not named).
- relay.rs runs three blocking threads (stdin reader, core to stdout copier, heartbeat) plus the main thread, rather than the role's one readiness loop (`process R8`). The relay isn't a per-session thread pattern and the module docs justify it. Whether R8's "each server role" covers the relay is unclear, so this is not counted.
- relay.rs:813-824 `test_timings_replace_the_defaults_only_when_valid` asserts defaults only when the process environment happens to have neither variable set, so it silently asserts nothing otherwise. The name also says "only when valid", but no invalid value is exercised. The parse in `Timings::from_env` (132-139) reads env and parses in one closure; a pure `parse_millis(Option<&str>)` would be testable.
- relay.rs:827 `a_zombie_or_a_missing_pid_doesnt_run` never tests a zombie.
- relay.rs:722-724 `heartbeats` returns silently if `Heartbeat.encode()` fails, with no `ended` message, leaving the relay without heartbeats. A constant message can't fail today.
- relay.rs:511 `step_down` hard-codes `req = 1`, and its `Ok(None) => return Ok(())` treats a close before `OK` as success.
- pty.rs:398-408 `program_name`'s `cmd.exe`/COMSPEC fallback and 412-426 `environment`'s merge with the holder's own environment are policy in the holder's seam (`process R1` "no policy"). CLAUDE.md says Brindle always names the program (`windows_default_program`) and sends a complete environment, so both fallbacks are dead in the product. The test code relies on them (and on `exact_env`).
- pty.rs:138-144 `impl Drop for Pty` closes the pseudoconsole, and `hang_up` is documented as "like dropping the Pty". The holder's hangup depends on Drop. This is a holder session, not a Brindle quit, so `process R16` is not engaged.
- pty.rs tests skip with `eprintln!` when `pwsh.exe`/`powershell.exe` is absent (914-917) or when no packaged ConPTY is built (1247-1250). A skipped test reports as passed (`testing R17`/`R9` flavour).
- pty.rs:659-665 test helper `owner()` returns 0 for "no owner" (a sentinel, test-only).
- pty.rs:356-363 `reparent` returns `io::Result<()>` that is always `Ok`, so the signature promises a failure it can't report.
- sys.rs:12-14 Windows `random_u64()` always returns `None`, so `core.rs::random_instance` (core.rs:232-241) always uses the clock-and-pid fallback on Windows for the "random id for takeovers". The seam item exists only for name parity.
- pty.rs:296-299 `end_its_programs` takes a Toolhelp snapshot per kill and calls `OpenProcess` per process, a large per-session cost inside the holder's thread (the doc says a hang-up never waits, but `kill_remaining` does).
