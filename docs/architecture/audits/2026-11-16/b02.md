## Violations

### fcis (functional core, imperative shell)

1. `src/notify/mod.rs:217-318` — fcis R1 (MUST), also fcis R9 (SHOULD) and fcis R8 (MUST). The rule says a decision (what to keep or drop, a grouping, a policy) is a pure function or a method of a GPUI-free model. The Notifier's bookkeeping decisions sit in `Notifier` methods. `Notifier` is a GPUI global, and its `Target` holds a `WindowHandle<Workspace>`, so it can't be built in a plain test.
   - `send_request` decides which id a bell replaces (`Source::Bell => self.bell_ids.get(&request.tab).copied().unwrap_or(0)`) and then sends in the same function.
   - `remember` and `forget` decide eviction at `MAX_REMEMBERED`, bell-id upkeep and token cleanup.
   - `on_reply` decides which reply is a click: `(action == "default").then_some(target.map(|t| (t, token))).flatten()`.
   - None of this has a unit test. Only `log_line` and `toast_xml` are tested.
   - Fix: move `pending`, `shown`, `order`, `bell_ids` and `tokens` into a GPUI-free `Registry` model with `replaces_for(tab, source)`, `remember`, `reply(Reply) -> Option<(Target, Option<String>)>` and unit tests. `Notifier` then only gathers, calls and applies.

2. `src/notify/dbus.rs:35,47` — fcis R1 (MUST), also ports R7 (MUST: seam code decides nothing). The retry policy is decided inside the worker loop: `if service.is_none() && retry_at.is_none_or(|t| Instant::now() >= t)`, `retry_at = Some(Instant::now() + RETRY)`, and the warn-once flag. That is a "when to reconnect" policy in a seam handler, with no pure helper and no test. Fix: a pure `Backoff::step(state, outcome, now) -> (state, Action)`, tested, with the loop reading the clock and applying it.

3. `src/notify/toast.rs:57-86` — fcis R1 (MUST), also ports R7 (MUST). The toast worker thread decides id allocation (`let id = if replaces != 0 { replaces } else { next_id += 1; next_id - 1 }`), eviction at `KEEP` (`while shown.len() > KEEP`), `retain` by id and the warn-once flag. `toast.rs` has no tests. Fix: put id allocation and eviction in a pure model shared with mod.rs's registry (violation 1).

4. `src/notify/dbus.rs:134` (module gated at `mod.rs:12`) — fcis R7 (MUST: a pure helper compiles and is tested on every platform; don't `cfg`-gate logic). `escape_markup` is pure string logic with a unit test, but it lives in a `#[cfg(target_os = "linux")]` module, so it and its test only build on Linux. `toast_xml` (mod.rs:335) is the ungated counterpart. Fix: move `escape_markup` next to `toast_xml` in ungated code (or into policy.rs).

### types (illegal states unrepresentable)

5. `src/notify/mod.rs:110-111,224,239` and `src/notify/toast.rs:69` — types R7 (MUST: no `0` id for "none"). `Command::Notify { replaces: u32 }` is documented "the sink's id of a notification this one replaces, or 0". `send_request` produces it with `.unwrap_or(0)` and `_ => 0`, and compares `replaces != 0` at mod.rs:239 and toast.rs:69. D-Bus's own "0 means none" belongs at the dbus.rs:127 boundary only. Fix: `replaces: Option<u32>`, mapped to 0 only where the D-Bus call is built.

6. `src/picker.rs:495-496,541,564` — types R7 (MUST). `Endpoint::answered: u64` is documented "the round `listing` is from; 0 for none yet". `complete()` is `answered == self.round`, so a model built at round 0 reads as complete before any answer. Fix: `answered: Option<u64>`.

7. `src/notify/mod.rs:121,307`, `src/notify/toast.rs:103`, `src/notify/dbus.rs:95` — types R6 (MUST: parse raw input once into a typed value at the boundary). The D-Bus action name arrives as a `String` and travels as `Reply::Action { action: String }`. It is compared with the literal `"default"` in `on_reply`, and toast.rs fabricates `"default".into()` to match. Fix: a closed enum (`Clicked`, or `Other`) parsed in dbus.rs, so toast.rs sends `Reply::Clicked { id }`.

8. `src/notify/dbus.rs:31-33` — types R1 (MUST: exclusive states are one enum, not an `Option` whose meaning depends on another field). `service: Option<Service>`, `retry_at: Option<Instant>` and `warned: bool` encode one three-state machine (connected / failed, not yet warned / failed, warned, retry at T). Connected implies `retry_at == None && !warned`, and nothing enforces that. Fix: `enum Link { Up(Service), Down { retry_at: Instant, warned: bool } }`.

### process (the UI thread)

9. `src/notify/mod.rs:231-235` — process R13 (MUST: the UI thread MUST NOT block). `Notifier::send_request` is called through `Notifier::send` on the UI thread. For the `Sink::Log` sink it does a synchronous file open and append (`OpenOptions::new().create(true).append(true).open(&*path).and_then(|mut file| file.write_all(...))`). This is the test sink (`BRINDLE_NOTIFY_LOG`), and the code comments that it is deliberately synchronous. The rule's words still cover it. Fix: have the shell append on the background executor and wait for it on quit, or keep it as a documented test-only exception.

10. `src/notify/activation.rs:98-99,118` — process R13 (MUST). `activation::raise` runs on the UI thread, from a notification click (mod.rs:324) and a forwarded launch (main.rs:541). On first use `with_attached` calls `registry_queue_init::<State>(&connection)?` and `globals.bind(...)`. Per the file's own comment, these need "a registry round trip": a blocking Wayland roundtrip on the UI thread. `connection.flush()` is a blocking socket write. It happens once per process and is short, but nothing bounds it. Fix: attach on the background executor ahead of time, or accept it as a documented bounded exception.

### ports (cfg outside seams)

`src/notify/mod.rs` is not a seam file. The seams are `notify/{dbus,toast,activation}.rs`. The file is not named in the exception, which lists `workspace.rs`, `terminal/mod.rs`, `main.rs`, `remote/local.rs` and "a few others". It carries 23 `cfg`/`cfg_attr` attributes (lines 10, 12, 16, 23, 53, 67, 69, 71, 73, 105, 118, 123, 130, 132, 136, 164, 178, 180, 242, 250, 258, 334, 348), reported untagged in three clusters.

11. `src/notify/mod.rs:23-60` — ports R4 (MUST: "Never start a second, parallel seam for a concern that has one"). The window-activation concern has its seam file `notify/activation.rs` (Linux only). mod.rs also defines two inline `pub mod activation` modules, a `cfg(windows)` one at 23-50 and a `cfg(not(any(linux, windows)))` one at 53-60, so the same module name has three homes. Fix: move them to `notify/activation/{linux,windows,other}` or into `activation.rs` with a per-platform split inside it.

12. `src/notify/mod.rs:26-28` — ports R8 (SHOULD: platform types stay inside the seam module). `windows::Win32::UI::WindowsAndMessaging::{FLASHW_ALL, FLASHWINFO, FlashWindowEx, IsIconic, ...}` are named and used (lines 30-49) in mod.rs, not in a seam file. Same fix as 11.

13. `src/notify/mod.rs:10-17,67-75,105,118,123,130-138,164-195,242-263` — ports R4 (MUST). The sink choice is `cfg`-selected at the call site: `Sink::Bus` / `Sink::Toast` / `Sink::Off` variants, the matching `send_request` arms (duplicated for Bus and Toast, with only the channel type differing), the `init` arms, and the `use` lists. A new platform touches every one. Fix: a `Sink` seam item set (`dbus.rs`/`toast.rs`/`off`) with the same `spawn(...) -> Handle` and `Handle::send(Command)` names, so mod.rs has no `cfg`.

14. `src/notify/mod.rs:334-363` — ports R4 (MUST), with ports R7. `icon_path` is `cfg(windows)`, reads and writes the file system (`dirs::data_local_dir`, `std::fs::read`, `create_dir_all`, `write_replacing`) and lives in mod.rs rather than `toast.rs`, the only caller (toast.rs:47). It is a Windows concern outside its seam. `toast_xml` carries `cfg_attr(not(windows), allow(dead_code))` for the same reason. Fix: move `icon_path` into toast.rs.

## Design smells (no rule's words cover them, or the evidence is thin)

- `src/notify/mod.rs:98-102,144-152` — notification ids are the sink's server-assigned `u32`, kept bare as map keys (`shown`, `tokens`, `Reply::Closed { id }`). `dbus.rs:64` drops the service and reconnects after a failed send. A restarted notification server may reuse ids, so a stale entry could be hit (types R3's "number that is reused"). I found no evidence of reuse, so it is a smell rather than a violation.
- `src/notify/mod.rs:182-186,232` and `toast.rs:34` — command and reply channels are unbounded (`futures::channel::mpsc::unbounded`, `std::sync::mpsc::channel`) with no high/low marks (process R9). `RateLimiter` caps the producer at about 10 per 2 s, so memory is bounded in practice.
- `src/notify/dbus.rs:56-67` — a failed D-Bus `Notify` is only logged and the notification dropped, and the same for toast.rs:84 and the Log sink's write failure (mod.rs:236). This looks like a "log and carry on" failure (railway R1), but desktop notifications are best-effort and aren't a session, tab or endpoint (railway R6), so I did not report it.
- `src/notify/activation.rs:86-88` — `thread_local! ATTACHED` is lazily created process-wide state (ports R11 prefers `main.rs`). It needs GPUI's live `wl_display`, which doesn't exist before the window, so it cannot be moved to `main.rs` as is.
- `src/notify/mod.rs:335-343` and `dbus.rs:134-136` — two separate XML/markup escapers (the toast one also escapes quotes) with no shared tested helper.
- `src/notify/mod.rs:89-102`, `policy.rs:73`, `workspace.rs:1037` — tab identity is a bare `u64` across modules (`Request.tab`, `Target.tab`, `RateLimiter::allow(tab: u64, ..)`, `show_tab(tab_id: u64)`). Types R4 asks for newtypes for new identifiers; the tab id predates the rules.
- `src/notify/policy.rs:73` — `RateLimiter.tabs: HashMap<(u64, bool), Bucket>` keys on an `is_bell: bool` derived from `Source`. A two-variant enum or `Source` itself would say what the bool means.
- `src/notify/policy.rs:34-39,56-61` — `Limit` has public fields, so `interval == 0` divides by zero in `refill`, and the check `tokens >= 1.0 - 1e-9` uses an epsilon on `f64`. Only three constants use it today (types R11, SHOULD).
- `src/notify/mod.rs:118-126` — `Reply::Token` is never constructed on Windows (`cfg_attr(windows, allow(dead_code))`), and `Command`, `Reply` and `Sink::Off` exist for a platform that has no sink (`allow(dead_code)` on non-Linux, non-Windows). This is a variant kept for a future platform (types R12 reads against it).
- `src/picker.rs:36-43` — `PaletteEvent::Confirmed(usize)` and `Kill(usize)` carry an index into the palette's last rows. They are handled synchronously by the owner, so the index is valid for the call, but it is the pattern types R3 warns about. `SessionsModel::rows()` is the lookup.
- `src/picker.rs:513,569-571` — `SessionsModel::killed: Vec<(Host, u32, String)>` is an untyped triple (endpoint, id, key) that only grows during the palette's life. A `SessionRef { host, id, key }` type would name it.
- `src/picker.rs:233-257` — `Palette::describe` builds the debug dump text inside a view method. It is display-only, but the row-to-text formatting is untested view code.
- `src/notify/mod.rs:304-308` — `on_reply` uses `let target = this.shown.get(&id).copied()` after removing the token. A click whose notification was already forgotten silently does nothing (log nothing).
