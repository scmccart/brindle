## Violations

Dependencies/imports (ports R1, R3): none. Manifest lists only `serde`, `serde_json` and (cfg(windows)) `windows`. No `use` points at another crate. Version 0.3.0 matches the other four crates (process R21).
Platform (ports R4/R5/R8): no `cfg` outside `#[cfg(test)]` in the three source files. Pure code (access.rs, build_id.rs, client.rs) reads no clock, env, file or global (fcis R2, R3). Decoders: no panic path on outside bytes (railway R5): build_id.rs uses `get`/`checked_add`; client.rs decodes through `wire::from_json`/`split_session` returning `io::Result`. No `unwrap`/`expect` outside tests.

1. remote-protocol/src/access.rs:119 — [EXCEPTION railway R3] (also types R2) — "A `match` on one of Brindle's own enums MUST be exhaustive, with no `_ =>` arm" — `_ => Ok(()),` in `match side { Side::Server if peer < own => …, Side::Client if peer != own => …, _ => Ok(()) }`, where `Side` is Brindle's own two-variant enum — fix: replace with `(Side::Server, false) | (Side::Client, false)` style arms, or two plain `if` arms per variant, so no wildcard stands for a variant.

2. remote-protocol/src/client.rs:322-359 (`SessionInfo`: `attached`, `owned`, `detached_secs`, `layout`) — types R1 (MUST) — "States that exclude each other MUST be one enum … Not two `bool`s, and not an `Option` whose meaning depends on another field" — `pub attached: bool` beside `pub owned: bool` (doc: "Always false while attached"), `detached_secs: u64` ("0 when attached or unknown") and `layout: Option<Value>` ("none while attached"): one attached/owned-unattached/unowned-detached state spread over four fields. The JSON shape is frozen (process R5), so the fix is a typed view built at the boundary (e.g. `enum Attachment { Attached, Detached { owned, secs, layout } }` in the consumer, types R9), not a change to the wire fields.

3. remote-protocol/src/client.rs:343-345, 352-354, 211-213, 338-342 — types R7 (MUST) — "Absence that means something MUST be a variant, or an `Option` handled at the boundary. No sentinels: no `-1`, no `0` id, no empty string for 'none'" — `/// Unix seconds; 0 when unknown. … pub started: u64`; `/// … 0 when attached or unknown. pub detached_secs: u64`; `/// Empty from a core that predates keys. pub key: String` (on both `SessionInfo` and `Spawned`); `title: String` where empty means no title — fix: type the absent case at the boundary (`Option<u64>`, `Option<SessionKey>`) with a serde adapter that keeps the omitted-when-unset encoding byte for byte, or convert in one function where the frame is decoded. Wire encoding is frozen, so this is a conversion at the decode boundary, not a format change.

4. remote-protocol/src/client.rs:129, 206, 234, 245, 322, 374 — types R11 (SHOULD) — "SHOULD NOT derive `Default` when its zero value is invalid" — `#[derive(Default)]` on `Hello` (`min`/`max` 0 and an empty `client_token` are not a valid HELLO; protocols start at 1), `Spawned`, `Detach`, `SetLayout`, `SessionInfo` and `Process` (session id 0 is invalid: ids start at 1) — fix: drop the derive and build test values with a helper (the tests use `..Default::default()` on `Hello` and `SessionInfo`), or give them a constructor taking the required fields.

## Design smells (no rule's words cover them)
- client.rs:914 — the unknown-type test lists `14` as an unknown core-bound type, but `MSG_SET_LAYOUT` is 14 since protocol 3. It passes only because the `{}` payload lacks `session` (InvalidData for a different reason). Replace `14` with an unassigned number such as 15.
- client.rs:313-320 — `ErrorMessage` carries only free text (`message`) plus `req`/`session`, so a client cannot branch on why a request failed (it can only show or compare text). Cf. railway R4; wire-frozen, a new field would be additive.
- client.rs:16/88 and wire.rs — `SessionId = u32` and `RequestId = u64` are type aliases, so a session id and a pid or request id mix without a compile error (types R4 keeps protocol-struct ids as plain integers, so not a violation).
- client.rs:254 — `MAX_LAYOUT` is only a constant here; the bound is enforced by the core after the frame has been decoded into `serde_json::Value` (remote-agent/src/server/core/sessions.rs:207), so the decoder itself accepts a layout up to the frame limit.
- client.rs:131-135 — `client_version: String` defaults to the empty string for "unknown" (sentinel flavour, wire-frozen). Resize/Spawn `cell_w`/`cell_h` default 0 with no documented meaning (0 as "unknown cell size" would be a sentinel too).
- client.rs:310 — `Reparent.hwnd: u64` puts a Windows handle value in the protocol. It is a plain integer and documented as reserved; no seam leak.
- build_id.rs:50-60, 69-76 — `as usize` casts from `u64` offsets truncate on a 32-bit target (the later `checked_add`/`get` keep it panic-free, so only the answer would be wrong). Use `usize::try_from(..).ok()?`.
- build_id.rs — `of_binary` parses bytes of a file but is not among `fuzz.rs`'s decoders; its test is a truncation sweep only (no corruption/random-bytes pass). Cf. railway R5 / process R6, which speak of message decoders.
- access.rs:15 — `Integrity(pub u32)` has a public field and no invariant, so it is fine as a wrapper (types R11 is about invariants); noted only because `Display`'s `Self(rid)` arm relies on every value being legal.
