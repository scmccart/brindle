## Violations

### ports R4 (cfg outside a seam)

Neither file is named in the exception text (`src/workspace.rs`, `src/terminal/mod.rs`, `src/main.rs`, `src/remote/local.rs` "among others"/"a few others"). Reported untagged, each noting the file is not named. If the "others" are meant to cover these files, retag them as [EXCEPTION ports R4].

1. `src/remote/mod.rs:34-38` — ports R4 (MUST) — "code outside it MUST NOT carry a `cfg` for that concern". `hide_window` carries `#[cfg(windows)] std::os::windows::process::CommandExt::creation_flags(command, crate::win::CREATE_NO_WINDOW);`. Hiding a child's console window is a platform concern, and `src/win.rs` is the Windows seam. mod.rs is not named in the exception. Fix: move `hide_window` into `src/win.rs`, with a no-op for other platforms in the same module set or behind one item. Callers (`client.rs`) call it unconditionally.
2. `src/remote/mod.rs:15` — ports R4 (MUST) — `#[cfg(any(target_os = "linux", windows))] pub mod local;`. Selecting which platforms build the server client is a platform concern, and mod.rs is not a seam or in the exception list. Fix: make `local` build everywhere with its `unix`/`windows`/`pipe` seams, or put the gate in the `local` seam itself (the macOS port's job).
3. `src/remote/mod.rs:10, 13, 91` — ports R4 (MUST) — three `#[cfg_attr(not(any(target_os = "linux", windows)), allow(dead_code))]` on `client`, `hosts` and `find_server_helper`. The same platform list is written three more times outside a seam. Same fix as 2: the gate on `local` disappears, and these go with it.
4. `src/remote/mod.rs:98` — ports R4 (MUST) — `find_server_helper_in(..., cfg!(windows))`. `cfg!(windows)` at the call site chooses the helper-lookup policy. The pure function takes `windows: bool`, which is good (tested on both platforms), but the `cfg!` that feeds it sits outside a seam. mod.rs is not named. Fix: a seam constant such as `win::IS_WINDOWS`, or have `local/{unix,windows}.rs` supply the value.
5. `src/session.rs:281` — ports R4 (MUST) — `let base = if cfg!(windows) { dirs::data_local_dir() } else { dirs::state_dir().or_else(...) }`. Where state lives is a platform concern with no seam. session.rs is not named. Fix: a pure `state_dir_in(env_override, windows: bool, local_data, state, home)` called by a one-line shell, or move it into a seam.
6. `src/session.rs:362-363` — ports R4 (MUST) — `#[cfg(unix)] std::os::unix::fs::DirBuilderExt::mode(&mut builder, 0o700);` in `private_dir`. Same concern (private file modes) as 7. Not named. Fix: one small seam module (for example `session`'s own `platform` submodule or `src/win.rs` counterpart) that owns "create private".
7. `src/session.rs:372-373` — ports R4 (MUST) — `#[cfg(unix)] std::os::unix::fs::OpenOptionsExt::mode(&mut options, 0o600);` in `private_file`. Fix as 6.

### fcis (decisions and ambient reads)

8. `src/remote/mod.rs:49-66, 76-85, 102-119` — fcis R3 (MUST) — "Pure code MUST NOT read the environment, files, ...". `find_helper_in` and `find_server_helper_in` take the environment values as arguments (good), but they decide through `exe_paths`/`beside_exe`, which call `dunce::canonicalize(exe)` and `path.is_file()`, and `find_helper_in` calls `path.is_file()` on the variable's value. The tests need real temp dirs and symlinks (lines 272-366). Fix: pass an `is_file: impl Fn(&Path) -> bool` and a `resolve: impl Fn(&Path) -> Option<PathBuf>` (or pre-gather a candidate list) so the order decision is tested with plain values.
9. `src/session.rs:446-459` — fcis R3 (MUST) — `resolve_cwd` is reached from the pure `resolve_tab`/`resolve_zone_node`, which are documented as the pure restore decision, and calls `cwd.filter(|d| d.is_dir())` and `Profile::working_directory().filter(|d| d.is_dir())`, which read the filesystem. Tests (`resolve_fallbacks` line 853, `zone_tree_round_trip_and_fallbacks` line 1215) depend on `/nonexistent/...`, `std::env::temp_dir()` and `/` existing. Fix: pass `is_dir: &dyn Fn(&Path) -> bool` into `resolve_tab`; the shell passes `Path::is_dir`.
10. `src/session.rs:276-287` — fcis R1/R3 (MUST) — `state_dir()` makes a decision (override variable, then per-platform base, then home fallback, then `.`) while reading `std::env::var_os("BRINDLE_STATE_DIR")`, `dirs::*` and `cfg!(windows)` itself. The idiom in fcis is that the caller reads the environment and a helper decides (`windows_editor_command`, `server_dir::resolve`). Also fcis R8: it has no unit test. Fix: `fn state_dir_from(over: Option<OsString>, windows: bool, local_data: Option<PathBuf>, state: Option<PathBuf>, home: Option<PathBuf>) -> PathBuf` with tests; `state_dir()` only gathers.
11. `src/session.rs:503` — fcis R3 (MUST) — pure `resolve_tab` calls `log::warn!("session restore: no profile named ...")`. Logging is a side effect in a decision function. Minor; see railway entry 14 for the larger issue on the same line. Fix: return the fallback as data (`RestoredTab::Local { fallback_profile: bool }` or a `(RestoredTab, Vec<Finding>)`), and let the shell log or show it.

### railway

12. `src/session.rs:267-272` — railway R1 (MUST) — "Not a panic, a sentinel value, or a log line with a default returned in its place". `to_text` returns `toml::to_string(self).unwrap_or_else(|err| { log::error!(...); String::new() })`. The empty string is then treated as text to write: `SessionStore::pending_write` hands `Some("")` to `write_atomic`, which replaces `session.toml` with an empty file that `load` then rejects ("no format version"). A serialization failure therefore destroys the saved session. The test at line 1267 even asserts the text is non-empty. Fix: `to_text() -> Result<String, toml::ser::Error>`; `pending_write` returns `None` (or the error) and does not mark `last_written`.
13. `src/session.rs:286` — railway R1 (MUST) — `base.unwrap_or_else(|| PathBuf::from(".")).join("brindle")`. When no data/state/home directory exists, the failure is replaced by a default (the current directory), silently, so the state file and `session.lock` land in cwd. Fix: return `Option`/`Result`, or surface it as a restore warning; at minimum log it.
14. `src/session.rs:502-505` — railway R1/R6 (MUST) — a recorded tab names a profile that is gone: `log::warn!(...)` then `unwrap_or_else(|| config.default_profile_index())`. An expected failure is a log line plus a default, and the user never sees it (R6: shown on the unit, not a log line alone). Fix: carry the substitution on `RestoredTab` (for example `profile_missing: Option<String>`) so the shell can note it on the tab. Low severity: the spec'd behaviour is a fallback.
15. `src/session.rs:223-260` (State::parse) / `src/session.rs:295` (`load`) — railway R5 (MUST, low confidence) — "bounds what it accepts". `std::fs::read_to_string(&path)` has no size bound and `ZoneNodeState` recurses (`resolve_zone_node`, `prune_zones`, `has_session`, `build_tree`, `active_cwd`) to a depth the file controls. The toml parser has its own nesting limit, which I did not verify, so the depth part may be bounded. Fix: cap the file size and the zone depth in `parse`, returning `Err`.
16. `src/remote/mod.rs:134` — railway R1 (SHOULD-level smell, listed here because R1 is MUST) — `child.kill().ok();` drops the kill error. Best effort and the following `wait()` reports the exit, so I treat it as acceptable. Not counted.

### types

17. `src/session.rs:61-80` (and uses 98-155, 581-606) — types R1 (MUST) — "States that exclude each other MUST be one enum ... not an `Option` whose meaning depends on another field". `ZoneNodeState` is a leaf or a split in one flat struct: `cwd`/`session`/`active` are "For a leaf ... Omitted for a split", `split`/`first`/`second` are three Options that must be all `Some` or all `None`. Invalid shapes (split with only `first`) compile and are silently read as a leaf (`resolve_zone_node` 462, `prune_zones` 583-589). `TabState::Local` and `SnapshotTab::Local` have the same shape: `zones: Option<_>` and `session: Option<_>` where `session` is meaningful only when `zones` is `None`. types R9 allows the flat form at the serialization boundary, but this type is also the in-memory model for `record_zones`, `prune_zones`, `drop_lost_zones`, `has_active`, `activate_first`. Fix: an in-memory enum `Node { Leaf{..}, Split{..} }` with a serde mapping, or reuse `RestoredZoneNode`-style enum with `Recorded` leaves.
18. `src/session.rs:45-47, 222-234, 568-577, 645-650` — types R3 (MUST) — "An identity MUST be the value that stays stable, never a position". `WindowState::active: usize` ("Index into `tabs`") is kept across file writes, restores and the three functions that delete tabs, each of which hand-adjusts it (`drop_skipped`, `drop_lost_zones`, `collapse`). The format is frozen (types R9), so the fix is internal: keep an enum/stable tab id in memory and convert to the index only when writing. Low severity.
19. `src/session.rs:429-442` — types R12 (MUST) — "A wrapper, variant or abstraction MUST exist for a meaning the code has today." `RestoredTab` has one variant, `Local`, which also covers remote tabs, and `resolve_tab` returns `Option<RestoredTab>` only to say "not restored" for `TabState::Skipped`. Fix: make it a struct (or return the struct in `Option`), and let `TabState::Skipped` stay the only absent case. `TabState::Local`'s name has the same mismatch (see smells).
20. `src/remote/mod.rs:186-188` — types R6 (MUST) — "Raw input MUST be parsed once into a typed value at the boundary ... never re-checks the raw one." `RemoteTarget::Container.engine` is a `String` (config.rs:196); `remote_command` checks `engine != "docker" && engine != "podman"` at use, and `settings_dialog/profiles.rs` has its own `ENGINES` list, so the validity rule exists in two places. Fix: `enum ContainerEngine { Docker, Podman }` parsed in `config.rs`, and `remote_command` matches on it without a bail.
21. `src/session.rs:660-669` — types R10 (SHOULD-level, MUST wording) — `last_written: Option<String>` is a stored derived value (the last serialized state) with no comment naming what refreshes it (only `pending_write` does). Also `touched` is documented, `last_written` is not. Fix: a doc comment on the field. Trivial.

### testing

23. `src/session.rs:310-311, 790-814, 891-916` — testing R7 (MUST) — "no shared temporary names, ... no dependence on test order", and R8 "a test MUST assert the rule, not a number that depends on timing". `write_atomic` skips a write whose `generation` is below the process-wide `WRITE_LOCK` value, which is one `static` for every directory. `atomic_write_and_load` (`write_atomic(&dir, &sample().to_text(), next_generation())`, then `assert_eq!(load(&dir), Ok(Some(sample())))`) and `old_tmux_entries_are_skipped` (`write_atomic(&dir, only, next_generation())`) run in parallel in one binary. If the other test's write lands with a higher ticket first, this write is skipped silently and the assertion fails. A real parallel-order flake. Fix: make the generation guard a per-store value (a `WriteGuard` argument to `write_atomic`) so tests don't share it.
24. `src/session.rs:817-836` — testing R9 (MUST) — a retry loop with `thread::sleep(10 ms)` for up to 5 s around `Lock::acquire`. testing R9 allows "a bounded retry ... only for a proven OS-level transient, with the cause written beside it": the comment is present (a forked child holds the open file description until its exec). Technically within the rule; recorded so it is counted: no violation, but R10's "shown by numbers" part is not evidenced in the file. Not counted.
25. `src/remote/mod.rs:272-366`, `src/session.rs:737-741, 790, 817, 891, 1179, 1205` — testing R7 (MUST) — "Each test has its own temporary directory with a cleanup guard." Directories are named `…-{pid}` (and, for mod.rs, not removed before creation) with a trailing `remove_dir_all(...).ok()` that does not run when an assertion fails first. A leftover directory from an earlier run with a recycled pid can change the next run's result (mod.rs tests assume `brindle-remote` is absent). Fix: a `TempDir` guard type with `Drop` cleanup, as the other test support code in the repo does if available.
26. `src/remote/mod.rs:342-345`, `src/session.rs:796-801` — ports R4 / testing R17 (SHOULD) — `#[cfg(unix)]`/`#[cfg(windows)]` symlink and permission checks in tests: tests only, and a test that can only run on one platform with its counterpart on the other (`helpers_are_found_beside_the_file_behind_a_link` has both; the 0o600 check has no Windows counterpart, which is not meaningful there). Not counted.

## Design smells

- `src/remote/mod.rs:121-139` `wait_process` polls with `try_wait` and a 20 ms sleep; it is only called from `client.rs` on a background thread (deploy), so process R13 holds, but a `wait` on a helper thread with a kill signal would avoid the polling.
- `src/remote/mod.rs` bundles unrelated things: helper lookup, process waiting, window hiding and `remote_command` (ports R13 asks for organisation by concern; no `utils` module, so not a violation).
- `src/remote/mod.rs:30-38` `hide_window` mutates and returns `&mut Command` while `remote_command` builds an owned `Command`; the Ssh and Container arms both end in the same call (fine).
- `src/session.rs:192-195, 210-214` `TabState::Local` is documented "A local tab" and also carries `remote: Option<RemoteTarget>` and records remote tabs; `Host` exists but the persisted form uses `Option<RemoteTarget>` (types R9 allows it at the boundary, but the name misleads).
- `src/session.rs:27` `MIN_SIZE: (f32, f32)` and `WindowState::{width, height}: Option<f32>` are logical pixels by comment only; no newtype (types R5 is not broken here, but a `LogicalPx` type would keep units apart).
- `src/session.rs:36-50` `WindowState` keeps `width`/`height` as two independent `Option<f32>`, so a state with only one of them is representable.
- `src/session.rs:310-334` no fsync of the directory after the rename, so a crash can lose the rename; the temp name is fixed (safe under the `session.lock` instance lock only).
- `src/session.rs:398` `unwrap_or(ZoneId(1))` gives the active zone a made-up id when there are no leaves; a tree always has a leaf, so it is a placeholder, not a sentinel the wire sees.
- `src/session.rs:668` `SessionStore` derives `Default` and tests build it with `SessionStore::default()` then set the private `lock` field directly; `new(lock)` is the constructor that expresses the invariant (types R11 SHOULD, nothing invalid is representable, so not a violation).
- `src/remote/mod.rs:42` `HELPER_NAMES` includes the Linux archive's file name for every platform; on Windows `BRINDLE_REMOTE_AGENT` names the Linux helper, a coupling the tests pin.
