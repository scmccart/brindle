## Violations

1. `remote-protocol/src/scope.rs:127-133` — `fcis R2` (MUST) — "Pure code MUST take time as an argument ... Random values (tokens, session keys) are made in the shell and passed in." Also `ports R7` (MUST): "A decision it needs (... a name) comes from a pure helper". `command()` is a tested builder, but it calls `unit_name`, which reads `SystemTime::now()` and `std::process::id()`: `let nanos = SystemTime::now().duration_since(UNIX_EPOCH)...`. The unit name is therefore not deterministic and the test can only assert `starts_with("--unit=brindle-serve-")`. Fix: `command` takes the unit suffix (or a full unit name) as an argument, and `current()`/callers supply it.

2. `remote-protocol/src/server_dir.rs:46` and `:72` — `fcis R3` (MUST) — "Pure code MUST NOT read the environment, files ... The caller reads them and passes values." `resolve` and `resolve_windows` take the variables as arguments, but both end with `std::path::absolute(dir)`, which reads the process's current directory for a relative `BRINDLE_SERVER_DIR`. The tests need that ambient state (`assert!(relative.is_absolute() ...)`, and the comment "`std::path::absolute` differs per platform"). Fix: take `cwd: &Path` and join, or return the path as given and let the caller absolutise it.

3. `remote-protocol/src/endpoint.rs:100-108` — `fcis R7` (MUST) — "A pure helper MUST compile and be tested on every platform ... Don't `cfg`-gate logic". `#[cfg(not(windows))] fn shown(&self, name: &str) -> Option<Holder>` is the string decision "which file names count as a holder socket, and where its lock and log are". It is compiled and tested only off Windows, while the Windows variant delegates to the ungated `server_dir::parse_holder_lock`. Fix: an ungated pure `holder_from_socket_name(dir, name)` and a test that runs everywhere; the cfg only chooses which one `shown` calls.

4. `remote-protocol/src/scope.rs:34-39` — `types R1` (MUST) — "States that exclude each other MUST be one enum ... not an Option whose meaning depends on another field." `Outcome { decision: Decision, user_manager: bool }`: `Decision::Scope(_)` implies `user_manager == true`, and `BRINDLE_NO_SCOPE=1` implies `false`. The state `(Scope, false)` is representable through the public fields. Fix: carry the manager's presence on the `Plain` variant (e.g. `Plain { reason, user_manager }`) so `Scope` has none.

5. `remote-protocol/src/ready.rs:29-35` — `types R1` (MUST), borderline — `Signal { len: usize, exact: bool }`: `exact` is only meaningful when `len == 1`; the three real states are Empty, Ready and Noise(len). The fields are private and `push` keeps them consistent, which limits the risk. Fix: a three-variant enum if the type is touched again.

6. `remote-protocol/src/holder.rs:171, 196, 198, 209, 211, 641, 645, 653, 659` — `types R7` (MUST) — "No sentinels: no `-1`, no `0` id, no empty string for 'none'." Wire and meta fields use 0 or "" for absent: `Hello.instance` (0), `Spawn`/`Resize` `cell_w`/`cell_h` (`#[serde(default)]`, 0 = unknown), `SessionMeta.command` ("empty for the login shell"), `key` ("empty for sessions spawned before keys"), `owner` ("empty for a session explicitly detached"), `started` ("0 when unknown"). The encodings are shipped and frozen (`process R5`), so the fix is at the boundary (`types R9`): map them to `Option`/enum in accessors on these structs so the core and client never compare to "" or 0.

7. `remote-protocol/src/relay.rs:44-63` — `types R7` (MUST) — same rule. `RelayHost.version`, `build`, `shell`, `home`, `server_dir` default to "" and `core_pid` to 0 when absent (`#[serde(default)]`, `#[derive(Default)]`). Fix: `Option` fields (still additive) or an accessor that turns missing into `None`; stop deriving `Default` for a type whose zero value is invalid (`types R11`).

8. `remote-protocol/src/version.rs:10-13` (and `holder.rs:162-178`, `Hello::range`) — `types R11` (SHOULD) and `types R6` (MUST) — "A type with an invariant SHOULD have private fields and constructors that enforce it." `VersionRange { pub min, pub max }` has the invariant `min <= max`, but `new` does not enforce it, the fields are public and wire data builds it directly (`Hello::range` wraps raw `u32`s). Every consumer (`negotiate`, `NegotiationError::fmt`) re-checks `min > max`, which is the raw value being re-checked past the boundary. Fix: `VersionRange::new` returns `Result` (or the decoder rejects it), and negotiation then needs no malformed arm.

9. `remote-protocol/src/holder.rs:670-694` — `railway R1` (MUST) — "An expected failure MUST be in the return type ... Not a sentinel value, or a log line with a default returned in its place." `SessionMeta::from_value` turns every malformed field into its default (`.and_then(... .ok()).unwrap_or_default()`), and a non-object into `Self::default()`, with no signal. A core that adopts a session with a corrupted `owner` or `policy` silently treats it as ownerless/default policy. Fix: return a result (or a `(SessionMeta, Vec<MetaFault>)`) and let the core log or show it; keep the default only for the documented "later core read an older meta" case (missing field), not for a field of the wrong type.

10. `remote-protocol/src/holder.rs:559-582` (`Assembler::begin`) — `railway R5` (MUST) — "it bounds what it accepts (frame lengths, control lines, layout blobs)". Each `begin` allocates `Vec::with_capacity(min(len, 1 MiB))` and inserts into a `HashMap` keyed by any `u32` session id, with no limit on how many blobs are open at once. A 9-byte `*_BEGIN` frame per session id costs 1 MiB, and `len` alone is capped at 64 MiB per blob. The peers are authenticated same-user processes, which lowers the practical risk. Fix: cap open blobs (or total announced bytes) per assembler, or allocate as chunks arrive.

11. `remote-protocol/src/lib.rs:66`, `holder.rs:670`, `upgrade.rs:32`, `server_dir.rs:127` — `process R6` (MUST) — "Every encoding MUST be pinned by a transcript test and every decoder fuzzed (`fuzz.rs`)." `fuzz.rs` covers `client::ToCore/ToClient`, `holder::ToHolder/ToCore`, `relay::RelayMessage` and `Assembler`, but not these parsers of outside bytes: `skip_preamble` (shell output over SSH), `SessionMeta::from_value` (opaque JSON from a holder), `semver` (a remote relay's version string), `parse_holder_lock` (directory entry names). They have fixed-case unit tests only. Fix: add them to `fuzz.rs` (random byte streams, random JSON values, random strings).

## Design smells

- `remote-protocol/src/lib.rs:18-19, 23-24`: `#[cfg(unix)] pub mod scope;` and `#[cfg(windows)] pub mod win;` sit in the crate root, which is not a listed seam. They only gate the seam modules themselves (as `platform/mod.rs` does), so I did not count them under `ports R4`. A reviewer could still ask for the cfg to live in a small `platform` module.
- `remote-protocol/src/lib.rs:6` and `relay.rs:4` say "protocols 1 and 2" and "protocol 1 and 2 frames", but client protocols are 1-3 (`SET_LAYOUT`).
- `remote-protocol/src/relay.rs:159-161`: the collision test says "1-13 and 32-41" and skips message 14 (`SET_LAYOUT`), so a future relay number cannot be checked against it.
- `remote-protocol/src/scope.rs:17`: `NO_SCOPE_ENV` (`BRINDLE_NO_SCOPE`) is documented as "tests, the e2e suite", but the relay also sets it in production when no scope is possible (per CLAUDE.md), so it is not a test-only switch under `process R20`, and the doc comment is wrong.
- `remote-protocol/src/scope.rs:26`: `Decision::Plain(&'static str)` carries the reason as free text, and `command(role: &str)` takes `"serve"`/`"hold"` as a string. A small enum for each would make a typo a compile error.
- `remote-protocol/src/scope.rs:128-131`: `.unwrap_or_default()` on a clock error turns "clock before the epoch" into nanos 0. It cannot matter for a unit name.
- `remote-protocol/src/holder.rs:665`: `serde_json::to_value(self).unwrap_or_default()` would turn a serialisation failure into `Null` meta (erasing owner and policy). It cannot fail for this struct today; an `expect("SessionMeta serializes")` would match `railway R9`.
- `remote-protocol/src/holder.rs:670-694`: `from_value` repeats the struct's fields by hand, so a new field must be added in two places or it silently defaults.
- `remote-protocol/src/holder.rs:657-659` (`SessionMeta.started: u64`, `scrollback: u32`): units live only in doc comments (`types R5` covers spaces that meet; none meet here).
- `remote-protocol/src/upgrade.rs:13-16`: `Build.version` is a raw `String` parsed by `semver()` on every `is_newer` call, and the string comes from a remote relay's `RELAY_HOST`. Parsing once into a typed version (`types R6`) would remove the repeated `Option` handling.
- `remote-protocol/src/endpoint.rs:31, 78`: a pipe name is stored as `PathBuf` (`server_dir::holder_pipe(...).into()`), and `server_dir::{core_pipe, holder_pipe, pty_pipe}` return `String` and take the SID and build as `&str`. A `PipeName` type would keep names apart from paths.
- `remote-protocol/src/endpoint.rs:89-95`: `fs::read_dir(...).flatten()` and `into_string().ok()` skip unreadable entries and non-UTF-8 names without a trace.
- `remote-protocol/src/holder.rs:73-79` (`HELLO`/`Hello`): `min`/`max` are repeated from `VersionRange` instead of embedding it (the encoding is frozen, so only a smell).
- `remote-protocol/src/holder.rs:64-71` and the `meta_is_kept_as_json` test: key order of `meta`/`layout` (`serde_json::Value`) is sorted only while no crate in the build enables serde_json's `preserve_order`. No manifest enables it today (`grep` over `Cargo.toml` files found none), but the encoding's determinism (`process R6`) depends on feature unification across the workspace, and the test input is already sorted, so it passes either way.
